# ADR 014: DB 스키마 정본 소유권 — 모비젠 단일 관리

> **Date:** 2026-10-28
> **Status:** Accepted

---

## 배경

본 과제의 메타데이터 DB는 모비젠(비정형)과 와이즈넛(정형)이 **같은 테이블 집합을 공유한다.**
`dcat_dataset`을 비롯한 공통 테이블 10종이 양측 적재 대상이다.

2026-10-28까지 양측은 **각자 DDL을 작성하고 각자 개발 DB에 적용**해왔다.
그 결과 같은 테이블의 정의가 갈라졌다.

- 와이즈넛 DDL에만 있던 것: `dcat_dataset_relation`의 `method` 포함 UNIQUE와 CHECK,
  정본 뷰 `dcat_dataset_relation_canonical`, 관계유형·지표 표준값 시드, 인덱스 9종
- 모비젠 DDL에만 있던 것: 비정형 전용 컬럼 3종(`subjects`·`owner_id`·`version`),
  `description`·`publisher` NOT NULL, `source_type` 기본값 제거

이 차이는 **양측 모두 상대 DDL을 보지 않으면 발견할 수 없었다.**
2026-10-28 통합 작업에서야 드러났다. 같은 구조가 유지되면 재발한다.

## 결정

**DB 스키마의 정본은 모비젠 저장소 `sql/` 한 곳이다. 와이즈넛은 이 정본으로 구성된
모비젠 DB에 데이터를 적재하고, 스키마 변경이 필요하면 모비젠에 요청한다.**

2026-10-28 와이즈넛과 합의 완료.

### 역할

| 주체 | 역할 |
|---|---|
| 모비젠 | 정본 `sql/` 관리, DB 운영, 변경 반영, 백업·복구 |
| 와이즈넛 | 정형 데이터 적재, 스키마 변경 요청 |

### 변경 절차

1. 변경이 필요한 쪽이 **대상 테이블·컬럼·사유를 명시해 메일로 요청**한다
2. 모비젠이 `sql/` 정본을 수정하고 `migration_YYYY_MM_DD_*.sql`로 남긴다
3. 모비젠이 운영 DB에 적용하고 결과를 회신한다
4. 수신 DDL 원본은 `sql/_received/<상대>_<수신일>/`에 그대로 보관한다

**어느 쪽도 운영 DB에 직접 DDL을 치지 않는다.** 이것이 양쪽 정의가 갈라지는 유일한 경로다.

### 데이터 적재 이후의 양방향 규칙

**적재가 시작된 뒤에는 모비젠도 상대에게 통보하고 허가를 받은 뒤 `DROP`/`ALTER`를 한다.**

정본 소유권은 모비젠에 있지만, 그것이 일방적 변경 권한을 뜻하지는 않는다.
상대 데이터가 들어 있는 테이블의 구조 변경은 상대 파이프라인을 깨뜨릴 수 있다.

## 계정·권한 분리를 하지 않는 이유

`GRANT`로 와이즈넛 계정의 `DROP`/`ALTER`를 막는 방안을 검토했으나 **채택하지 않는다.**

- 와이즈넛의 작업 범위는 **적재뿐**이고, DDL을 칠 일이 없다
- 변경이 필요한 상황은 위 절차로 처리되며, 그 절차는 **양측 합의 사항**이다
- 권한 분리는 운영 복잡도(역할 관리, 신규 테이블마다 GRANT 추가)를 늘리는 데 비해
  현재 얻는 것이 적다

**재검토 조건**: 적재 주체가 셋 이상으로 늘어나거나, 위 절차를 우회한 직접 DDL이
실제로 발생하면 그때 권한 분리를 도입한다. 그 시점에는 이 ADR을 override한다.

## 따라오는 제약 — 스키마 변경 비용이 적재 시점을 기준으로 뛴다

적재 **전**에는 모비젠이 단독으로 `ALTER`를 할 수 있다.
적재 **후**에는 통보·허가·일정 조율이 붙는다.

→ **구조 변경은 적재 개시 전에 끝내는 것이 원칙이다.**

특히 `dataset_id` URN 전환은 FK에 `ON UPDATE CASCADE`를 부여하는 `ALTER TABLE`을
동반하므로, **와이즈넛 적재 개시 전에 완료해야 한다.**
→ [database/dataset_id_urn_migration.md](../database/dataset_id_urn_migration.md)

## 결과

**좋아지는 것**

- 정의가 갈라지지 않는다. 대조 도구(`scripts/compare_ddl.py`)가 정본 한 벌만 검사하면 된다
- 변경 이력이 `migration_*.sql`로 한 줄기로 남는다
- 와이즈넛이 DB 운영 부담을 지지 않는다

**감수하는 것**

- **모비젠이 병목이 된다.** 와이즈넛의 변경 요청이 모비젠 작업 일정에 묶인다
  → 요청을 받으면 당일 회신하는 것을 기본으로 한다
- **DB 가용성 책임이 모비젠에 온다.** 장애 시 와이즈넛 적재도 함께 멈춘다
  → 백업·복구 절차 정비 필요 ([infrastructure/03_PostgreSQL.md](../infrastructure/03_PostgreSQL.md))
- 와이즈넛 개발 환경의 `db/init` 초기화 스크립트를 정본으로 교체해야 한다
