# ADR 021: 시제품 로그인 — K4 인증 전까지의 임시 구현

> **Date:** 2026-11-10
> **Status:** Accepted (임시 — 케이웨어 K4 인증이 오면 대체)

---

## 범위 — 먼저 읽을 것

**계정·인증(K4 OAuth2)은 연구개발계획서상 케이웨어 과업이다.** 이 로그인은 모비젠 시제품에서
아래 세 가지를 실제로 확인하려고 만든 **임시 구현**이다. 모비젠의 성과(연차보고서·SW 등록)로 잡지 않는다.

1. 사용자는 **자기 데이터셋만** 고친다(분류 확정·공개 범위)
2. **비공개(PRIVATE)·기관 내부(ORG)가 실제로 가려진다**
3. 관리자 페이지는 **관리자만** 쓴다

만들지 않는 것: 회원가입, 비밀번호 찾기·변경, 기관·권한 관리 화면, 소셜 로그인, 세션 철회.
전부 K4 몫이다.

관련 결정: NEXT_STEPS 2026-11-10 사용자 결정(관리자 페이지 로그인 필수 / 사용자 두 기관 /
범위는 문서에만 기록), 케이웨어 범위 위험 메모(2026-11-05).

## 배경

2026-11-10 사용자 등록 흐름(`/v1/my`)을 만들면서 사용자를 `X-User-Id` 헤더로 구분했다.
서버가 헤더를 그대로 믿으므로 헤더만 바꾸면 남의 데이터셋을 고칠 수 있었고, 포털이 쓰는
`/v1/console/*`는 총괄 관리자 시점이라 PRIVATE도 목록·검색에 그대로 나왔다.
"구분이 된다"를 시연할 수 없는 상태였다.

## 결정

| 항목 | 결정 |
|---|---|
| 계정 | 관리자 1 + 사용자 5(`demo-user-0001~0005` — DB의 기존 등록자 ID를 그대로) |
| 기관 | 사용자 0001~0003 = 기관 A, 0004~0005 = 기관 B, 관리자 = 운영기관 |
| 저장 | 서버 파일 `configs/auth_users.local.yaml`(git·이미지 제외)에 ID·이름·역할·기관·**비밀번호 해시**. DB 테이블 없음 |
| 해시 | PBKDF2-SHA256 600,000회(표준 라이브러리) |
| 토큰 | `Authorization: Bearer` JWT(HS256), 8시간. 서명 키 `AUTH_SIGNING_KEY`(32자 이상, 없으면 로그인 거절) |
| 무차별 대입 | 같은 ID 10분 내 5회 실패 시 10분 잠금(프로세스 메모리) |
| 관리자 API | `/v1/console/*`의 운영 기능 전부 `require_admin` — 테스트가 라우트 전체를 훑어 빠진 것을 잡는다 |
| 공개 범위 | `src/api/access.py` 한 곳에서 판정(아래 표) |

| 공개 범위 | 비로그인 | 사용자 | 관리자 |
|---|---|---|---|
| PUBLIC | 본다 | 본다 | 본다 |
| ORG | 못 본다 | 등록자와 같은 기관이면. **등록자 없는(관리자 등록) ORG는 로그인한 사용자 모두** | 본다 |
| PRIVATE | 못 본다 | 등록자 본인만 | 본다 |

- 볼 수 없는 데이터셋을 직접 열면 404(있다는 사실도 드러내지 않는다). 목록·검색·관계 지도에서는 뺀다.
- **공개 API(`/v1/*`)의 비로그인 기본값이 PUBLIC+ORG → PUBLIC만으로 좁아졌다.** main.py 주석이
  "인증이 붙으면 좁혀야 한다"고 적어 둔 그 변경이다. 외부 소비자가 있다면 ORG 15건이 안 보이게 된다.

## 교체 방법 (K4가 오면)

`src/api/auth.py`에서 두 곳만 바꾼다.

- `_decode()` — 우리 HS256 검증 대신 K4 토큰 검증(JWKS 등)
- `login()`·계정 파일 — K4로 넘기고 삭제

라우트들이 쓰는 `optional_user`·`current_user`·`require_admin`과 `User(id, role, org)`는 그대로 둔다.
`access.org_members()`(같은 기관 사용자 목록)는 K4의 기관 정보 조회로 바꾼다.

## 로그인이 안 될 때

1. 서버 로그에서 `로그인 실패 (id=…, 원인=…)`를 본다 — 원인은 `없는 아이디`·`비밀번호 미설정`·`비밀번호 불일치`.
   화면 응답은 원인과 관계없이 같다(아이디 존재 여부를 드러내지 않는다).
2. `PYTHONPATH=. .venv/bin/python scripts/auth_check_login.py` — 아이디·비밀번호를 받아 계정 파일과 대조한다(출력하지 않음).
3. 흔한 원인: **macOS 터미널에서 한글 입력 상태로 비밀번호를 설정**하면 한글로 저장되는데, 브라우저 비밀번호 칸은
   항상 영문으로 입력돼 맞지 않는다. 2026-11-10부터 `auth_setup_users.py`는 영문 외 문자를 거절한다.

## 한계 (임시라서 감수하는 것)

- 토큰을 브라우저 localStorage에 둔다 — XSS에 약하다. 운영에서는 HttpOnly 쿠키나 K4 방식으로
- 로그아웃은 브라우저에서 토큰을 지우는 것뿐이다(서버 측 철회 없음, 만료 8시간)
- 잠금 기록은 프로세스 메모리라 API를 다시 띄우면 풀린다
- 기관 정보가 계정 파일에만 있다 — 데이터셋 쪽 `publisher`와 연결돼 있지 않다
- **여전히 외부에 열지 않는다.** 로컬·내부 시연용이다
