## 1. 무엇을 여는가

지금까지 수집·검색·분석이 전부 CLI였다. 이 API가 그것을 HTTP로 연다.

| 엔드포인트 | 하는 일 |
|---|---|
| `GET /v1/datasets` | 카탈로그 목록 (원천·출처·키워드 필터, 페이징) |
| `GET /v1/datasets/{id}` | 상세 — B1 특징, B2 관계, 내려받기 경로 |
| `GET /v1/datasets/{id}/jsonld` | DCAT JSON-LD |
| `GET /v1/search` | 하이브리드 검색 (ADR-010) |
| `GET /v1/discover` | **활용 목적으로 데이터셋 묶음** (C2) |
| `GET /healthz` | DB까지 닿는지 |

```bash
PYTHONPATH=. uvicorn src.api.main:app --port 8000
# 문서(OpenAPI): http://localhost:8000/docs
```

## 2. 읽기 전용이다

등록·수정은 **D1(운영 기능)**의 일이고, 그때는 인증이 먼저다.
지금 쓰기를 열어 두면 인증 없이 데이터가 바뀐다.

---

## 3. 내보내지 않는 것

응답 모양은 `src/api/schemas.py`의 **허용 목록**으로 고정한다.
테이블 컬럼을 그대로 흘려보내지 않는다 — 컬럼이 늘 때마다 응답이 저절로
넓어지면, 언젠가 내보내면 안 되는 것이 섞여 나간다.

| 대상 | 이유 |
|---|---|
| `dataset_credentials` 전체 | **API Key 암호문.** 어떤 경로로도 나가지 않는다 |
| `owner_id` | 플랫폼 계정 식별자. 데이터셋 메타가 아니다 |
| `party` · `visibility` | 내부 권한 메타 |

테스트가 이 목록을 전수 검사한다(`tests/test_api_federation.py`).

### ⚠️ 공개 범위가 아직 좁혀지지 않았다

`DEFAULT_VISIBILITY = ("PUBLIC", "ORG")`다. 2026-11-04 기준 모든 데이터셋이
`ORG`라 `PUBLIC`만 내보내면 빈 응답이 되기 때문이다.

**이대로 외부에 열면 조직 내부용 데이터가 나간다.** 인증이 붙는 D1에서
반드시 좁혀야 한다.

## 4. 검색 응답에는 두 채널의 순위가 실린다

```json
{ "id": "30151", "title": "치핵 수술 후 통증관리…",
  "vec_rank": 1, "kw_rank": 7, "rrf": 0.031319,
  "ai_summary": "치핵 수술 후 통증이나 이상 증상이…", "ai_keywords": ["통증","치핵"] }
```

`vec_rank`/`kw_rank`가 `null`이면 그 채널에는 안 걸렸다는 뜻이다.
**이게 없으면 결과를 해석할 수도, 고칠 수도 없다.**

`?explain=true`를 주면 질의 토큰과 최희귀어 판정이 함께 온다.
`rarest_token.absent`가 `true`면 답이 없을 가능성이 높다(ADR-018).

`ai_summary`·`ai_keywords`는 A2의 추출 요약이다. **색인에는 넣지 않는다** —
생성물을 색인에 넣으면 원문이 아닌 것으로 검색되고, 나중에 생성 방식을 바꿀 때
무엇이 원문이고 무엇이 파생인지 구분이 안 된다.

## 4-1. 목적 기반 탐색 — `/v1/discover`

검색은 "맞는 것 하나하나"를 준다. 그런데 사람이 데이터를 찾는 이유는 대개
무언가를 하기 위해서이고, 그러려면 **함께 쓸 것들**이 필요하다.

    목적 → 카탈로그 검색(C1) → 관계 1-hop 확장(B3) → 묶음

```
GET /v1/discover?purpose=암과 소화기 질환 환자 교육 자료를 만들고 싶다

  0.03146 [both]     대항병원 대장항문 질환 정보
          ↳ 검색 3위 · '암 정보 큐레이션'와 SEMANTICALLY_RELATED
                     · '암 정보 큐레이션'와 KEYWORD_OVERLAP (대장암, 수술)
  0.01109 [relation] HBM 뉴스
          ↳ '내가 보는 바이오 뉴스'와 KEYWORD_OVERLAP (기록, 기업, 매출)
```

**각 항목에 `paths`로 도달 경로가 실린다.** 마지막 줄이 그 가치를 보여준다 —
HBM 뉴스가 일반어(`기록`·`기업`·`매출`)로 끌려 들어온 것이 근거에 그대로
드러나서, 사람이 걸러낼 수 있다. 근거가 없으면 이것이 조용히 섞인다.

### 점수를 더하지 않는다

검색 RRF(~0.03)와 관계 코사인(~0.9)은 단위가 다르다. 그냥 더하면 관계가
전부를 압도한다. 순위만 쓴다.

경로 순번에는 **기하 감쇠**를 건다. 선형으로 더하면 관계 기여가 검색 기여의
3배가 되어, "목적에 맞는 것"이 아니라 **"많이 연결된 것"**이 1등이 된다.

## 5. 외부 포털 연합 (CKAN)

```bash
PYTHONPATH=. python scripts/harvest_external.py \
    --portal https://open.canada.ca/data --query health --max 30 --embed
```

**메타데이터만 가져온다.** 원본 파일은 복제하지 않고 `landing_page`로 가리킨다.
복제하면 라이선스·최신성·용량이 전부 우리 문제가 되고, 연합 검색의 목적은
"어디에 무엇이 있는지 아는 것"이지 "다 가져오는 것"이 아니다.

| 표시 | 값 |
|---|---|
| `dataset_origin` | `external` — 수집 파이프라인이 건드리지 않는다 |
| `source` | `CKAN:<포털>` |
| `external_ids` | `['<포털>:<원천id>']` (와이즈넛 합의 형식) |

**`data_registry`에는 넣지 않는다.** 그 테이블은 "다음에 언제 수집할 것인가"를
담는데 외부 데이터셋은 우리가 수집하지 않는다. 넣으면 스케줄러가 수집하려 들고
실패만 쌓인다.

### ⚠️ `--embed`를 빠뜨리면 조용히 누락된다

임베딩이 없으면 **카탈로그 목록에는 보이지만 검색에는 안 걸린다.**
오류가 나지 않아 눈으로는 알 수 없다.

### 외국 데이터에 우리 기본값이 붙지 않게 한다

`dcat_dataset.language`는 NOT NULL에 기본값 `'ko'`, `spatial`은 `'KR'`이다.
우리가 수집하는 국내 데이터를 위한 값이라, 그냥 두면 **캐나다 데이터셋이
한국어·한국 소재로 기록된다.** 오류가 안 나서 눈으로는 안 보인다.

- `language` — 포털이 준 값 우선, 없으면 `en`
- `spatial` — **추측하지 않고 NULL**

## 6. 확인된 동작 (2026-11-04)

캐나다 공개데이터 포털에서 30건을 들여와 같은 색인에 합쳤다.

```
질의 "health care system"        질의 "암 건강 정보"
  [외부] Primary health care…      [내부] 암 정보 큐레이션
  [외부] Health Canada's Approach  [내부] 내가 보는 반려동물 블로그
  [외부] Achieving Health for All  [내부] 대항병원 대장항문 질환 정보
```

**같은 색인에서 함께 검색되면서 질의 언어에 맞게 갈린다.**
