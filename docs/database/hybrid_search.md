## 1. 무엇이 바뀌었나

검색이 **단일 채널 → 두 채널**이 됐다.

| | 벡터 채널 | 키워드 채널 |
|---|---|---|
| 색인 | `*_vec.embedding` (pgvector, 768차원) | `*_vec.tsv` (tsvector + GIN) |
| 점수 | 코사인 `1 - (embedding <=> q)` | `ts_rank_cd` (cover density) |
| 집계 | 청크 최대값 → 원본 1건 | 청크 최대값 → 원본 1건 |
| 강한 곳 | 표현이 달라도 의미가 같을 때 | 고유명사·숫자·영문 약어의 정확한 일치 |
| 깨지는 곳 | 어떤 질의에나 0.85가 나온다 | 질의어가 본문에 없으면 0건 |

두 채널을 **RRF**(Reciprocal Rank Fusion)로 합친다. 점수가 아니라 **순위**만 쓴다.

    rrf(d) = Σ_channel  1 / (k + rank_channel(d))     (기본 k = 60)

점수 가중합을 쓰지 않는 이유는 두 채널의 단위가 다르기 때문이다(코사인 0.7~1.0 대
`ts_rank_cd` 0~수십). 정규화하려면 채널별 분포 통계가 필요한데 현 규모에서는
그 통계를 신뢰할 수 없다.

## 2. 배포 순서 (지키지 않으면 조용히 깨진다)

```bash
# 1) 스키마 — *_vec 4종에 token_text / tokenizer_ver / tsv(생성 컬럼) + GIN
psql ... -f sql/migration_2026_10_30_keyword_channel.sql

# 2) 기존 청크 163,407건 토큰 채우기 (중단·재개 가능)
PYTHONPATH=. python scripts/backfill_tokens.py

# 3) 확인
PYTHONPATH=. python scripts/search_demo.py "반도체 수출 규제" --why
```

⚠️ **1)을 건너뛰면 수집이 실패한다.** `src/embedding/sync.py`가 청크를 넣을 때
`token_text`를 같이 쓴다. 없는 컬럼이라 INSERT가 깨진다 — 눈에 띄는 고장이라 낫다.

⚠️ **2)를 건너뛰면 아무 오류도 안 난다.** 키워드 채널이 0건을 반환하고 하이브리드가
벡터 단독으로 조용히 수렴한다. **이쪽이 더 위험하다.** 확인은 이걸로:

```sql
SELECT count(*) FILTER (WHERE tsv <> '') AS 색인됨, count(*) AS 전체
FROM meta_news_vec;
```

## 3. 토크나이저 버전은 왜 저장하나

질의와 문서가 **다른 토크나이저**를 거치면 오류가 나지 않고 **리콜만 0이 된다.**
검색은 성공하고 결과만 비어 있어서, 로그를 봐도 알 수 없다.

그래서 청크마다 `tokenizer_ver`을 적어 두고 검색 진입점에서 현재 버전과 대조한다.
불일치면 `TokenizerMismatch`로 **중단시킨다**(ADR-010이 요구한 바).

버전 문자열에는 셋이 다 들어간다 — `kiwi-0.24.1+model-0.24.0+pos1`

| 조각 | 왜 필요한가 |
|---|---|
| `kiwi-<ver>` | 분석기 자체가 바뀌면 토큰이 달라진다 |
| `model-<ver>` | 같은 분석기라도 사전이 바뀌면 분해가 달라진다 |
| `pos<n>` | **품사 화이트리스트**. 이게 빠지면 "같은 kiwipiepy인데 색인만 조용히 어긋난" 상태를 잡을 수 없다 |

`src/search/tokenize.py`의 `_KEEP`이나 `_ALLOWED`를 고치면 **`_POS_VER`을 올리고
재토큰화**해야 한다. 임베딩은 건드릴 필요 없다 — 토큰만 다시 만들면 된다.

```bash
PYTHONPATH=. python scripts/backfill_tokens.py   # 버전이 다른 행만 자동으로 골라낸다
```

## 4. 토큰화가 하는 일

조사·어미를 떼어낸다. 떼지 않으면 같은 단어가 조사에 따라 다른 토큰이 되어,
질의 `대역폭`이 본문 `대역폭을`에 **영원히 걸리지 않는다.** 실측 왜곡:

| 어절 그대로 | 문서빈도 | 형태소 분해 후 | 배수 |
|---|---|---|---|
| `대역폭을` | 0.23% | `대역폭` 15.04% | **65배** |
| `맨몸으로` | 0.28% | `맨몸` 2.65% | 9.5배 |

남기는 품사는 내용어뿐이다 — `NNG` `NNP` `VV` `VA` `XR` `SL` `SH` `SN`.
조사(`J*`)·어미(`E*`)·의존명사(`NNB`)·관형사(`MM`)는 버린다.

**길이로 거르지 않는다.** 한국어는 복합어가 쪼개지면서 1글자 조각이 핵심 의미를
지고 가는 경우가 흔하다.

    대역폭   → 대역 + 폭      (폭을 버리면 '주파수 대역' 기사와 구분 불가)
    전기차   → 전기 + 차      (차를 버리면 전기 일반 기사와 구분 불가)
    맨몸으로 → 맨(XPN) + 몸   (몸을 버리면 토큰이 하나도 안 남는다)

Kiwi가 `©`를 외국어(SL)로, `%`를 기호(SW)로 태깅하기 때문에 품사만으로는 기호가
안 걸러진다. 그래서 문자 화이트리스트(`[0-9a-z가-힣]`)를 한 번 더 통과시킨다.
이 필터는 **색인 쪽과 질의 쪽이 같은 함수를 쓴다** — 그게 둘이 어긋나지 않는 보장이다.

## 5. 결과 읽는 법

```
$ PYTHONPATH=. python scripts/search_demo.py "반도체 수출 규제" --why

      토큰: 반도체 수출 규제
      최희귀어: '반도체'  문서빈도 312건 (0.75%)

   #  순위(V=벡터 K=키워드)  RRF       제목
   1.    V3    K1  0.032266  미국, 대중국 …
   2.    V1    K4  0.032018  美 재무부, 中 겨냥 …
```

- `V3 K1` — 벡터 3위, 키워드 1위. 두 채널 다 올렸다.
- `V12 K-` — **벡터만** 잡았다. 표현이 다르지만 의미가 맞는 경우거나, 그냥 틀린 경우.
- `V- K2` — **키워드만** 잡았다. 벡터 후보 200건 밖이었다는 뜻.

한쪽만 달린 결과가 많으면 두 채널이 서로 다른 것을 보고 있다는 신호다.
`--mode vector`로 예전 단일 채널 결과와 직접 비교할 수 있다.

### "답이 없다"는 판정

`--why`가 **최희귀어의 문서빈도**를 같이 보여준다. 쓰는 신호는 하나뿐이다 —
**`df == 0`(코퍼스에 아예 없음).**

문서빈도에 `< 1%` 같은 선을 긋는 시도는 ADR-018에서 전부 실패했다. 정답 있음
최저 0.63%와 정답 없음 최고 25.3%의 구간이 겹친다. **어떤 고정 임계값도 틀린다.**

## 6. 측정 결과 (2026-10-30) — 균일한 개선이 아니다

ADR-018의 질의 19건을 **전체 코퍼스 복제본**(video 19,039 / news 41,410 /
blog 102,884 청크)에서 벡터 단독과 비교했다. 순위 정답지가 없으므로 Recall@k는
만들 수 없고, **잴 수 있는 것만** 쟀다.

| 측정 항목 | 결과 |
|---|---|
| top-10 중 벡터 단독 대비 교체된 문서 | 3~10건 (평균 5.7) — 결합이 실제로 순위를 바꾼다 |
| **키워드 채널 단독 기여** | **0건** — 벡터 top-200 밖 문서가 top-10에 든 적이 없다 |
| 최희귀어 부재(`df=0`) 적중 | 19건 중 2건(`치질`·`제주도`), 둘 다 정답 없음 — **오탐 0** |
| 지연 | 하이브리드 399~3,136ms (벡터 단독과 같은 수준) |

### 6.1 키워드 채널은 리콜을 넓히지 않는다

단독 기여 0건은 **키워드 채널이 벡터 후보 200건 안에서 재정렬만 한다**는 뜻이다.
이 코퍼스에서는 벡터 top-200의 리콜이 이미 충분했고, 키워드가 보태는 것은
정밀도(순서)이지 범위가 아니었다.

### 6.2 그리고 한 질의에서 **나빠졌다**

    질의: "메모리 대역폭을 늘리는 적층 기술"   (정답 있음)

    벡터 단독 top3
      2. HBM 12단서 8단으로…SK하이닉스 수익성 셈법 달라지나      ← 정답
      3. AI 반도체 병목 뚫었다…'메모리 월' 넘는 삼성전자 zHBM    ← 정답

    하이브리드 top3
      1. 삼양사, '트리라이트 데이 2026' 개최…반도체 초순수 소재
      2. "용인, 세계 최대 반도체 생태계 만든다"
      3. 삼성전자, 3분기 영업이익 107.4조 사상 최대            ← 전부 무관

**원인은 튜닝이 아니라 구조다. `ts_rank_cd`는 IDF를 쓰지 않는다.** 질의 토큰은
`메모리 / 대역 / 폭 / 늘리 / 적층 / 기술`인데, OR 질의에서 고빈도어(`기술`·`메모리`)가
빽빽한 일반 반도체 기사가 희귀어 `적층`(df 23)을 담은 정답 기사를 밀어낸다.
cover density는 "질의어가 얼마나 몰려 있나"를 보지 "그 단어가 얼마나 드문가"는
보지 않는다.

ADR-018이 측정한 것과 같은 함정이다 — 고빈도 어절은 모든 지표를 "확신"으로
만든다. 형태소 분해가 이걸 **악화시키는 면도 있다**: `전기차`는 어절로는 드물지만
`전기`+`차`로 쪼개면 둘 다 흔하다. 실제로 최희귀어 부재 규칙의 적중이
ADR-018의 4/8에서 2/7로 떨어졌다.

### 6.3 그래서 지금 고치지 않는다

떠오르는 처방은 세 가지다 — 질의 토큰을 df로 가중, 고빈도 토큰 제거 후 OR,
AND 우선 후 OR 폴백. **셋 다 평가셋 없이는 고를 수 없다.**

ADR-018이 보인 것이 정확히 이것이다. 1차 12건에서 깔끔하게 갈리던 지표가
적대적 질의 7건을 넣자 전부 겹쳤다. 19건으로 처방을 고르면 같은 실수를 반복한다.
**평가셋 확보가 선행 조건**이다(NEXT_STEPS P0-6).

> 현재 상태 요약: 결합은 동작하고, 판정 근거(키워드 채널)가 생겼고, 순위를
> 바꾼다. 그러나 **모든 질의에서 더 낫다고 말할 수 없다.** 최소선은 여기까지다.

## 7. 아직 없는 것

| 항목 | 왜 안 했나 |
|---|---|
| **검색 평가셋** | 질의–정답문서 쌍이 없다. **이것 없이는 아래가 전부 추측이다** |
| RRF `k` 스윕 (10/20/30/60) | 평가셋이 있어야 고를 수 있다. 지금은 관례값 60 |
| 필드 가중치 (`setweight`) | 청크에 출처 필드가 기록돼 있지 않다 (ADR-010 §구현) |
| 동의어 사전 | `synonym(term, alt)` 테이블 — 목표선 |
| 재순위 (cross-encoder) | 표준 3단 구성의 마지막 단. 후보 품질이 먼저 |

**평가셋이 최우선이다.** ADR-018이 질의 19건으로 보인 것은 "작은 평가셋에서
관측된 분리는 신뢰할 수 없다"는 것이었다 — 1차 12건에서 깔끔하게 갈리던 지표가
적대적 질의 7건을 넣자 전부 겹쳤다. 같은 함정이 `k` 튜닝에도 그대로 있다.
