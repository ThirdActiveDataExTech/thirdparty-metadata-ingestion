## 1. 무엇을 물었나

검색이 **코퍼스에 답이 없는 질의에도 상위 N건을 반환한다.** "결과 없음"을 판정할
방법이 필요했고, 세 가지를 차례로 확인했다.

1. 코사인 유사도 고정 임계값으로 가를 수 있는가 → **아니오**
2. 키워드 신호를 같이 보면 가를 수 있는가 → **단일 임계값으로는 아니오, 규칙으로는 부분적으로 예**
3. 지금 적재 방식(청킹·MAX 집계·e5)에 결함이 있어서인가 → **아니오. 모델 사양이다**

## 4. 깨지는 방식은 두 종류다

### (a) 키워드는 낮은데 답이 있다

`quantum computing qubit` — 상위 5건이 전부 양자컴퓨팅 기사로 **정확히 맞혔는데**
본문이 한국어라 리터럴 겹침이 없다. cov@10 0.23.
**키워드로 거르면 맞은 답을 버린다.**

### (b) 키워드는 높은데 답이 없다

`국내 기업 투자 확대 계획` — 어절이 전부 고빈도(국내 444, 기업 782, 확대 897)라
cov@10 0.72, 최희귀어 DF 25.3%. 모든 지표가 "확신"을 가리키는데 답은 없다.
**IDF 가중으로도 해결되지 않았다**(가중 후에도 `HBM 메모리`와 겹침).

## 5. 형태소 분석 부재가 측정을 왜곡한다

(a)·(b)와 별개로, **조사가 붙은 어절을 그대로 쓰면 DF가 무너진다.**

| 어절 | DF | 어간 | DF | 배수 |
|---|---|---|---|---|
| 대역폭**을** | 4 (0.23%) | 대역폭 | 264 (**15.04%**) | **65배** |
| 맨몸**으로** | 5 (0.28%) | 맨몸 | 47 (2.65%) | 9.5배 |
| 늘리**는** | 27 (1.54%) | 늘리 | 89 (5.07%) | 3.3배 |

조사 하나로 "코퍼스에 없다"는 판정이 나온다.
[ADR-010](../adr/010_Korean_Fulltext_Search.md)이 Kiwi 앱단 토큰화를 택한 근거가
여기서 실측으로 재확인된다.

이 측정에서는 분석기가 없어 **접미 1~2자를 깎아 DF가 최대인 형태를 쓰는 근사**로
대체했다. 이 근사도 완전하지 않다 — `HBM`→`HB`, `대장내시경`→`대장내시`,
`고양이`→`고양`처럼 과도하게 자른다.

## 6. 쓸 만한 규칙 — 최희귀어 출현 확인

> **질의의 최희귀어가 상위 10건에 실제로 출현하는가?**

19건 중 **16건** 적중. 중요한 것은 오류 방향이다.

| | 결과 |
|---|---|
| 정답 있는 질의 11건 | **11건 전부 "통과"** — 잘못 버린 건 0 |
| 정답 없는 질의 8건 | 4건 "결과 없음" 판정, 4건 통과(오판) |

**오류가 전부 "그냥 보여줌" 방향이다.** 현재 동작과 같으므로 더 나빠지지 않는다.
영어 질의 `quantum computing qubit`도 통과시켰다(희귀어 `computing`이
한국어 기사 본문에 원문 그대로 섞여 있다).

오판 3건은 §4(b) 유형과 라벨 모호 1건(`고양이 사료 추천` — 블로그에 고양이
언급 문서가 56건 있어 "없음" 라벨 자체가 다툼의 여지가 있다)이다.

## 7. 적재 방식의 결함이 아니다

점수가 0.84~0.93의 좁은 구간에 몰리는 것은 **e5 모델의 설계된 동작**이다.
InfoNCE 대조학습에 temperature 0.01을 쓴 결과이며, 모델 저자가 모델 카드에
직접 적었다.

> This is a known and expected behavior as we use a low temperature 0.01 for
> InfoNCE contrastive loss. (…) what matters is the **relative order** of the
> scores instead of the absolute values.
> — `intfloat/e5-large-v2` README

청킹·MAX 집계·`passage:`/`query:` 프리픽스([ADR-016](../adr/016_Embedding_Model_And_Conventions.md))는
모두 모델 사용법대로다. **절대값에 의미를 부여하려던 시도가 잘못이었다.**

## 8. 재현

측정 스크립트는 일회성이라 저장소에 포함하지 않았다. 재현하려면 아래를 구현한다.

1. 질의를 어절 단위로 분리(`[^0-9A-Za-z가-힣]+` 기준, 2자 이상).
   **ADR-010 구현 후에는 Kiwi 토큰을 쓴다.**
2. 어절별 코퍼스 문서빈도: `SELECT count(DISTINCT meta_id) FROM <vec> WHERE embed_text ILIKE '%<어절>%'`
3. 벡터 상위 50건: `MAX(1 - (embedding <=> q))` + `GROUP BY` 원본키 (`scripts/search_demo.py`와 동일)
4. 각 상위 문서에 대해 `bool_or(embed_text ILIKE ...)`로 어절 출현 여부
5. §3·§6의 지표를 집계

> ⚠️ 서버에 `pg_trgm`·`pg_bigm`·한국어 `ts_config`가 **없다**(설치 확장: `pgcrypto`, `plpgsql`, `vector`).
> 그래서 이 측정은 `ILIKE` 부분문자열로 키워드 채널을 근사했다. 실제 구현은
> [ADR-010](../adr/010_Korean_Fulltext_Search.md)대로 Kiwi + `simple` tsvector + GIN이다.
