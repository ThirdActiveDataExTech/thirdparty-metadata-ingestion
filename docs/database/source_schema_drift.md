# 원천 스키마 드리프트 감지

**C4(동적 변화 파이프라인) 최소선 완료 기준의 후반부** — "소스 스키마 변경이
자동 감지·기록됨". 전반부(주기 수집)는 `scripts/scheduler_tick.py`.

구현: `src/pipeline_engine/drift.py` · 저장: `data_registry.source_schema_*`

---

## 1. 막으려는 고장

어댑터 스펙은 원천 응답의 경로를 **문자열로** 박아 둔다.

```yaml
fields:
  published_at: snippet.publishedAt
```

원천이 이 경로를 옮기거나 없애면 `dig()`가 `None`을 돌려주고, 해당 컬럼은
**오류 없이 NULL**로 들어간다. 수집은 "성공"으로 끝나고 `item_count`도 평소대로
늘어난다. 사람이 알아채는 시점은 한참 뒤 "검색 결과가 왜 이래?"다.

2026-11-04에 `<b>` 태그 오염 28건을 **실물을 눈으로 보고서야** 찾은 것과
같은 종류의 고장이다. 로그에도 지표에도 안 남는다.

## 2. 두 가지를 따로 본다

| | 질문 | 성격 | 심각도 |
|---|---|---|---|
| **drift** | 원천 모양이 지난번과 달라졌나 | **사건** — 한 번 일어나고 지나간다 | `additive` / `removed` |
| **mapping** | 우리가 쓰는 경로가 지금도 오는가 | **상태** — 고칠 때까지 계속 참이다 | `breaking` |

지문 비교만 하면 안 되는 이유가 여기 있다. 지문은 바뀐 순간 한 번 울리고,
새 지문을 저장하면 다음 수집부터 "변경 없음"이 된다 — **깨진 매핑을 그대로 둔 채
경보만 사라진다.** 그래서 "스펙이 읽는 경로가 지금 관측에 있는가"는 지문과
무관하게 **매번** 확인한다.

## 3. 무엇을 지문으로 삼는가

레코드 하나에서 필드 **경로**를 전부 뽑는다. 컨테이너 자신도 경로로 센다
(`snippet`과 `snippet.title`이 둘 다). 그래야 `tags: []`처럼 비어 있을 때도
키가 있다는 사실이 남는다.

**리스트 인덱스는 접는다.** `items.0.title`·`items.1.title`을 각각 세면
결과 건수만 달라져도 지문이 흔들린다 → `items[].title`.

**선택 필드는 뺀다.** 60건의 합집합을 쓰면 한 건에만 있던 필드 때문에 매 수집마다
"변경됨"이 뜬다. 무뎌진 경보는 없는 것과 같다. 관측 비율이 `CORE_RATIO`(0.9)
이상인 경로만 스키마로 본다. 표본이 `MIN_SAMPLE`(5)보다 적으면 비율을 믿을 수
없으므로 아예 판정하지 않는다.

## 4. 임계선에서 깜빡이지 않게 — 히스테리시스

2026-11-04 YouTube 실측:

| 경로 | 관측 비율 |
|---|---|
| `snippet.thumbnails.maxres` | 93.6% |
| `snippet.thumbnails.standard` | 97.9% |
| `snippet.thumbnails.fhd` | 4.3% |

`maxres`가 **문턱 90% 바로 위**다. 다음 수집에 88%가 되면 아무 일도 없었는데
"필드 제거"가 뜬다. 그래서 **들어오는 문턱은 높게, 나가는 문턱은 낮게** 둔다 —
이미 스키마로 보던 경로는 `CORE_RATIO - STICKY_BAND`(0.7)까지 버틴다.
진짜로 사라지면 비율이 0 근처로 떨어지므로 그때는 빠진다.

## 5. 결과 읽기

```
🚨 원천 스키마: changed / breaking (표본 60건, 필드 5개)
     + publishedAt
     - pubDate
     ✗ 스펙이 읽는 pubDate 가 지금 안 온다 → 후보: publishedAt
```

| status | 뜻 |
|---|---|
| `skipped` | 표본 부족 — 판정하지 않음 |
| `unregistered` | `data_registry`에 행이 없음 (스펙의 `dataset_id` 오타 등) |
| `first_seen` | 첫 관측 — 비교 대상 없음 |
| `unchanged` | 지문 동일 |
| `changed` | 지문이 달라짐 |

대체 후보는 **이름이 닮은 것**을 고를 뿐이다(`pubDate` ↔ `publishedAt`,
대소문자·밑줄 무시). 고쳐 주지 않는다 — 원천이 의미까지 그대로 옮겼는지는
사람이 봐야 안다.

## 6. 감지기가 수집을 죽이지 않는다

이건 **관측이지 관문이 아니다.** 드리프트 감지가 실패해도(DB 끊김 등)
수집 결과는 유효하다 — 데이터는 이미 손에 있다. `runner._check_drift`가
예외를 삼키고 `status: error`로 남긴다.

마찬가지로 `breaking`이 떠도 **적재는 계속한다.** 일부 컬럼이 비는 것과
그날 수집이 통째로 없는 것 중에서는 전자가 낫고, 무엇이 비었는지는 기록에 남는다.

## 7. 끄는 방법 — 스펙에서만

파이프라인 스펙에 `drift: false`. **단계(`steps`)로 만들지 않았다** —
단계로 두면 스펙이 조합으로 뺄 수 있게 되고, 끌 수 있는 감지기는 결국 꺼져 있다.

## 8. 한계 (현재)

- **알림 경로가 없다.** 로그와 `data_registry` 컬럼에만 남는다.
  운영 화면·알림 연동은 D1에서 본다.
- **이력이 1세대뿐이다.** 직전 집합만 보관하므로 "언제부터 이랬나"는 답하지 못한다.
  변경 이력 테이블은 목표선.
- **값의 분포는 보지 않는다.** 필드가 오긴 오는데 전부 빈 문자열인 경우는
  이 감지기가 못 잡는다 — 그건 B1 기술통계·품질 프로브의 일이다
  (`docs/database/metadata_quality_probe.md`).
