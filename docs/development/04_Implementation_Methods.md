### 0.2 유연성 원칙 — 최소선 우선

모든 과업은 **🟩 최소선(러프)** 과 **🟦 목표선** 을 나눠 정의한다.

- 요구사항을 100% 만족하기 어려운 항목은 **"걸치는 수준"으로 먼저 구현**하고 한계를 문서화한다.
- 일정이 부족하면 **모든 과업을 최소선까지 채우는 것**이 일부만 완벽히 하는 것보다 평가상 유리하다.
- 평가에서 중요한 것은 ① 동작 증거(코드 + 산출 데이터 + 재현 절차), ② 한계의 명시.
- **억지로 끼워 맞추지 않는다.** 데이터 구조상 성립하지 않는 항목은 §4에 근거와 함께 제외한다.

### 0.3 라이선스 원칙

과제 산출물은 SW 등록·상업적 활용 가능성이 있으므로 **상업적 이용 가능 라이선스만** 채택한다.
비상업(NC)·라이선스 미표기·share-alike 해석 여지가 있는 자산은 §5 점검표에서 판정한다.

## 1. 선행 과제 — 신규 개발보다 먼저

신규 기능을 쌓기 전에 해결해야 할 **기존 결함·공백** 5건. 비용 대비 효과가 가장 크다.

### 1.1 🔴 임베딩 입력이 128토큰에서 잘린다 (기존 결함)

`perf_eval/_models/mpnet/sentence_bert_config.json` → `"max_seq_length": 128` **(직접 확인)**

| 단계 | 실제 동작 |
|---|---|
| `scripts/embed_news.py` 등 | 본문을 `content[:500]`으로 절단 |
| mpnet 모델 | 다시 **128토큰**(한국어 약 200~300자)에서 절단 |
| 결과 | 500자를 넘겨도 **앞 200~300자만 벡터에 반영**, 나머지는 조용히 버려짐 |

뉴스 본문이 500~3000자이므로 **본문의 10% 내외만 검색에 쓰이고 있다.** `[:500]` 절단은 무의미하다.

- 🟩 **최소선**: 본문을 250자 단위로 청킹 → 각각 인코딩 → **평균 풀링**. `*_vec` 스키마 변경 불필요.
- 🟦 **목표선**: 청크별 벡터를 개별 저장. 현재 `*_vec`는 **원본 1행 = 벡터 1개(PK=FK)** 구조이므로 **DDL 변경 필요**.
- 대안(한국어 특화 모델 교체)은 **재임베딩 비용 + 기존 벡터와 다른 공간**이라 지금은 보류.

### 1.2 🔴 YouTube 자막이 수집만 되고 아무도 쓰지 않는다

- 저장 위치: S3 `raw/video/{dataset_id}/{video_id}.json` (내부에 `segments[]` + `full_text`)
- DB에는 `has_transcript` / `transcribed_at` **플래그만**. 행 자체가 없음
- `scripts/embed_video.py`는 `title + description + tags`만 임베딩 — **자막 미사용**

가장 긴 비정형 자산인데 활용 경로가 없다. 이걸 연결하면 **B1(특징 추출)·C1(검색)·A2(AI 메타)가 동시에 설득력을 얻는다.**
STT는 이미 `faster-whisper`(CPU, int8, small)로 동작 중이므로 추가 비용이 없다.

- 🟩 **최소선**: `full_text`를 읽어 청킹 임베딩 + 키워드 추출 대상에 포함.
- 🟦 **목표선**: `segments` 단위 색인으로 "영상 내 구간 검색"까지.

### 1.3 🟡 컨테이너화 부재

`Dockerfile`이 없어 C3·C4(파이프라인 자동화·스케줄링)가 구조적으로 막혀 있다.
베이스 이미지는 사내 정책상 `registry.example.com/hub` 경유, **`latest` 태그 금지**, 버전 고정.
모델 가중치(mpnet 등)는 **이미지에 포함하거나 PVC 마운트** 후 `HF_HUB_OFFLINE=1` — 폐쇄망 다운로드 실패가 최대 운영 리스크.
`kiwipiepy`는 모델을 패키지에 동봉하므로 이 문제가 없다(선정 이유 중 하나).

### 1.4 ✅ 외부 LLM API — **사용 불가로 결정** (2026-10-27)

→ **[ADR-013](../adr/013_No_External_LLM_API.md)** 로 확정. 모든 언어모델 추론을 온프레미스 로컬로 한정한다.

핵심 원칙: **LLM이 없어도 기능이 성립해야 하고, LLM은 품질을 올리는 선택지여야 한다.**

| 기능 | 대체 경로 |
|---|---|
| A2 요약 | **추출 요약**(문장 선택) — hallucination 없음, Kiwi 파이프라인 재사용. 🟦 로컬 sLLM 생성 요약 |
| C2 질의 확장 | **공기어(co-occurrence) 테이블** 상위 N개 — 완전 오프라인, 반나절 |
| C1 평가 | **전량 사람 라벨** — LLM-judge 편향 논란이 사라져 오히려 근거가 강해진다 |
| C7 연계 | 어댑터 규약은 OpenAI 호환 유지, 구현체만 로컬 `llama-server` → **교체 가능성 자체가 과업 증거** |

✅ 전제 확인 완료(2026-10-27): 온프레미스 로컬 추론은 가능. 단 **최소선은 LLM 없이 성립하도록 유지**한다 — 처리량이 실측 전까지 미확정이고, 모델 장애가 파이프라인을 멈춰서는 안 되기 때문.

### 1.5 ❓ 메타데이터 품질 실측 (착수 전 SQL 2건, 각 1일 이내)

1. `dcat_dataset`의 `keywords` 채움률, `description` 길이 분포 → **B2 키워드 자카드 엣지의 실현 가능성 판정**

## 3. 과업별 구현 방법

### A1. 수집 어댑터화 〔3차 · 모비젠 단독〕

**근거(계획서)**: "확장 가능한 데이터 수집" / **현재**: `src/collectors/` 5종 독립 구현

**선언형으로 되는 것과 안 되는 것 — 경계를 먼저 긋는다**

| 영역 | 선언형 가능 | 코드 필요 |
|---|---|---|
| 인증 | 헤더 고정키, 쿼리파라미터 키, Bearer | OAuth2 refresh, HMAC 서명, 토큰 캐싱 |
| 페이징 | offset/limit, page번호, nextPageToken | 응답 구조에 따라 바뀌는 커서, 날짜 슬라이딩 |
| 레코드 추출 | `items[]` 단순 경로 + 필드 매핑 | 중첩 배열 평탄화, 한 응답 → 2개 테이블 |
| 삭제 감지 | "이번 수집에 없으면 삭제"(전량조회형) | 뉴스처럼 **URL 재확인 후 404/410만 삭제** |

> ⚠️ **과제 문구를 "코드 작성 없이 신규 소스 추가"로 잡지 말 것.**
> 기존 5종 중 선언형으로 재현 가능한 건 많아야 2종이다. Airbyte low-code CDK도 custom component 탈출구를 둔다.
> **"설정 기반 확장 + 필요 시 훅"** 으로 서술해야 나중에 곤란해지지 않는다.

- 🟩 **최소선**: `src/collectors/declarative/` 신설. YAML 스펙 + JMESPath + 페이징 3종 + 고정키 인증 + 상태코드별 재시도. **기존 5종 무이관**, `src/main.py`에 fallback 1줄. 신규 소스 1종으로 증명.
- 🟦 **목표선**: `custom_hook`(모듈경로:함수명) 탈출구, 증분 커서(STATE) 분리 저장, `Retry-After` 준수, `jsonschema`로 스펙 검증.

**공존이 성립하는 이유**: 선언형 러너와 기존 5종이 **적재·이력 헬퍼(`src/database/dcat.py`)를 공유**한다. 수집·정규화만 새로 하고 나머지는 재사용.

**참고 설계(도입 아님)**: Airbyte low-code CDK(커넥터·CDK는 **MIT**)의 매니페스트 7슬롯 구조 — `requester` / `paginator` / `record_selector` / `incremental_sync` / `partition_router` / `transformations` / `schema`. Singer·Meltano SDK(**Apache-2.0**)의 `SCHEMA`/`RECORD`/**`STATE` 분리** 개념.

### A2. AI 생성 메타데이터 〔1·2차 미이행 · 모비젠〕

**현재**: STT만 구현. NLP·VLM 없음. `meta_*_ai` DDL 없음.

**설계 변경 제안 — 소스별 분리 → 공통 단일 테이블**

기존 문서(`infrastructure/03_PostgreSQL.md`)는 `meta_video_ai` / `meta_news_ai` / `meta_blog_ai`로 **소스별 분리**를 예정해 뒀다. **공통 단일 테이블 + JSONB를 권고한다.**

| 방식 | 장점 | 단점 |
|---|---|---|
| 소스별 분리 | 타입 안전, 쿼리 단순 | **소스 추가마다 DDL+코드 증식**, 크로스소스 검색이 UNION, 백필 로직 N벌 |
| **공통 + JSONB** | 소스 추가 시 DDL 0, 백필 1벌, 크로스소스 용이 | 타입 안정성 약함 → `kind` 컬럼 + GIN + Pydantic 검증으로 완화 |

소스가 이미 5종이고 계속 늘어난다. **아직 DDL을 만들지 않은 지금이 전환 비용이 가장 싸다.**
→ ADR 후보 §6.

**핵심 설계**

- `generator_version = sha256(model_id | model_digest | prompt_id | prompt_hash | params)[:16]`
  → 모델·프롬프트·파라미터 중 **무엇이 바뀌어도 값이 바뀐다** = 재처리 대상 추적의 단일 수단
- 구버전은 **UPDATE하지 않고 새 버전 행을 INSERT** (UNIQUE 키에 버전 포함) → 품질 비교·롤백 가능
- `input_hash`(원문 sha256) → 원문이 바뀌면 같은 버전이어도 재생성
- **lease 기반 워커 큐**(`lease_owner`/`lease_until` + `FOR UPDATE SKIP LOCKED`) → 큐는 DB 자체, 브로커 불필요. K8s Job 재시작·OOM에 안전
- **필드 단위 분리 호출**: `summary`/`keywords`/`category`/`entities`를 별도 호출로. 한 번에 묶으면 한 필드 실패가 전체를 버린다
- **상태 3단**: `success` / `partial`(성공 필드만 저장하고 계속) / `failed`. 재시도 상한 초과 시 `skipped`로 격리
- **품질 게이트(규칙 기반, 비용 0)**: 길이 하한·상한, 한국어 비율, n-gram 반복률, JSON 스키마 적합, 원문에 없는 숫자·고유명사 과다. 위반 시 `quality_flag` + 외부 노출 뷰에서 제외

- 🟩 **최소선**: 1개 소스(YouTube **자막** 기반). **LLM 없이** — 추출 요약(문장 선택) + TF-IDF 키워드. ADR-013
- 🟦 **목표선**: 로컬 sLLM 생성 요약(구동 가용 확인됨, §3 C7), 개체명·분류 추가, 전 소스 확대, CLIP 이미지 태깅.

#### 부속 과업 — 공통 분류(`category`) 부여

와이즈넛 공통 분류(디지털 집현전 주제 분류, 대분류 7 / 중분류 76)를 비정형 데이터셋에도 부여해야 한다.
분류표·규칙 전문은 [database/category_taxonomy.md](../database/category_taxonomy.md).

> 💡 **ADR-013(외부 LLM 미사용)과 충돌하지 않는다.** 와이즈넛 정의 문서의 2단계 폴백이
> **"데이터셋 요약 임베딩과 가장 가까운 중분류 1개"** 로 되어 있어, 그 경로를 주 경로로 쓰면 된다.

- 🟩 **최소선**: 76개 중분류 라벨을 임베딩해 두고 `title + description + keywords` 임베딩과
  코사인 최근접 1~3개 선택. 기존 mpnet(768차원) 재사용.
  `perf_eval/metadata_theme_classification/`의 라벨 임베딩 zero-shot 코드 재활용 가능
- 🟦 **목표선**: 로컬 sLLM이 분류표 범위 안에서 선택 → 실패 시 임베딩 최근접으로 폴백(와이즈넛과 동일 2단 구조)

- ⚠️ 입력 품질이 상한선이다 — §1.5에서 확인한 대로 `description`이 평균 25자인 데이터셋이 많다

**처리량 현실**: 4B Q4 기준 요약 1건 ≈ 5~15초 → 10,000건 ≈ 14~42시간(단일 워커).
→ **야간 CronJob + 복수 Pod 수평 분할.** 입력 절삭(앞 N토큰 + 구조 기반 발췌)이 가장 효과 큰 비용 절감 수단.
**과제 문서에 "비동기 배치 생성"으로 명시할 것. 실시간 응답을 약속하지 말 것.**

### B1. 데이터 특징 추출·분석 〔1차 미이행 · SW모듈 귀속: 모비젠〕

**근거**: "액티브 메타데이터 기반 데이터 특징 추출 및 분석 기술" / 1차 SW 모듈 **"데이터 특징 추출 및 분석 모듈(모비젠)"**

#### 정형 특징
pandas `describe()`, 결측률, 카디널리티. (쇼핑·페르소나 인사이트가 대상 — 완전 정형)

#### 비정형 텍스트 — 소스별로 성질이 다르므로 비대칭 설계

| 소스 | 실제 보유 텍스트 | 예상 품질 | 주의점 |
|---|---|---|---|
| 뉴스 `content` | **스크래핑 전문**(API 아님) | **상** | 기자명·언론사·`무단전재 금지`·`사진=` 보일러플레이트 선제거. selector 실패 시 `<p>` 휴리스틱 폴백이라 노이즈 혼입 가능(`has_content`는 이진 플래그뿐) |
| 블로그 `content` | **스크래핑 전문** | 하~중 | 광고 문구(`소정의 원고료`, `체험단`, `내돈내산`)가 고빈도 상위 점유 → 광고 불용어 사전 필수. 짧아서 TF-IDF 신호 약함 → 제목·태그 가중 |
| YouTube 자막 | **S3 JSON의 `full_text`** (§1.2) | 중 | 문장부호 없음 → `kiwi.space()` → `kiwi.split_into_sents()` 선행. STT 음차 표기 흔들림(`엘에프피`/`LFP`) → 정규화 사전 |
| YouTube `description` | 최대 5000자 | 중 | |

#### 키워드 추출 — 확정

**Kiwi 명사 추출 + 어절 내 연속 명사 결합 + 소스별 코퍼스 TF-IDF**

1. **Kiwi (kiwipiepy ≥0.24, Apache-2.0)**. ⚠️ **0.23.2 이하는 LGPL — 버전 고정 필수.**
   설치가 `pip install` 한 줄(manylinux/macOS 휠 제공), 모델 동봉으로 폐쇄망에 유리.
   실측: 8,700자 47ms(≈185k자/초).
2. **어절 내 연속 명사 결합이 사실상 필수.** 기본 토큰화는 `인공`+`지능`으로 분절된다.
   결합하면 `인공지능`, `과학기술정보통신부`, `고대역폭메모리` 정상 복원.
3. **IDF는 소스별로 따로 집계**한다. 자막·뉴스·블로그는 문체가 달라 혼합하면 IDF가 망가진다.
   IDF는 주기 배치로 갱신하고 **버전을 기록**한다.
4. 키워드는 **문서 1건 단위**로 산출한다(메타데이터 속성이므로).

> **KR-WordRank는 문서 1건 키워드 추출에 쓰면 안 된다.** 실측 결과 자막 단일 문서에서 상위에
> `그러니까`·`근데`·`보면` 같은 기능어가 올라왔고, 짧은 문서는 키워드를 2~4개만 반환했다.
> **코퍼스 단위에서 미등록 신조어·고유명사를 발굴해 Kiwi 사용자 사전(`add_user_word`)에 주입하는 전처리 용도**가 올바른 쓰임이다.

- 🟩 **최소선**: 위 TF-IDF까지. 단 **코퍼스가 수백 건 미만이면 IDF가 불안정** → 초기에는 단순 빈도+불용어로 운영하다 전환하는 2단계 전략.
- 🟦 **목표선**: 상위 30후보를 **KeyBERT + MMR**로 재랭킹. 기존 mpnet 재사용(문서 1건당 CPU 1.5~2초, 배치 전제라면 수용 가능). ⚠️ 128토큰 절삭 회피를 위해 **250자 청킹 후 평균** 필수.

#### 개체명 인식

- 🟩 **최소선**: **Kiwi NNP 태그 + gazetteer(기관·지명·제품 사전) Aho-Corasick 매칭.** 의존성 추가 0.
  "개체명 추출을 했다"고 말하기에 충분한 하한선. 미등록어가 조사까지 묶여 NNP로 오분석되는 함정은 사용자 사전으로 보정.
- 🟦 **목표선**: `Leo97/KoELECTRA-small-v3-modu-ner` (15종 태그, F1 0.8339, **14.1M≈56MB**로 CPU 현실적).
  ⚠️ **모델 카드에 라이선스 표기 없음 + 모두의말뭉치 이용조건 상속 가능성 → 법무 확인 전 미채택.**
- ❌ spaCy `ko_core_news_lg`: 설치는 가장 쉬우나 **CC BY-SA 4.0 share-alike**. 라벨도 6종뿐이라 제품명·기술용어를 못 잡는다.

#### 토픽 모델링 — 확정

**기존 768차원 임베딩 + KMeans + c-TF-IDF.** BERTopic을 러프하게 대체한다.

근거: ① BERTopic 공식 문서가 `hdbscan_model=KMeans(...)` 교체를 명시 지원 — 즉 "임베딩→군집→군집별 키워드"가 BERTopic의 실제 골격이고 **1단계를 이미 보유**. ② 단문·다도메인 실험에서 HDBSCAN이 문서 대부분을 outlier로 버린 반면 KMeans는 유사 성능 + outlier 0. 블로그·자막처럼 짧고 잡음 많은 텍스트에 오히려 안전. ③ umap-learn·hdbscan(C 빌드) 의존성 제거.

- KMeans는 모든 문서를 강제 배정하므로 **군집 중심과의 거리 상위 5%를 "기타"로 사후 분리**.
- **k 선택**: `k=5~30` sweep + silhouette, 또는 **데이터셋 단위로 k를 10~15로 고정하고 라벨을 사람이 1회 검수·명명**. 후자가 비용 대비 가장 현실적이며 산출물 설명도 쉽다.
- ⚠️ **데이터셋 단위로 분리해 군집할 것.** 자막·뉴스를 섞으면 주제가 아니라 **문체·소스·길이로 군집이 갈린다.**

**저장**: 신규 테이블 `meta_feature(dataset_id, scope, target, feature_name, value JSONB, computed_at)`

**측정**: 공개 정답셋이 사실상 없다. **소스별 50~100건 수동 샘플 검수** 결과를 산출물로 제시하는 것이 현실적이다.

### B2. 관계 분석 〔1차 미이행 · 모비젠〕

**근거**: "데이터 패턴 모델링 기반 데이터 관계 분석 기술"

> ⚠️ **저장은 와이즈넛 합의 스키마 `dcat_dataset_relation`을 쓴다**([ADR-012](../adr/012_Graph_Storage_PostgreSQL.md)).
> `relation_type`이 `relation_type_registry`에 FK로 묶여 있어 **등록되지 않은 유형은 INSERT 자체가 불가능**하다.
> 2026-10-27 기준 비정형에 쓸 수 있는 표준 유형은 **`SEMANTICALLY_RELATED`·`KEYWORD_OVERLAP` 2종뿐**이며,
> 아래 `entity_shared`·`temporal_comovement`는 **registry 등록을 먼저 제안**해야 쓸 수 있다.

**채택하는 엣지 4종**

| 종류 | 산출 방법 | 비고 |
|---|---|---|
| `semantic_similar` | pgvector 코사인, **mutual top-K** | 뼈대. K=5(데이터셋)/10(아이템) |
| `keyword_overlap` | `keywords`/`subjects` JSONB 자카드 ≥0.2 | 사람이 넣은 값이라 해석 가능 |
| `entity_shared` | 키워드·태그·카테고리명 공유 (bipartite) | 근거 제시가 가장 쉬움 |
| `temporal_comovement` 🟦 | 일별 리샘플 → **1차 차분** → **스피어만** | "패턴 모델링" 문구에 가장 직접 대응 |

**임계값 3단 규칙** (multilingual-mpnet은 코사인이 0.3~0.9에 몰려 절대 임계값 이식성이 낮다)

1. **mutual top-K**: A의 top-K에 B가 있고 **동시에** B의 top-K에 A가 있을 때만 엣지 → 허브 폭주 방지
2. **분포 기반 하한**: 전체 쌍 코사인의 **95 백분위**를 계산해 `min_sim`으로. 하드코딩 금지, `dcat_graph_run.params`에 기록
3. **상한 컷**: `sim > 0.98`은 중복 데이터셋 의심 → 엣지 대신 `duplicate_candidate` 플래그

> **HNSW 인덱스**: 데이터셋 레벨(수십 개)은 **전수 비교가 더 빠르고 recall 100%** — 인덱스 불필요.
> 현재 `*_vec.sql`에 주석 처리된 상태가 맞다. **아이템 레벨(수만 건)에서만** `USING hnsw (embedding vector_cosine_ops)` 생성.

**시계열 공변동 3원칙 — 안 지키면 전부 가짜 상관**
① 원계열은 추세·주간계절성으로 raw 피어슨이 0.8+ 남발 → **1차 차분 후 스피어만**
② **겹치는 구간 ≥30포인트** 미만 쌍은 버림 (YouTube·뉴스 active 테이블은 기간이 짧아 여기서 많이 걸린다)
③ **다중비교 보정** — BH FDR(q=0.05), 최소한 `|rho| ≥ 0.5 AND n ≥ 30`을 고정 규칙으로 문서화
가중치는 `abs(rho)`, 부호는 `evidence.sign`에 보관(음의 상관도 관계다).

### B3. 네트워크(지식그래프) 생성 〔2차 미이행 · SW모듈 귀속: 모비젠〕

**근거**: 2차 SW 모듈 **"액티브 메타데이터 기반 네트워크 생성 및 분석 모듈(모비젠)"**

**저장 설계 — 단방향 + 전개 뷰**

이종 노드(dataset/item/keyword)를 **(node_type, node_id) 복합 식별자**로 한 테이블에 담는다.
무방향 엣지는 **CHECK 제약으로 사전순 정규화를 강제**해 양방향 중복 저장을 구조적으로 차단하고,
조회는 전부 `v_relation_edge`(UNION ALL 전개) 뷰만 보게 한다.

> 양방향 중복 저장은 **한쪽만 갱신되는 버그가 반드시 발생**한다. 조회 비용은 이 규모에서 논점이 아니다.

**다중 홉 재귀 CTE 방어 4종 — 전부 적용**
① 깊이 상한을 **재귀항 안에** (최종 WHERE에 두면 전개는 다 하고 버린다)
② **누적 가중치 곱셈 감쇠 컷** (`path_w * e.weight >= 0.25`) — 실질적으로 폭발을 잡는 건 이것
③ 약한 엣지 선차단
④ `CYCLE ... SET is_cycle USING path` — 유사도 그래프는 사이클 투성이고, `depth` 컬럼이 들어가는 순간 `UNION` 중복 제거는 무효가 된다(공식 문서 명시 함정)

**분석: NetworkX (메모리 상 연산 전용)**

패턴 = **PostgreSQL이 진실원천, NetworkX는 일회성 연산 엔진.** 적재→계산→`dcat_graph_metric` 기록→객체 폐기.
상태를 NetworkX에 두지 않으므로 동시성·복구 문제가 없다.

| 지표 | 과제 문서에서의 의미 |
|---|---|
| Degree / Weighted degree | "가장 많이 연결된 허브 데이터셋" — 시연 1순위 |
| PageRank | "영향력 상위 데이터셋" — 추천 랭킹에 바로 사용 |
| Louvain 커뮤니티 | "자동 발견된 주제 클러스터" — 그림이 가장 잘 나옴 |
| **Modularity** | 커뮤니티 품질 수치(0.3~0.7이 통상 유의) — **정량 지표로 보고서에 적합** |
| Connected components | "고립 데이터셋 탐지" → 메타데이터 품질 개선 액션으로 연결 |

- ⚠️ **`seed=42` 고정 필수** — Louvain은 시드마다 결과가 달라진다.
- ⚠️ 동일 쌍에 여러 relation_type이 있을 때 **가중치 합성 규칙(max 권장)을 명시·문서화**. 합산하면 관계 종류가 많은 쌍이 과대평가된다.
- 지표는 `dcat_graph_metric`에 **run 단위 누적 기록**(덮어쓰지 않음) → 시점별 네트워크 변화 제시 가능. `dcat_dataset` 본체에 컬럼을 추가하지 않는다(파생값이 원천 카탈로그를 오염시키면 안 됨).

**규모 한계**: ~10만 엣지는 전 지표 수 초. ~100만은 betweenness가 O(V·E)로 사실상 불가(근사 또는 제외). 우리는 첫 구간.

### B4. 와이즈넛 관계 모델 결과 수용 〔공동 인터페이스〕

**우리가 먼저 규격을 제안해야 한다.** 상대가 출력 포맷을 정하면 변환 계층을 우리가 영구히 떠안는다.
설계 원칙: **"엣지 1건이 자기 출처를 스스로 설명할 것."**

**협력사에 요구할 필수 5개 필드**
`producer.model_version` / `weight` / `confidence` / `evidence.reason`(자연어 1문장 — 데모에서 "왜 연결됐나"를 보여줄 유일한 수단) / `src`·`dst`의 **우리 식별자 그대로**(`node_namespace` 명시).
마지막이 가장 중요하다 — 협력사 내부 ID를 쓰면 매핑 테이블을 우리가 영구 관리하게 된다.

**수용 검증**: `spec_version` 호환 → jsonschema → **id 실존 조회** → 0~1 범위 → 자기루프·중복 제거 → 정규화 → 배치 UPSERT.
한 건 실패 시 **해당 건만 reject 로그, 배치는 진행**(all-or-nothing은 운영 부담).

**규칙 엣지와 모델 엣지 공존 — 주의 5가지**

1. `origin` + `method` + `method_version`이 **UNIQUE 키에 포함**되어야 같은 쌍에 규칙·모델 엣지가 공존한다(서로 다른 주장이므로 덮어쓰면 안 됨)
2. **weight 스케일이 다르다.** 코사인 0.7과 GNN 확률 0.7은 다른 의미 → NetworkX 적재 시 **method별 랭크 정규화**. 안 하면 모델 엣지가 PageRank를 지배하거나 묻힌다
3. ⚠️ **만료 처리를 `origin='rule'`로 한정할 것.** 규칙 엣지는 일간 재계산, 모델 엣지는 비정기 납품 — `scope` 단위로 싹 지우면 **협력사 납품 엣지가 통째로 날아간다.** 가장 흔히 놓치는 지점
4. **분석 결과를 두 벌 낸다**: 규칙만 / 규칙+모델. 두 결과의 차이(커뮤니티 변화, modularity 변화)가 **"협력사 모델이 실제로 기여했다"의 유일한 정량 증거**이며 평가에서 가장 강한 산출물이 된다
5. 모델 엣지는 **신뢰도 컷을 분리 운용**(`confidence >= 0.7`을 params로) → 협력사 품질이 기대 이하여도 **설정값 변경만으로 데모를 지킬 수 있다**

### C1. 검색 고도화 〔1차 보강 · SW모듈 귀속: 모비젠(검색 전처리 모듈)〕

**핵심 결정: 한국어 전문검색을 어떻게 할 것인가**

PostgreSQL 기본 FTS는 한국어 형태소를 지원하지 않는다. → **애플리케이션 단에서 Kiwi로 토큰화한 결과를 `simple` 설정 tsvector에 넣는다.**

근거: ① **DB 확장 설치 불필요** — 컨테이너 이미지 재빌드·`shared_preload_libraries` 변경·재기동이 전부 사라진다(pg_bigm·PGroonga는 모두 이게 전제). ② `ts_rank_cd` 랭킹과 `tsquery` AND/OR/구문검색을 그대로 쓸 수 있다(pg_bigm은 LIKE 전용이라 결합할 점수가 사실상 없다). ③ 이 규모에서 선택 기준은 속도가 아니라 운영 리스크와 랭킹 품질이다. ④ 분석기를 바꿔도 **DB 스키마는 불변, 재색인만** 하면 된다. ⑤ 질의·문서에 동일 토크나이저를 쓰므로 "조사가 안 떨어진다"는 한국어 고질 문제가 설계 단계에서 제거된다(n-gram은 확률적 우회일 뿐).

> ⚠️ **결정적 구현 디테일**: `array_to_tsvector(tokens)`를 쓰면 **위치 정보가 없어 `ts_rank`/`ts_rank_cd`를 못 쓰고 소문자 정규화도 안 된다.**
> 반드시 `to_tsvector('simple', array_to_string(tokens, ' '))` 형태로 만들 것. 이 한 줄이 성패를 가른다.

필드 가중치는 `setweight`로 제목 A / 키워드 B / 설명 C. `pg_trgm`은 **오타·부분일치·자동완성 보조 채널로만** 병행.
`tokenizer_ver` 컬럼을 두고 **기동 시 버전 일치를 검증**한다 — 질의·문서 분석기가 불일치하면 **조용히 리콜이 0이 된다.**

**하이브리드 결합: RRF**

`RRF(d) = Σ w_i / (k + rank_i(d))`. **SQL 단일 CTE**로 구현(네트워크 왕복 1회, 필터가 두 채널에 일관 적용, 재현성).
`k`는 통상 60이 기본값이나, **데이터셋 수십 건이면 후보군이 작아 과도하게 평탄화될 수 있다** → `k ∈ {10,20,30,60}` 스윕을 평가 항목에 포함.
점수 정규화 가중합은 분포 통계가 필요한데 이 규모에선 통계가 신뢰할 수 없다 → RRF.
`vec_rank`·`kw_rank`·`vec_sim`을 **응답에 그대로 반환**해야 근거 설명과 디버깅이 가능하다. 숨기지 말 것.
`to_tsquery`에 사용자 입력을 직접 넣지 말고 **토큰 화이트리스트 기반으로 조립**(주입·구문오류 방지).

**품질 측정 — "개선했다"를 방어하는 부분**

정답셋 40개: (a) 시나리오 질의 10~15개(사람 작성) + (b) 역생성 질의 20~25개(설명→LLM이 질의 생성) + (c) 실사용 로그 5~10개.
3단 등급(2=핵심/1=관련/0=무관), pooling 방식으로 top-10 합집합만 라벨링.
지표는 **nDCG@10(대표) + Recall@3·@10 + MRR(보조)**.

⚠️ **반드시 부트스트랩 95% 신뢰구간을 병기할 것.** 질의 40개면 평균 차이 0.03은 노이즈다.
⚠️ **(b) 역생성 질의는 설명문 어휘를 그대로 쓰므로 키워드 채널에 유리하게 편향**된다 → (a) 비중 30%↑ 유지 + 그룹별 분리 보고.
⚠️ LLM-as-judge를 쓰면 **사람 라벨 100~150쌍과의 일치도(Cohen's κ)를 측정해 함께 보고**. κ<0.6이면 LLM 라벨만으로 결론 내지 말 것.

🔴 **가장 큰 측정 리스크**: 데이터셋 수십 건이면 **Recall@10이 금방 1.0으로 포화**되어 개선이 수치로 안 보인다.
→ **C6 외부 수집을 앞당겨 모수를 수백~수천으로 확대하는 것이 평가 신뢰도 관점에서 우선순위가 높다.**

### C2. 활용 목적 기반 자동 탐색·추천 〔2차 미이행 · 모비젠〕

흐름: 자연어 목적 → **질의 확장** → 하이브리드 검색(seed top-10) → **1-hop 그래프 확장**(+20~30) → 번들 스코어링·중복 제거 → **경량 재순위** → **근거 생성**

- 확장 점수 `score(dst) = max_over_seeds(seed_rrf × decay × weight)`, decay 0.5. **1-hop만.** 2-hop은 이 규모에서 전체 그래프를 반환한다.
- **질의 확장**: LLM 1회로 확장어 3~5개 → **키워드 채널에만** OR로 추가. 벡터 채널에 섞으면 주제가 흐려진다. 결과는 캐시.
  LLM 불가 시(§1.4) → **공기어(co-occurrence) 테이블** 상위 3개 추가. 완전 오프라인, 반나절.
- **재순위**: ① 규칙 기반 가산(제목 매칭·최신성·공식 출처)을 **항상 켜둔다**(0ms). ② 그 위에 **LLM listwise rerank(top-10, 1회 호출)**를 옵션 플래그로. ③ cross-encoder(`bge-reranker-v2-m3`)는 ONNX CPU 변환본이 약 2.3GB이고 **한국어 CPU 실측 자료가 없다** → 0.5일 벤치 후 판단.
- **근거 반환은 기계적 근거 우선**: `matched_terms`, `ts_headline` 하이라이트, 채널별 rank/score, 그래프 경로(`"A와 행정동코드로 조인 가능해서 함께 추천"` 같은 형태가 사람이 납득하는 근거). LLM 1문장 요약은 **선택 필드**로 두고 단독 반환 금지 — LLM 없이도 API가 동작해야 한다.

### C3. 템플릿 기반 파이프라인 〔2차 미이행 · SW모듈 귀속: 모비젠〕

**단계 인터페이스는 함수 하나로 통일**: `step(ctx: dict, params: dict) -> dict` (반환값을 ctx에 merge)
`ctx = {dataset_id, triggered_by, started_at, config, records, counts{new,updated,removed}, state}`
**멀티 아웃풋 금지** — 복잡도 폭발 방지.

- 단계 레지스트리: `fetch_dataset` / `collect` / `normalize` / `upsert` / `detect_removed` / `export_s3` / `record_provenance` / `update_registry`
- 실패 처리는 `on_error: fail | warn | skip` 3값이면 충분(기존 코드가 이미 "S3 export 실패는 경고, 수집은 성공"을 하고 있다)
- **재실행 단위는 데이터셋 전체**로 못 박는다. 단계별 체크포인트·부분 재개는 구현하지 않는다 — 수집이 upsert 기반이라 전체 재실행이 안전하고, 상태 저장 복잡도 대비 이득이 없다
- 러너 구현량 추정 **150~250줄**

- 🟩 **최소선**: 고정 4단계 템플릿 + 소스 스펙 주입
- 🟦 **목표선**: `templates/*.yaml` 3종(발견형 / 지표시계열형 / 검색형)으로 "템플릿 기반 생성" 문구에 직접 대응

⚠️ **조건분기·루프를 스펙에 넣지 않는다**는 선을 처음부터 긋는다. 넣기 시작하면 YAML이 읽기 어려운 DSL로 변질된다. 필요하면 훅으로 내보낼 것.

### C4. 동적 변화 파이프라인 자동 구성 〔4차 · SW모듈 귀속: 모비젠〕

#### 스케줄링 — **Airflow 미도입 권고 (ADR-007 재검토 필요, §6)**

K8s CronJob 1개를 **`*/5`**로 두고 `next_collect_at <= now()`인 데이터셋을 `LIMIT 20`으로 집어 실행.
`idx_data_registry_next` 인덱스가 **이미 존재**하고, `next_collect_at`도 **이미 매 실행마다 갱신되고 있다.**
`src/main.py`의 `run_dataset()`을 그대로 호출하면 되므로 **스케줄러는 실질 30줄**이다.

| 함정 | 대응 |
|---|---|
| 이전 틱이 실행 중인데 다음 틱 | CronJob `concurrencyPolicy: Forbid` **+** 데이터셋 단위 어드바이저리 락(둘 다) |
| 중복 실행 | `pg_try_advisory_lock(42, hash(dataset_id))` **2-키 형태**로 네임스페이스 분리. 세션 락이므로 커넥션 끊기면 자동 해제 — TTL 불필요. **PgBouncer 미사용 확인됨** |
| 긴 작업 | 세션 락 사용(트랜잭션 락은 수십 분간 트랜잭션을 열어둬야 해 부적절). Job `activeDeadlineSeconds` 상한 |
| 실패 반복으로 쿼터 소진 | 기존 `now+1h` 재시도에 **연속 실패 지수 백오프**(1h→2h→4h, 상한 24h) 추가 |
| 락 획득 실패 | **에러 아님.** debug 로그 후 skip — 다음 틱에 자연히 재시도 |

#### 동적 변화 감지 — 과제 핵심 문구의 분해

**① 스키마 드리프트**
첫 레코드가 아니라 **최대 200개 레코드의 필드 경로 합집합**(선택적 필드 때문에 첫 레코드만 보면 오탐 폭발).
점표기 평탄화 경로 + 타입 7종 축약 → `schema_hash = sha256(sorted([(path,type)]))`.
**타입 변화도 본다** — 비용이 거의 0이고 실무에서 더 자주 터지는 게 타입 변화(숫자가 문자열로 오기 시작)다.
심각도 분리: **필드 삭제·타입변경 = high, 필드 추가 = low.**
저장은 **해시가 바뀔 때만 1행 추가**(변경 이력), 그 외엔 `last_seen_at`만 UPDATE.

**② 볼륨·분포 드리프트**
고정 상수 대신 **직전 N=10회의 이동평균/표준편차**: `|x-mean| > 3*std`, 단 `std = max(std, 0.1*mean)`로 바닥을 깔고 `n<5`면 판정 보류.
보조 규칙: **`row_count == 0`인데 직전이 0이 아니면 무조건 high** — 실무에서 가장 가치 있는 단일 규칙.
결측률은 비율이므로 절대 변화량 규칙(`|Δ| > 0.2`).

**③ 갱신 주기 자동 조정 (AIMD 변형)** — ⚠️ **합의 필요**

> 와이즈넛 「자동 실행 계약」(설계 초안 §4.3)이 산정 규칙을 명시했다:
> **차기 등록 예정일 → 갱신 주기 → 둘 다 없으면 주간.**
> 아래 적응형 조정은 이 계약에 없으므로 **도입하려면 별도 합의가 필요하다.**
> 설계(선언값을 덮어쓰지 않고 `adaptive_interval`을 따로 두는 방식)는 유지하되 적용은 보류한다.
> 우선 계약대로 구현하고, **"둘 다 없으면 주간" 폴백이 현재 코드에 없으므로 먼저 추가**한다.
변경 있음 → `interval = max(interval/2, min_interval)` / 변경 없음 → `interval = min(interval*1.5, max_interval)`
감소를 공격적(1/2), 증가를 보수적(1.5배)으로 **비대칭**하게 두는 게 핵심 — "놓치는 것"이 "낭비"보다 비싸다.
⚠️ **사람이 선언한 `accrual_periodicity`를 덮어쓰지 말 것.** `adaptive_interval` 컬럼을 따로 두고
`next_collect_at = now() + COALESCE(adaptive_interval, accrual_periodicity)`. 이러면 adaptive를 끄는 게 컬럼 NULL 처리로 끝난다.
**±10% 지터** 필수 — 없으면 모든 데이터셋이 같은 틱에 몰린다.
⚠️ 주기를 자동으로 줄이는 방향이라 **소스 약관·쿼터 위반 위험**이 생긴다. `min_interval` 하한을 소스별로 명시 선언하고 쿼터 소진 시 즉시 하한을 올리는 방어를 함께 넣을 것.

**④ "자동 재구성"의 범위 — 3등급 분기**

| 등급 | 변화 유형 | 처리 |
|---|---|---|
| **자동 적용** | 신규 필드 추가, 수집 주기 조정 | 즉시 반영 + 이력 기록 (되돌리기 쉬운 변화만) |
| **제안 → 승인** | 필드 삭제, 타입 변경, 응답 구조 변경 | `status='proposed'` + 제안 패치(JSON). 승인 시 소스 스펙 갱신 |
| **즉시 중단** | 인증 실패 지속, 수집 0건 연속 3회 | `status='error'`, 수집 중단, 알림 |

→ 과제 문서에 **"변화 유형별 위험도에 따라 자동 적용 / 승인 기반 반영 / 수집 중단으로 3단 분기하는 자동 재구성 정책"** 이라고 쓸 수 있고, **이건 과장이 아니라 사실이 된다.**

⚠️ 드리프트 임계값은 **초기 3~4주간 오탐이 난다**(이동평균 표본 부족). 초기에는 `high`만 알림, 나머지는 적재만.

### C5. 데이터 패키징 〔3·4차 · SW모듈 귀속: 모비젠〕

**RO-Crate 채택.** 자체 포맷을 만들지 않는다.

| 표준 | 판정 | 사유 |
|---|---|---|
| **RO-Crate 1.2** (`rocrate` 0.16.0, **Apache-2.0**) | **채택** | JSON-LD + schema.org 기반 → **기존 `jsonld_export.py`의 @context·엔티티 구조를 거의 그대로 재사용**. PROV-O를 `CreateAction`으로 표준 수용. 엔티티 단위 `license` 지정. ZIP/BagIt 어디에 담아도 되는 중립 포맷 |
| Frictionless Data Package | 탈락 | 표 형식 중심. 우리는 비정형 혼재이고 이미 DCAT/JSON-LD를 쓴다 → **어휘만 하나 더 늘어남**. 리니지 표현 불가 |
| BagIt (RFC 8493) | **부분 차용** | 체크섬·디렉터리 규약만 정의, **의미 메타데이터가 전혀 없음** → 단독으로는 "신뢰성 보장" 불가. `manifest-sha256.txt` 1장만 차용(외부 도구 호환성) |
| OCFL | 탈락 | 리포지터리 전체 버전관리 표준. 목적이 다름 |

**서명**

| 방식 | 판정 |
|---|---|
| SHA-256 매니페스트 | **필수** (비용 0, 외부 검증 쉬움) |
| HMAC(공유키) | **탈락** — 검증하려면 **수신자에게 비밀키를 줘야 한다.** 외부 배포에 구조적으로 부적합, 유출 시 위조 가능 |
| **Ed25519 분리 서명** | **채택(목표선)** — 개인키는 K8s Secret, 공개키만 배포. `cryptography`로 10줄. `key_id`로 회전 대응 |
| Sigstore/cosign | 탈락 — OIDC IdP + Rekor 공개 투명성 로그 전제. 폐쇄망 자체 호스팅은 과함 |

**리니지**: 기존 `dcat_provenance`(PROV-O)를 `CreateAction`으로 매핑 — `activity_type`→`name`, `agent`→`agent`+`instrument`, `started_at`/`ended_at`→`startTime`/`endTime`, `params`→`mi:params`, `rows_affected`→`mi:rowsAffected`.

**"능동형"의 해석**: 패키지를 미리 만들지 않고 **요청(`purpose` + `selector`)을 입력으로 그때그때 조립**한다. 목적별 프로파일이 포함 데이터셋·컬럼, 마스킹 규칙, 부여 라이선스를 다르게 결정.
`quality_flag IS NOT NULL`인 AI 메타는 기본 제외(프로파일로 조정).

- 🟩 **최소선**: RO-Crate + SHA-256 + BagIt 매니페스트 + ZIP + 검증 CLI(체크섬만)
- 🟦 **목표선**: + Ed25519 서명 + 능동형 selector + 발급 이력 추적 + `verify --signature`

⚠️ **국내 공공데이터 맥락에서 RO-Crate 적용 사례는 확인되지 않았다.** 과제 문서에서는 **"국제 연구데이터 패키징 표준 차용 + 국내 공공데이터 메타데이터 표준과의 매핑 테이블 제공"** 으로 포지셔닝할 것.
⚠️ `rocrate`는 아직 **0.x** → 버전 핀 고정 필수.

### C6. 탐색 확장·통합 + OpenAPI 〔3차 · 모비젠〕

**외부 포털 수집** — ⚠️ **공공데이터포털(data.go.kr)은 CKAN이 아니다.**

| 경로 | 인증키 | 판정 |
|---|---|---|
| 목록 파일데이터(CSV) | 불필요(추정) | **1단계 권장** — 가장 빠름 |
| DCAT 메타데이터 엔드포인트 | 불필요(추정) | DCAT 매핑에 최적 — **공식 문서로 엔드포인트·이용조건 확인 필요** |
| 오픈API | **필요**(활용신청, 승인 10분~3일) | 상세 명세 확인 필요 |

CKAN 계열(해외·일부 국내)은 `GET /api/3/action/package_search` — **공개 데이터셋 검색은 인증 불필요.**
`rows` 상한 기본 1000, `start`로 페이징, 종료 조건은 `count`. rate limit은 문서에 없으므로 **보수적으로 초당 1회.**
공공데이터 표준 에러코드: `22`(일일 한도) `23`(초당 한도) `29`(차단 IP) `20`(인증키) `05`(타임아웃) → 분기 처리 + 체크포인트 재개.

**DCAT 매핑 주의점**
① **1 Dataset : N Distribution** — 포맷별 배포가 여럿이다. 1:1로 접으면 포맷 필터가 불가능해짐 → `dcat_distribution` 자식 테이블 필요
② **외부 ID를 내부 `dataset_id`로 쓰지 말 것** — `(source_system, source_id)` 복합 유니크 + 내부 ID 자체 발급
③ `accessURL`(랜딩/API) vs `downloadURL`(직접 파일)을 포털들이 섞어 쓴다
④ `keyword`(자유 태그) vs `theme`(통제어휘) 구분. 국내 분류체계는 DCAT theme와 1:1이 아님 → **매핑 테이블 별도, 미매핑은 NULL 유지(억지 매핑 금지)**
⑤ `accrualPeriodicity` 코드값이 포털마다 상이 → 정규화 사전
⑥ 날짜 타임존 누락 → KST 가정 명시
⑦ `license`/`rights` 미기재가 흔함 → 필수 아님 처리

**구분 플래그**: `origin('internal'|'external')`, `source_system`, `source_id`, `source_url`, `harvested_at`, `is_active`(소프트 삭제).
외부 레코드는 설명이 짧아 **임베딩 품질 분포가 내부와 다르다** → 평가 지표를 `origin`별로 분리 산출.

> 💡 **부수 효과가 본 효과보다 클 수 있다**: 외부 수집으로 모수가 수백~수천이 되면 **C1의 지표 포화 문제가 해소된다.**

**OpenAPI (FastAPI)**

| Method | Path | 비고 |
|---|---|---|
| GET | `/health` | |
| POST | `/v1/search` | `mode`(hybrid/vector/keyword), `filters`, `rrf_k`, `weights`, `explain` |
| GET | `/v1/datasets/{id}` | DCAT 상세 + distributions |
| GET | `/v1/datasets/{id}/related` | 1-hop 관계 + evidence |

- `rrf_k`·`weights`를 **API 파라미터로 노출** → 평가 스크립트가 같은 엔드포인트로 설정을 비교. **평가와 서비스가 같은 코드 경로를 타는 것이 중요.**

### C7. 외부 모듈 연계 ((s)LLM) 〔4차 · 모비젠〕

**자체 얇은 어댑터 + OpenAI 호환 `/v1/chat/completions` 규약 하나만.**

vLLM·Ollama·llama.cpp `llama-server`·주요 상용 API가 **모두 OpenAI 호환 엔드포인트를 제공**한다.
즉 **통합 레이어 없이도 "설정으로 교체 가능"이라는 요구는 이미 충족**된다.
LiteLLM(코어 MIT)을 처음부터 넣으면 의존성 트리 100+와 빠른 릴리스 주기를 떠안는다 → **비-OpenAI 호환 모델이 실제로 필요해질 때만** 백엔드 구현체로 추가. **Proxy는 미도입.**

**로컬 sLLM 현실성 (GPU 없음)**

| 런타임 | 판정 |
|---|---|
| **llama.cpp (`llama-server`)** | **채택** — 네이티브 CPU, GGUF 양자화, OpenAI 호환 |
| Ollama | 개발·PoC용 대안 |
| vLLM | 공식 CPU 백엔드는 문서상 "basic", avx512f 권장 → GPU 도입 전까지 미채택 |

> **CPU 상한은 사실상 4B급 Q4 양자화까지다.**
> 4B Q4 + 최신 다코어 CPU → 수십 tok/s로 **배치 메타데이터 생성(요약 200~300토큰)에는 충분**.
> 7~8B는 노후·저코어 CPU에서 한 자릿수 tok/s → **요약 1건당 30초~1분**, 수만 건 배치는 비현실적.
> 메모리: 4B Q4 ≈ 2.5~3GB, 8B Q4 ≈ 4.5~5.5GB.
> ⚠️ 인용 수치는 모두 2차 자료 — **실제 노드에서 `llama-bench` 측정 후 Pod 수·배치 크기 확정 필요.**

**재시도·degrade**: 지수 백오프 + 지터, 429는 `Retry-After` 존중, 5xx·타임아웃만 재시도, 4xx는 즉시 실패.
**동시성은 세마포어로 1~2건 고정** — CPU 추론은 동시 요청이 늘면 전체가 느려진다.
**서킷 브레이커**: 연속 실패 20회 시 엔드포인트 차단하되 **작업은 큐에 남긴다(소실 금지)**.
**타임아웃 2단**: 요청 60s + 배치 전체 예산(2시간) → 초과분은 다음 배치로 이월.

**재현성**: 프롬프트 템플릿은 **파일로 git 관리**, `prompt_id` + `sha256`을 결과마다 기록. 모델은 `model_id` + GGUF 해시 + 샘플링 파라미터.

#### 로컬 sLLM 구동 설계 (2026-10-27 가용 확인)

| 항목 | 결정 |
|---|---|
| 런타임 | **llama.cpp `llama-server`** — OpenAI 호환 `/v1/chat/completions` 노출 |
| 배포 | K8s **Deployment 1개 + ClusterIP Service**. 이미지는 사내 registry 경유, **`latest` 금지·버전 고정** |
| 모델 배치 | GGUF를 **PVC에 사전 적재**(폐쇄망 전제, 런타임 다운로드 없음). 파일 **sha256을 기록**해 재현성 확보 |
| 모델 | **Qwen3 4B급 Q4 (Apache-2.0)** — ⚠️ 체크포인트별 LICENSE 개별 확인 |
| 메모리 | 4B Q4 ≈ 2.5~3GB → Pod `requests` 4Gi / `limits` 6Gi 선에서 시작 |
| 스레드 | `--threads`를 노드 가용 코어에 맞춰 고정. 과다 지정은 오히려 느려진다 |
| 동시성 | **`--parallel 1` + 앱 세마포어 1~2.** CPU 추론은 동시 요청이 늘면 전체가 느려진다 |
| 컨텍스트 | `-c`를 **필요 최소로.** 프리필(프롬프트 처리)이 지배적이므로 입력 절삭이 가장 큰 절감 수단 |
| 호출 | 벤더 SDK 직접 호출 금지. **반드시 `src/llm/` 어댑터 경유** |

**선행 측정 절차 (Pod 수·배치 크기 확정용)**

1. 실제 노드에서 `llama-bench`로 **pp(프롬프트 처리) / tg(생성)** tok/s를 측정한다.
2. 1건 소요 ≈ `입력토큰 / pp_tok_s + 출력토큰 / tg_tok_s`
   (요약 기준 입력 약 1,500토큰 · 출력 약 250토큰으로 가정)
3. `대상 건수 × 1건 소요 ÷ 야간 배치 가능 시간` → 필요 Pod 수
4. 결과가 비현실적이면 **적용 범위를 좁힌다** — 전 소스 대신 1개 소스, 전건 대신 최신분 우선.
   이때도 나머지는 추출 요약(최소선)으로 채워지므로 **공백이 생기지 않는다.**

> ⚠️ 2차 자료 기준 감각: 4B Q4 + 최신 다코어 CPU는 수십 tok/s, 7~8B는 노후 CPU에서 한 자릿수 tok/s.
> **인용 수치를 그대로 쓰지 말고 반드시 자체 측정값으로 대체할 것.**

**장애 대응**: 연속 실패 20회 시 엔드포인트를 일정 시간 차단하되 **작업은 큐에 남긴다(소실 금지)**.
모델·런타임 장애가 메타데이터 파이프라인을 멈추게 해서는 안 된다 — `status='partial'`로 계속 진행한다.

## 4. 범위에서 제외하는 항목 — 근거와 과제 문서용 문장

억지로 끼워 맞추지 않고, **판단 근거를 남겨 "안 했다"가 아니라 "검토하고 선택했다"로** 만든다.

### 4.1 스키마·컬럼명 유사도 기반 조인 가능성 탐지 — 제외

우리 스키마는 소스별 고정 5종이다. 같은 `source_type`끼리는 유사도 1.0(정보량 0), 다른 타입끼리는 `dataset_id`·`collected_at` 같은 **운영 컬럼만 매칭**된다. 구현해도 "전부 조인 가능" 아니면 "전부 불가"만 나온다.
→ 컬럼명 대신 **값 집합 중첩**(뉴스 검색어 ↔ 쇼핑 카테고리명 ↔ 유튜브 태그)으로 치환하면 의미가 생기는데, 그건 `entity_shared` 엣지와 같은 것이므로 **B2에 흡수**한다.
→ 계획서에 명시되어 있다면 **"외부 데이터 수용 단계(C6)에서 적용"으로 시점을 미룬다.**

### 4.2 연관규칙(Apriori/FP-Growth) — 제외 권장

연관규칙은 "트랜잭션 = 아이템 집합"을 전제한다. **우리 DB에 장바구니·세션·동시소비 로그가 없다.**
억지로 "문서=트랜잭션, 키워드=아이템"으로 맞추면 돌아는 가지만, 그 결과는 **자카드나 PMI로 수십 줄이면 얻는 정보와 같고** support/confidence/lift 임계값 3개를 새로 자의적으로 정해야 한다.
→ 평가 항목에 명시적으로 박혀 있지 않은 한 넣지 않는다. 필수라면 `relation_type='assoc_rule'`로 **100줄 이내 부속 모듈**로만 두고 메인 분석 경로에서 분리한다.

### 4.3 그래프DB(Neo4j/Memgraph) — 미도입

> 본 과제의 관계 그래프는 데이터셋 수십 개와 아이템 수만 건 규모로, 생성되는 엣지 수가 수십만 건 이하이다. 이 규모에서는 관계형 데이터베이스의 인덱스 탐색과 재귀 CTE만으로 다중 홉 탐색 성능이 충분히 확보되며, 별도 그래프 데이터베이스 도입 시 발생하는 이중 적재 파이프라인·동기화 지연·운영 부담이 성능 이득을 상회한다. 또한 관계 정보를 메타데이터 카탈로그(DCAT)와 동일한 PostgreSQL 인스턴스에 보관함으로써 메타데이터와 관계 정보 간 참조 무결성을 외래키 제약으로 직접 보장할 수 있다. 따라서 관계를 PostgreSQL에 정규화 저장하고, 중심성·커뮤니티 탐지 등 전역 연산은 분석 시점에 메모리 상 그래프(NetworkX)로 수행하는 하이브리드 구조를 채택한다. **데이터 규모가 엣지 100만 건을 상회하거나 실시간 가변 길이 경로 질의가 상시 워크로드로 요구될 경우 그래프 데이터베이스 전환을 재검토한다.**

### 4.4 외부 워크플로 오케스트레이터(Airflow 등) — 미도입 권고

> 본 과제의 수집 파이프라인은 데이터셋 간 의존관계가 없는 단일 선형 흐름이며, 실행 이력은 DCAT PROV 모델(`dcat_provenance`)에 이미 표준 형식으로 적재된다. 범용 워크플로 오케스트레이터는 의존성 해결·백필·분산 팬아웃을 제공하지만 본 과제의 실행 특성상 해당 기능이 사용되지 않으므로, 상시 구동 컴포넌트(스케줄러·웹서버·메타데이터 DB)의 운영 비용만 추가된다. 따라서 선언형 파이프라인 명세를 해석·실행하는 경량 실행기를 자체 구현하고, 스케줄링은 Kubernetes CronJob과 PostgreSQL 어드바이저리 락으로 구성한다. 향후 데이터셋 간 의존관계나 백필 요구가 발생할 경우, 실행 계약(`run(dataset_id)`)이 오케스트레이터 비의존적으로 설계되어 있어 외부 도구로의 이행 비용은 낮다.

마지막 문장은 **사실이다** — `src/main.py`에 이미 그 계약이 있다.

### 4.5 OpenSearch/Elasticsearch — 미도입

데이터셋 수십 건·트래픽 거의 0인 연구용 시스템에 상시 클러스터 1식과 PG↔ES 동기화 파이프라인(이중 진실원천)을 추가하는 것은, 얻는 것(Nori 형태소 품질)이 §3 C1으로도 대부분 확보되는 데 비해 비용이 비대칭적으로 크다.
**"PostgreSQL 단일 스택으로 하이브리드 검색을 구현했다"가 산출물로 더 방어하기 쉽다.**
→ 수십만 건 이상으로 확대되면 재검토.

### 4.6 데이터 품질 검증 프레임워크 — 미도입

필요한 검증은 ① 필수 필드 존재 ② 타입 ③ 건수 범위 ④ 결측률 4가지이고, **전부 C4의 드리프트 감지에 이미 포함**된다.
- Great Expectations: Data Context/Datasource/Checkpoint/Store 개념 스택이 자체 세계관을 요구 — 규모 대비 비용 역전
- pandera(MIT): DataFrame 전제. 우리는 dict 리스트를 다루므로 역방향
- ⚠️ **Soda Core: PyPI 4.28.0의 라이선스 메타데이터가 `Proprietary`** — 국책과제 산출물에 라이선스 불명확 의존성을 넣으면 안 된다. 도입 보류 강력 권고

### 4.7 VLM 이미지 캡셔닝 — 포기, CLIP으로 대체

CPU에서 VLM 캡셔닝은 이미지 인코더(ViT) + 수백~수천 이미지 토큰 프리필로 **1건당 수십 초~수 분**. 수천 건이면 며칠이다.
대체:
- 🟩 **이미지 기본 메타**: 해상도·종횡비·파일크기·포맷·대표색·평균 밝기·**pHash(중복 탐지)**. Pillow + imagehash, 1건당 수십 ms. ⚠️ **EXIF GPS는 제거**(개인정보)
- 🟦 **CLIP/OpenCLIP zero-shot 태깅**: 이미지 1회 인코딩(CPU 수백 ms~1초) + 사전 정의 한국어 라벨셋과 코사인 비교. **생성이 아니라 분류이므로 CPU로 감당 가능.** 임베딩을 pgvector에 넣으면 유사 이미지 검색까지 덤
- 💡 **영상은 썸네일 대신 이미 수집해 둔 자막을 텍스트 파이프라인에 태우는 것이 비용 대비 효과가 가장 크다**(§1.2)
