# P05 방법론 상세 정리 (코퍼스·쿼리·지표·통계 검정)

> 이 문서는 [PREREGISTRATION.md](PREREGISTRATION.md)의 확정 설계를 **왜·어떻게** 관점에서
> 자세히 풀어쓴 참고 문서다. 배경지식이 적어도 읽히도록 정의·직관·**우리 데이터 예시**를
> 함께 넣었다. 수식·판정 기준의 최종 권위는 PREREGISTRATION이다.

전체 흐름 한 장:

```
[코퍼스 결정] 14 카테고리 × 60편 = 840편          ← 다양한 영상 풀(gap 분산 확보)
      │
[임베딩] 썸네일/제목 → CLIP·mpnet 벡터 → gap 자동계산(라벨 X)
      │
[쿼리 결정] 초성 sweep → curation → 기준 기반 큐레이션 → 70쿼리(14×5)  freeze
      │
[retrieval] 각 쿼리로 Text/Visual/Fusion이 840편을 정렬 → 순위
      │
[라벨링] pooling 후보를 3인이 0/1/2 → median-of-3 → qrels(정답지)
      │
[채점·검정] MRR·NDCG·Recall / Δrank / gap → H1(Wilcoxon) · H2(Spearman)
```

## 1. 영상 코퍼스를 어떻게 뽑았나

### 1.1 목적 — "IR 평가셋"이 아니라 "다양한 영상 풀"
코퍼스의 목적은 **gap(시각-텍스트 간극)이 넓게 분포하는 영상 집합**을 확보하는 것이다.
검색 성능 평가는 쿼리·qrels가 담당하고, 코퍼스는 **"다양한 영상을 골고루 모으는 표집(sampling)"**
문제다. 이 둘을 개념적으로 분리한 것이 설계의 핵심이다.

### 1.2 표집 틀(sampling frame) — YouTube 공식 카테고리 14개
`videoCategories.list(regionCode='KR')`의 `assignable=true` 카테고리를 **주제 다양성 확보용
층화(stratification) 틀**로 쓴다. 카테고리마다 성격이 다른 영상(뉴스/스포츠/음악/게임/자동차…)이
모이므로 gap 분포가 넓어진다.

> ⚠️ **categoryId = Sampling Anchor, NOT Ground Truth.** 카테고리는 "골고루 모으기 위한
> 도구"일 뿐, "이 영상은 스포츠다" 같은 **정답 레이블로는 절대 쓰지 않는다**(H1/H2 어디서도).
> 제작자가 categoryId를 임의로 다는 경향이 있어 레이블로 신뢰할 수 없기 때문이다.

### 1.3 수집 절차(논리적 순서)
1. **카테고리당 복수 seed(검색어) 고정**(frozen, Appendix 수록) — 단일 seed 편향 방지.
2. `search.list`로 수집 → `videos.list`의 `categoryId`로 **사후 필터링**(search의 카테고리
   필터가 부정확함을 실측했기 때문).
3. **정렬 3혼합**(relevance + viewCount + date) — 인기·최신·관련성을 섞어 한쪽 편향 방지.
4. **채널당 최대 5편**(channel cap ≤5) — 한 채널 독식 방지, 채널 다양성 확보.
5. **seed 간 round-robin** — 한 seed가 카테고리를 독식하지 않게 번갈아 채움.
6. **Shorts 제외**: 영상 길이 **실측 60초 초과**만 남김(`videoDuration='long'`은 20분 초과라
   일반 영상을 배제 → 미채택).
7. **날짜 하한**: 2025-01-01 이후 게시분.

### 1.4 결과 규모와 근거
- **카테고리당 60편 × 14 = 840편**(사전 고정, best-effort 층화).
- 왜 60/840인가: (a) 카테고리별 **균형**(동일 N)으로 층화, (b) gap 분산·H2 상관 검정에
  충분한 영상 수, (c) 라벨링·임베딩 비용이 감당 가능한 규모.
- **확률표본이 아니라 층화표본**임을 명시(대표성 주장은 "2025년 이후 한국어 non-Shorts
  YouTube 영상의 카테고리 층화표본"으로 좁게 규정).
- 수집 단계별 감소(수집→categoryId 필터→중복 제거→…)는 **funnel 표**로 투명 보고.

## 2. 평가 쿼리를 어떻게 뽑았나

### 2.1 원칙 — 연구자가 만들지 않는다, 영상에서 뽑지도 않는다
- **연구자 임의 창작 금지**: 실제 사용자 검색어를 반영해야 하므로 **YouTube 공개 자동완성
  (Suggest)** 에서 생성한다(Google Trends=재현 불가, Naver DataLab=도메인 불일치로 미채택).
- **영상 텍스트에서 파생 금지**(KeyBERT 등): 코퍼스 영상 제목에서 쿼리를 만들면 "쿼리가
  코퍼스에 맞춰짐" → **순환논리(circularity)**. 그래서 쿼리(Suggest)와 코퍼스(seed)를 **독립
  구성**한다.

### 2.2 생성 — 초성(jamo) sweep
카테고리 term에 **초성 ㄱ/ㄴ/ㄷ…을 이어 붙여** Suggest를 촉발한다.
```
예: "뉴스 ㄱ" → 뉴스 경제·기자·교통사고·공장 …   "자동차 ㄴ" → 자동차 낙엽제거·냉각수 …
```
- **왜 초성인가**: 처음엔 음절 sweep(가/나/다…)을 썼는데, 이는 사실상 **ㅏ모음 음절만** 훑어
  거/게/고/구/기 등 다른 모음 완성어를 **구조적으로 누락**했다(예: 뉴스 경제/자동차 리뷰를
  못 잡음). 초성 sweep은 **해당 초성으로 시작하는 넓은 후보군**을 탐색해 이 결함을 고친다.
  (음절/초성/bare 추천검색어 3방식을 전수 비교해 초성 채택; §PREREG 2026-08-14b.)

### 2.3 선별(curation) — 사전 등록된 규칙 + 감사추적
raw 후보에 **사전 고정 규칙**을 적용해 제외하고, 무엇을 왜 뺐는지 전량 기록(→ Appendix
exclusion funnel):
- **navigational**(특정 채널/프로그램/인물: 뉴스타파·음악중심) → 제외.
- **category mismatch**(다른 카테고리 주제) → 제외.
- **상품/서비스**(보험·차량용품) → 제외.
- **content-search intent**(영상 콘텐츠를 찾는 검색)만 KEEP.
- 애매한 것은 강제 제외하지 않고 REVIEW → 사람 판정(감사추적 보존).

### 2.4 선정 — 기준 기반 사람 큐레이션 (검색·라벨링 前, 결과 blind)
curation 통과 pool(eligible)에서 **카테고리당 5개**를 **사전 정의 기준**으로 선정한다(IR
테스트컬렉션의 표준적 토픽 구성 방식):
- **배제**: 채널·프로그램·작품·인물·기관명(navigational), category mismatch, 상품/서비스,
  무의미 초성결합, 과도하게 특정한 쿼리.
- **선정**: `[카테고리 + 주제/활동]` 형태의 topical 쿼리를 **카테고리 내 주제 다양성**이
  확보되도록 5개. 모든 선정 쿼리는 자동완성 후보 풀에 존재(사용자 검색어 근거 유지).
- **blind 보장**: 선정은 retrieval·관련성 라벨링 **이전**에 완료 → gap/융합 결과를 보고
  고르지 않음. **선정 기준·최종 쿼리·후보 pool 전량을 공개**해 검증 가능.
- **배경(변경 이력 2026-08-24)**: 초기엔 `md5(SALT+query)` 결정적 표집을 썼으나, 초성 절단
  편향 제거(cap 비구속)로 풀이 커지자 랜덤 표집이 채널·작품·기관명 등 비-topical 후보를
  그대로 끌어오는 한계가 확인됨 → 기준 기반 큐레이션으로 전환(사전등록·라벨 前이라 HARKing 아님).

### 2.5 규모·동결
- **N=70 (14 카테고리 × 5)**. §0.6 Query Pilot(pool 크기·라벨링 부담 실측)로 56~84 범위에서
  70 확정.
- **Freeze 순서**: 쿼리 생성 → **Freeze** → Retrieval → Evaluation. **성능을 보고 쿼리를 바꾸지
  않는다**(HARKing 방지).

## 3. 정답지(qrels)를 어떻게 만드나

### 3.1 후보 풀(pooling)
쿼리마다 **Text-only ∪ Visual-only ∪ Late Fusion 각 Top10의 합집합**(중복 제거)을 후보로
삼는다. 한 시스템 상위만 라벨링하면 편향되므로 **세 시스템 후보를 합쳐** 공정하게 만든다.

### 3.2 3인 blind·독립 라벨링 → median-of-3
- 후보 (쿼리, 영상) 쌍마다 **3명이 독립적으로** 0/1/2를 매김(2=직접관련, 1=부분, 0=무관).
- **blind**: 어느 시스템이 뽑았는지 숨기고 쿼리별 셔플(위치·시스템 편향 차단).
- 최종 등급 = **세 판단의 중앙값(median)**. (A=B면 C가 값에 영향 없음 → C가 불일치 쌍만
  판정해도 결과 동일.)
- 신뢰도 = **Fleiss κ**(3인 전체)를 primary로 보고하고, 평가자 쌍별 **Cohen κ**를 보조로 제시.

### 3.3 zero-relevance 쿼리 제거
최종 qrels에서 **관련(등급≥1) 문서가 0개인 쿼리**는 채점 불가라 평가에서 제외(제거 수 투명
보고). 이건 필터가 아니라 "채점 불가 항목 정리"다.

## 4. 검색 지표 — 정의·수식·직관·예시

용어: 한 시스템이 쿼리에 대해 840편을 점수순으로 세운 것이 **순위(ranking)**, 특정 영상의
자리번호가 **rank**(1위가 가장 좋음).

### 4.1 Reciprocal Rank (RR) / MRR@10 — "첫 정답이 얼마나 위인가"
- **정의**: 쿼리 q에서 **첫 번째 관련(등급≥1) 영상의 rank가 r**이면 `RR = 1/r`. 상위 10위
  안에 관련 영상이 없으면 `RR = 0`.
- **MRR@10** = 모든 쿼리의 RR 평균.
```
RR = 1/r_first_relevant   (r ≤ 10, 아니면 0)
MRR@10 = (1/Q) Σ_q RR_q
```
- **직관**: 1위에 정답 → 1.0, 2위 → 0.5, 5위 → 0.2. 정답이 위일수록↑.
- **예시**: `자동차 냉각수`에서 첫 관련 영상이 Fusion 순위 **3위** → RR=1/3=0.33. Text에선
  **8위** → RR=1/8=0.125. 이 차이가 Fusion 개선.

### 4.2 NDCG@10 — "여러 정답을, 등급까지 반영해 얼마나 잘 배치했나"
- **정의**: 등급이 높은(2>1>0) 영상을 위에 둘수록↑. 위치가 내려갈수록 로그로 할인.
```
DCG@10 = Σ_{i=1..10} (2^{rel_i} − 1) / log2(i + 1)      (rel_i = i위 영상의 등급 0/1/2)
IDCG@10 = 이상적 정렬(등급 높은 순)로 계산한 DCG
NDCG@10 = DCG@10 / IDCG@10        (0~1, 1이 완벽)
```
- **직관**: MRR은 "첫 정답"만 보지만 NDCG는 **상위 10개 전체의 정답 배치 품질**을 본다.
  등급 2를 1보다 더 크게 보상(2^2−1=3 vs 2^1−1=1).
- **예시**: 상위 3개가 [등급2, 등급0, 등급1]이면 DCG=3/log2(2)+0/log2(3)+1/log2(4)=3+0+0.5=3.5.
  이상적 정렬 [2,1,0]이면 IDCG=3+1/1.585+0=3.63 → NDCG≈0.96.

### 4.3 Recall@10 — "정답 중 몇 개를 상위 10위에 넣었나"
```
Recall@10 = (상위10 안의 관련영상 수) / (그 쿼리의 전체 관련영상 수)
```
- **예시**: 쿼리에 관련 영상이 총 4편, 그중 3편이 상위10위 안 → Recall@10 = 3/4 = 0.75.

### 4.4 Δrank — "Fusion이 정답 영상을 몇 칸 올렸나" (H2의 핵심 재료)
```
Δrank(v, q) = rank_text(v|q) − rank_fusion(v|q)      (양수 = Fusion이 위로 올림)
```
- **관련(qrels≥1) 영상에 대해서만** 계산(무관 영상의 순위 변동은 무의미).
- **rank 범위 = 전체 평가 코퍼스(840) 내 순위**(Text·Fusion 모두 전체로 계산, Top-K 절단 없음
  → Top-10 밖이라도 Δrank 항상 정의). 성능 지표(@10)와 달리 Δrank는 순위 이동을 온전히 담는다.
- **예시**: 정답 영상이 Text 8위 → Fusion 3위 → Δrank = 8−3 = **+5**.

### 4.5 gap — "썸네일이 제목과 얼마나 다른 정보를 담나" (자동, 라벨 X)
```
gap = 1 − cos( center(썸네일 임베딩), center(제목 임베딩) )     (centered = 모달별 평균 차감)
```
- 높을수록 썸네일이 제목에 없는 정보를 담음 → 시각 채널이 보완할 여지↑.

## 5. 통계적 검정 — 자세한 설명 + 우리 데이터 예시

### 5.1 Wilcoxon 부호순위 검정 (signed-rank test) — H1의 주 검정
**언제 쓰나**: 같은 대상(쿼리)에 **두 조건(Text vs Fusion)의 쌍(paired)** 점수가 있고, 그 차이가
정규분포라는 보장이 없을 때. **비모수(non-parametric)** 검정 — 순위만 쓰므로 극단값·비정규에
강함(paired t-test의 대안).

**가설**:
- H0(귀무): Fusion과 Text의 RR@10 차이의 중앙값 = 0 (효과 없음).
- H1(대립): 중앙값 ≠ 0 (양측) 또는 > 0 (단측, "Fusion이 낫다").

**절차**:
1. 쿼리별 차이 `d_q = RR_fusion − RR_text` 계산.
2. `d_q = 0`인 쿼리는 제외.
3. `|d_q|`를 작은 순으로 **순위(rank)** 매김(동점은 평균 순위).
4. 순위에 원래 부호를 붙임(signed rank).
5. **W+ = 양수 순위 합, W− = 음수 순위 합**. 검정통계량 `W = min(W+, W−)`.
6. 표본이 크면(≥~20) **정규근사**: `z = (W+ − n(n+1)/4) / sqrt(n(n+1)(2n+1)/24)` → p값.
7. **p < 0.05**면 H0 기각(Fusion 효과 유의).

**우리 예시**(설명용 5쿼리; 실제는 ~70):

| 쿼리 | RR_text | RR_fusion | d = fus−text | |d| 순위 | signed rank |
|---|---|---|---|---|---|
| q1 | 0.20 | 0.50 | +0.30 | 3 | +3 |
| q2 | 0.33 | 0.33 | 0 | (제외) | — |
| q3 | 0.10 | 0.25 | +0.15 | 2 | +2 |
| q4 | 1.00 | 0.50 | −0.50 | 4 | −4 |
| q5 | 0.14 | 0.20 | +0.06 | 1 | +1 |

→ W+ = 3+2+1 = 6, W− = 4, W = min = 4. (n=4는 검정력이 낮아 설명용일 뿐 — 실제 N≈70이면
정규근사로 p 산출.) **해석**: 대부분 쿼리에서 Fusion이 개선(양수)하나 q4처럼 반례도 있어,
전체가 유의한지를 **부호와 크기(순위)를 함께** 따져 판정한다.

> **왜 t-test가 아니라 Wilcoxon인가**: RR@10은 1, 0.5, 0.33처럼 **이산적·치우친 분포**라 정규성
> 가정이 약하다. Wilcoxon은 순위만 쓰므로 이 문제에서 자유롭고 IR에서 표준적이다.

**H1(=논문 RQ2) 판정**: 유의성은 **Wilcoxon p<0.05** 단독으로 본다. 효과의 크기는 **MRR·NDCG·
Recall의 절대 변화량 + 부트스트랩 95% CI + rank-biserial correlation**으로 **별도 보고**한다
(유의성과 효과 크기를 분리; 임의의 개선 임계값은 두지 않음). [2026-08-18 개정: 구 '+0.05 MRR
임계' 제거 — 0.05에 근거 없음]

### 5.2 Spearman 순위상관 검정 — H2(=논문 RQ1)의 주 검정
**무엇을 보나**: 영상별 **gap**과 **median Δrank**가 "커지면 같이 커지는" 관계인지.

**정의**: 두 변수를 각각 **순위로 바꾼 뒤 상관**을 잰다(선형이 아니라 단조 관계를 봄).
```
ρ = 1 − 6 Σ d_i² / (n(n²−1))       d_i = (gap 순위 − Δrank 순위)_i,  n = 영상 수
```
- ρ ∈ [−1, 1]. **ρ>0 & p<0.05**면 "gap 클수록 Δrank 크다"(H2 지지).
- **왜 Spearman(순위)인가**: gap↔Δrank 관계가 직선이라는 보장이 없고, 우리 주장은 "**높으면
  대체로 크다**"는 **단조** 관계라서. 순위 기반이라 스케일·극단값에 강함.

**우리 예시**(설명용 5영상):

| 영상 | gap | median Δrank | gap 순위 | Δrank 순위 | d | d² |
|---|---|---|---|---|---|---|
| A | 0.68 | +9 | 5 | 5 | 0 | 0 |
| B | 0.55 | +5 | 4 | 4 | 0 | 0 |
| C | 0.40 | +2 | 3 | 2 | +1 | 1 |
| D | 0.30 | +3 | 2 | 3 | −1 | 1 |
| E | 0.19 | 0 | 1 | 1 | 0 | 0 |

→ Σd² = 2, ρ = 1 − 6·2/(5·24) = 1 − 0.1 = **0.90** (강한 양의 상관 → H2 지지).
gap 높은 A·B가 Δrank도 크고, gap 낮은 E는 Δrank 0인 패턴.

### 5.3 부트스트랩 95% 신뢰구간 (bootstrap CI)
- **왜**: 위 ρ·MRR 차이가 **얼마나 안정적인지**를 보이려고.
- **방법**: 표본(쿼리 또는 영상)을 **복원추출로 1,000번 재표집** → 매번 통계량 계산 → 그 분포의
  **2.5%~97.5% 지점**을 신뢰구간으로. 구간이 0을 포함하지 않으면 유의.

### 5.4 MDES (최소 탐지 가능 효과크기)
- 표본 수 N, α=0.05, power=0.80에서 **우리가 탐지할 수 있는 최소 상관 ρ_min**을 사전 보고.
- "N이 작아 약한 상관은 못 잡을 수도 있다"는 **검정력 한계를 정직하게** 밝히는 장치.

### 5.5 카테고리 교란 통제 — cluster-robust 회귀 (H2 secondary)
gap 분포가 카테고리마다 달라 **허위 상관**(실은 카테고리 효과)일 수 있다. 이를 통제:
```
Δrank_{q,v} = β0 + β1·gap_v + (카테고리 더미) + ε      SE는 video로 클러스터링
```
- **β1 > 0 & 유의**면, 카테고리를 통제한 뒤에도 gap 효과가 남는다는 뜻(H2 강화).
- **video 클러스터-robust SE**: 한 영상이 여러 쿼리 쌍에 반복 등장(반복측정)하므로, 그 상관을
  무시한 과소추정 SE를 보정.

### 5.6 효과크기 Cohen's d — "실질적으로 큰 차이인가"
- gap을 상·중·하 3등분해 **상위군 vs 하위군의 Δrank 차이**를 표준화:
```
d = (mean_high − mean_low) / pooled_SD      (0.2 작음 / 0.5 중간 / 0.8 큼, Cohen 1988)
```
- p값(유의성)뿐 아니라 **효과의 크기**까지 보고.

### 5.7 라벨 일치도 — Cohen's κ / Fleiss κ
```
κ = (p_o − p_e) / (1 − p_e)      p_o=관측 일치율, p_e=우연 일치율
```
- Cohen κ: 2인용(A-B). Fleiss κ: 3인 이상. **≥0.6(substantial)** 목표.
- 우연 일치를 제거한 "진짜 일치도" → 정답지 신뢰성 지표.

## 6. 무엇을 무엇과 비교하나 — 우리 데이터로 정리

| 가설 | 비교 대상 | 지표 | 검정 | 성공 기준 |
|---|---|---|---|---|
| **H1=RQ2** (융합 효과) | **Text-only vs Fusion(α=0.5)** | 쿼리별 RR@10 | **Wilcoxon** 부호순위 | p<0.05 (효과크기는 Δ·95% CI·rank-biserial 별도 보고, 임의 임계값 없음) |
| **H2=RQ1** (gap–개선 연관) | **gap(영상) vs median Δrank(영상)** | Spearman ρ | ρ 유의성 + bootstrap CI (+ 회귀는 exploratory) | ρ>0 & p<0.05 (연관, 예측 아님) |

**H1 흐름(예)**: 70쿼리 각각에서 Text 순위·Fusion 순위를 내고 → 쿼리별 RR@10 두 개 → 차이에
Wilcoxon → "Fusion이 전반적으로 정답을 위로 올리나?" 판정. (α=0.5는 사전 고정; α grid는 곡선만
sensitivity로 보고, "최고 α"를 성능 보고 고르지 않음.)

**H2 흐름(예)**: 관련(qrels≥1) 영상마다 (여러 쿼리에서의) Δrank를 **median으로 집계** → 그 영상의
**gap**과 짝 지어 → 전체 영상에 Spearman → "gap 큰 영상일수록 Fusion 개선이 큰가?" 판정.
+ 카테고리 stratified/회귀로 교란 통제, raw vs centered gap로 sensitivity, Cohen's d로 효과크기.

**주장 수위**: gap은 "**높으면 반드시 도움**"이 아니라 "**도움을 예측하는 유의한 변수**"(확률적).
그래서 반례(gap 높은데 개선 없음)가 있어도 성립하며, 그 반례를 논문에 공개한다.
