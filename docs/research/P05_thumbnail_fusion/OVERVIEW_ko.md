> 풀어쓴 안내문). 정식 정의·수식·통계 절차는 논문과 [PREREGISTRATION.md](PREREGISTRATION.md)를 본다.
> 처음 보는 용어는 **맨 아래 [용어 미니사전](#용어-미니사전)** 에 한 줄 설명이 있다.

## 0. 한 문장 요약

**영상 검색에서 썸네일의 시각정보가 검색에 실제로 기여하는지, 그리고 그 기여를 라벨링 없이
자동 계산되는 하나의 숫자(`gap`, 썸네일–제목 의미 격차)로 설명할 수 있는지**를 한국어 YouTube
데이터로 분석한 논문이다.

> **실제 결과(2026-08-27 확정)**: 썸네일 단독은 텍스트보다 약했고, 동일가중 융합은 검색 성능을
> 유의하게 개선하지 못했다. 다만 융합은 관련 영상의 **깊은 순위를 재배치**하는 양상이 있었고,
> 낮은 시각 가중에서 일부 지표의 탐색적 개선이 관찰되었다. gap–순위변화의 관계는 유의하지
> 않았고 카테고리 이질성에 영향받아, **단일 gap 하나로는 시각 기여를 설명하기 어렵다**는 결론.
> 즉 "썸네일=강한 신호"도, "썸네일=무용"도 아니며, 단일 gap 설명은 한계가 있었다.

---

## 1. 무슨 문제를 푸는가 (배경)

### 지금 상황
YouTube에서 영상을 검색하면, 시스템은 대부분 **제목·설명·태그 같은 텍스트**만 보고 순위를
매긴다. 정작 사람이 클릭할 때 크게 참고하는 **썸네일 이미지**는 검색에 거의 안 쓰인다.

### 이미 알려진 것
"썸네일 같은 시각 정보를 텍스트와 **합치면(fusion)** 검색 성능이 좀 오른다"는 건 여러
연구가 보고했다. 그래서 이 논문은 "성능이 오른다"를 다시 증명하는 게 목표가 **아니다.**

### 아직 모르는 것 (이 논문의 출발점)
성능이 오른다면 — **모든 영상에서 골고루 오르는가, 아니면 특정 영상에서만 오르는가?**

이 구분이 실무에서 중요하다. 썸네일을 이미지로 분석하는 건 **계산 비용**이 든다. 만약
"일부 영상에서만 도움이 된다"면, 그 일부만 골라서 처리하면 비용을 아낄 수 있다. 문제는
**"어떤 영상이 그 일부인지"를 미리 아는 방법**이 없다는 것이다.

### 이 논문의 답
그 "어떤 영상"을 미리 골라내는 자동 지표를 제안한다. 그게 아래의 `gap`이다.

---

## 2. 핵심 아이디어: `gap` (시각-텍스트 의미 격차)

### 직관 먼저
- 어떤 영상은 **제목만 봐도 내용이 충분히 설명된다.** 이때 썸네일은 제목을 그림으로
  반복할 뿐이라, 검색에 **새 정보를 거의 안 준다.**
- 어떤 영상은 **썸네일에 제목엔 없는 정보**가 들어 있다. 이때는 썸네일이 검색에 도움이
  될 **여지**가 생긴다.

→ 그래서 "썸네일이 도움 될 여지"는 결국 **"썸네일이 제목과 얼마나 다른 내용을 담는가"**로
바꿔 말할 수 있다. 이 '다른 정도'를 숫자로 잰 것이 `gap`이다.

### 어떻게 숫자로 재는가
1. 썸네일 이미지와 제목 텍스트를 각각 **임베딩**(embedding, 의미를 담은 숫자 벡터)으로
   바꾼다. 이때 이미지와 텍스트를 **같은 공간**에서 비교할 수 있게 해주는 모델(CLIP)을
   쓴다.
2. 둘이 얼마나 **비슷한 방향**을 가리키는지 **코사인 유사도**(cos, 1에 가까울수록 비슷)로
   잰다.
3. `gap = 1 − (유사도)`. 즉 **비슷할수록 gap이 작고, 어긋날수록 gap이 크다.**

> 참고: 이 "이미지-텍스트 유사도" 계산 자체는 새로 발명한 게 아니라 이미 널리 쓰이는
> 방식(CLIPScore)이다. 이 논문의 새로움은 **그 숫자를 "검색에 도움이 될지 예측하는
> 변수"로 새로 해석**한 데 있다.

### 왜 좋은가
- **라벨링이 필요 없다.** 사람이 "이 썸네일은 인물형/제품형…" 하고 분류할 필요 없이,
  검색 시스템이 이미 만드는 임베딩만으로 자동 계산된다.
- **재현 가능하다.** 사람 주관이 안 들어가므로 누가 돌려도 같은 값이 나온다.

## 3. 무엇을 확인하려 하는가 (연구 질문과 가설)

이 논문은 질문을 **두 개**로 나눈다. 하나는 기반 확인용, 하나가 진짜 기여다.

| | 질문 | 역할 | 검증하는 가설 |
|---|---|---|---|
| **RQ2**(성능) | 썸네일을 텍스트와 합치면 검색이 **전반적으로** 좋아지는가? | 기반 확인 | **H1** |
| **RQ1**(조건) | `gap`이 큰 영상일수록 썸네일이 검색을 더 많이 개선하는가? | **핵심 기여** | **H2** |

아래는 **사전등록한 가설(검증 대상)** 이다. *실제 결과는 둘 다 확인되지 않았다* — §0의
결과 요약 참조.

- **H1 (성능):** 썸네일+텍스트 결합이 텍스트만 쓴 것보다 검색 성능이 통계적으로 유의하게
  높다. → *결과: 확인 안 됨(동일가중 융합 개선 없음).*
- **H2 (조건, ★핵심):** `gap`이 큰 영상일수록 썸네일 결합으로 인한 **검색 순위 개선폭이
  크다.** → "썸네일이 **언제** 도움이 되는지"를 `gap`으로 설명하려는 가설. *결과: 확인 안 됨
  (gap–순위변화 관계 유의하지 않음).*

> **주장 수위(중요):** "gap이 높으면 **반드시** 도움 된다"가 아니라, "gap은 도움 여부를
> **예측하는 데 유용한 변수**"라는 약한(확률적) 주장을 한다. 그래서 gap이 높은데도 도움이
> 안 된 **반례**가 나와도 논문이 무너지지 않고, 그 반례를 오히려 논문에 공개한다.

## 4. 어떤 데이터를 쓰는가

### 영상 (검색 대상 = 코퍼스)
- **한국어 YouTube 영상 840편.**
- YouTube 공식 카테고리 **14개 × 각 60편 = 840편**으로 **균형** 있게 모았다.
  (예: 뉴스·스포츠·음악·게임·여행·자동차·과학·동물 등)
- **쇼츠(Shorts) 제외**: 실제 길이가 60초 넘는 영상만 남겼다.
- ⚠️ **카테고리는 "골고루 모으기 위한 도구"일 뿐,** "이 영상은 스포츠다" 같은 **정답
  라벨로는 절대 쓰지 않는다**(카테고리를 정답으로 쓰면 분석이 오염되기 때문).

### 검색어 (쿼리)
- 실제 사용자가 칠 법한 검색어를 쓴다. 연구자가 지어내지 않는다.
- **YouTube 자동완성(검색 제안)**에서 후보를 긁어온 뒤, **미리 정한 규칙으로 걸러낸다:**
  - 뺀다: 특정 채널·프로그램 이름 찾기(예: "나혼자산다"), 다른 카테고리 얘기, 상품/서비스
    구매성 검색(예: "보험", "중고 가방").
  - 남긴다: 실제 영상 **내용**을 찾는 주제성 검색.
- 최종 개수는 라벨링 부담을 보고 정했다 — **70개(14 카테고리 × 5)**. 검색어는 카테고리
  이름에 초성(ㄱ·ㄴ·ㄷ…)을 붙여 YouTube 자동완성을 넓게 수집한 뒤 걸러내 뽑았다.

### 정답지 (qrels = 어떤 영상이 어떤 검색어에 관련 있는가)
- 검색어마다, 여러 방식이 뽑은 상위 결과를 **모아서(pooling)**, **평가자 3명이 서로
  못 보게 독립적으로** 0/1/2를 매기고, 세 판단의 **중앙값(median)** 으로 정한다.
- 세 사람 판단이 얼마나 일치하는지(κ)도 함께 보고해 신뢰도를 투명하게 밝힌다.

## 5. 어떻게 실험하는가

### 5-1. 세 가지 검색 방식을 비교
| 방식 | 무엇으로 순위를 매기나 |
|---|---|
| **Text-only** | 제목 텍스트만 |
| **Visual-only** | 썸네일 이미지만 |
| **Late Fusion** | 둘의 점수를 **가중합** (`α`로 비율 조절, 기본 반반 `α=0.5`) |

> `α`(알파)는 텍스트와 이미지를 몇 대 몇으로 섞을지 정하는 값이다. 이 논문은 결과를 보고
> "제일 좋은 α"를 고르지 **않는다**(그건 반칙 — 정답을 보고 맞추는 셈). 그냥 공정하게
> 반반(`α=0.5`)을 미리 정해 쓰고, 나머지 비율은 참고용 곡선으로만 보여준다.

### 5-2. 핵심 측정값: `Δrank` (순위가 얼마나 올랐나)
관련 있는 영상 하나가,
- 텍스트만 썼을 때 검색 순위 = `rank_text`
- 썸네일까지 합쳤을 때 순위 = `rank_fusion`

**`Δrank = rank_text − rank_fusion`** → **양수면 썸네일 덕에 순위가 올라갔다**는 뜻.

### 5-3. 그래서 무엇을 보나
- **H1 검증:** 결합 방식이 텍스트-only보다 검색 성능(MRR@10 등)이 유의하게 높은지
  통계 검정(Wilcoxon).
- **H2 검증(핵심):** 영상별 `gap`이 클수록 그 영상의 `Δrank`도 큰지 **상관관계**를 본다
  (Spearman 상관). "gap이 크다 → 순위 개선도 크다"가 통계적으로 성립하면 가설 지지.
- 추가로: 카테고리 때문에 생기는 **착시 상관**을 걸러내는 보조 분석, `gap`을 상·중·하로
  나눴을 때 개선폭 차이가 실질적으로 큰지(효과 크기 Cohen's d)까지 본다.

### 5-4. 정직성 장치 (미리 못박아 둔 것들)
- 가설·데이터 규모·분석 방법을 **실험 결과를 보기 전에** [PREREGISTRATION.md](PREREGISTRATION.md)에
  고정했다(결과 좋게 나오라고 사후에 방법을 바꾸는 것[HARKing]을 막기 위함).
- 실패/반례를 숨기지 않고 논문에 싣는다.

## 6. 실제로 무엇을 알아냈나 (결론)

- **당초 가설(“gap이 낮으면 썸네일 생략, 높으면 적용하는 선별 색인”)은 지지되지 않았다.**
  동일가중 융합이 평균 성능을 못 올렸고, gap도 기여 영상을 안정적으로 식별하지 못했다.
- 대신 알아낸 것: 썸네일은 **강한 검색 신호는 아니지만 무용하지도 않으며**, 융합은 상위
  결과보다 **후순위(깊은 순위) 관련 영상을 재배치**했다. 낮은 시각 가중에서 일부 지표의
  탐색적 개선이 있었으나 카테고리마다 방향이 달랐다.
- 즉 이 논문의 기여는 "성능 올리는 새 기법"이 아니라, **시각 정보의 검색 기여와 그 설명 변수
  (gap)를 분석**하고, **단일 gap 하나로는 그 기여 조건을 설명하기 어렵다**는 것을 실증한 데 있다.

## 7. 한눈에 보는 흐름

```
                    ┌─────────────────────────────────────────────┐
   YouTube 영상     │  썸네일 ──▶ [CLIP 이미지 인코더] ──▶ 이미지 벡터 │
   840편            │  제목   ──▶ [CLIP 텍스트 인코더] ──▶ 텍스트 벡터 │
                    └──────────────┬──────────────────────────────┘
                                   │  두 벡터의 어긋난 정도
                                   ▼
                            gap = 1 − 유사도        ← 영상마다 자동 계산 (라벨링 X)
                                   │
   검색어(쿼리) ──▶ 세 가지 검색(Text / Visual / Fusion) ──▶ 순위
                                   │
                    영상별 Δrank = (텍스트 순위) − (결합 순위)   ← 순위가 오른 정도
                                   │
                                   ▼
             ★ gap이 클수록 Δrank도 큰가?  (Spearman 상관 = H2)
                                   │
                                   ▼
             [결과] gap–Δrank 관계 유의하지 않음 → 단일 gap으로 설명 한계
```

## 용어 미니사전

| 용어 | 한 줄 설명 |
|---|---|
| **임베딩 (embedding)** | 이미지나 문장의 '의미'를 숫자 벡터로 바꾼 것. 비슷한 의미면 벡터도 비슷해진다. |
| **CLIP** | 이미지와 텍스트를 **같은 공간**에 넣어 서로 비교할 수 있게 학습한 모델(OpenAI, 2021). |
| **코사인 유사도 (cosine similarity)** | 두 벡터가 얼마나 같은 방향을 가리키는지. 1에 가까울수록 비슷, 0이면 무관. |
| **gap** | `1 − (썸네일·제목 유사도)`. 이 논문의 핵심 지표. 클수록 썸네일이 제목과 다른 내용을 담음. |
| **fusion (late fusion)** | 텍스트 점수와 이미지 점수를 각각 낸 뒤 가중합해 최종 순위를 내는 방식. |
| **α (알파)** | fusion에서 텍스트:이미지 섞는 비율. `0.5`면 반반. |
| **Δrank (delta rank)** | (텍스트만 썼을 때 순위) − (결합했을 때 순위). 양수면 결합 덕에 순위가 오른 것. |
| **qrels** | "어떤 검색어에 어떤 영상이 관련 있는가"를 사람이 매긴 **정답지**. 검색 성능 채점 기준. |
| **pooling** | 여러 검색 방식의 상위 결과를 모아 정답지 후보를 만드는 표준 절차(한 방식에만 유리하지 않게). |
| **MRR / NDCG / Recall@10** | 검색 성능 점수들. 관련 영상이 상위에 잘 왔는지를 각각 다른 방식으로 잰다. |
| **Spearman 상관 (ρ)** | 두 값이 "커지면 같이 커지는" 순위 관계인지 재는 통계. H2 검증에 씀. |
| **Cohen's d / κ (kappa)** | d = 두 집단 차이가 실질적으로 큰지(효과 크기). κ = 평가자들이 얼마나 일치했는지(3인 전체=Fleiss κ primary, 쌍별=Cohen κ 보조). |
| **HARKing** | 결과를 본 뒤 가설·방법을 슬쩍 바꿔 잘 맞은 척하는 나쁜 관행. 사전등록으로 방지. |
| **적응형 검색 (adaptive retrieval)** | gap이 높은 영상에만 시각 처리를 적용하려던 **당초 구상**. 단, 본 연구 결과로는 지지되지 않았다(gap이 기여 영상을 안정적으로 식별하지 못함). |
| **카테고리 = Sampling Anchor** | 카테고리는 영상을 **골고루 모으는 도구**로만 쓰고, 정답 라벨로는 쓰지 않는다는 원칙. |
