## 초록

YouTube 영상의 API 메타데이터(제목·설명·태그)는 업로더 입력값으로 키워드 스터핑이나
콘텐츠 내용과의 불일치가 빈번하다. 자동 자막(STT) 트랜스크립트가 있지만 한국어 STT는
전문 용어 오인식이 심해 그대로 쓰기 어렵다. 본 연구는 STT 노이즈가 심한 한국어
트랜스크립트에서 공개 LLM으로 요약·키워드·개체명·콘텐츠 유형 4종의 구조화 메타데이터를
자동 추출하는 파이프라인을 제안한다. 기술 110편, 의료 50편, 뉴스 50편으로 구성된 영상
210편과 검색 평가용 Query-Relevance 쌍 50개로 평가한다. 사람이 직접 요약·키워드·개체명을
작성해 생성물과 비교하는 절차 대신, 이 메타데이터를 벡터 검색 인덱스에 추가했을 때
검색 정확도가 실제로 향상되는지만으로 가설을 검증한다. LLM 메타데이터를 모두 추가한
조건에서 NDCG@5가 API 메타데이터 단독 대비 0.078 향상되었으며(paired t-test,
*p* = 0.012), 이 향상의 대부분(0.053/0.078)은 개체명·콘텐츠 유형이 아니라 요약·키워드
추가 단계에서 이미 발생했다. 다만 도메인별로 나누면 의료 도메인에서는 향상이 통계적으로
유의하지 않았다(Δ=0.029, *p*=0.21) — STT의 전문 용어 오인식이 요약·키워드 단계에서부터
핵심 정보를 이미 지워버리는 경우가 많았기 때문이다. 무료 Groq API 모델(llama-3.1-8b,
gemma2-9b)을 유료 품질 상한 기준(GPT-4o-mini)과 비교한 결과 gemma2-9b가 근소하게
우세했고, GPT-4o-mini와의 검색 기여도 격차도 크지 않아(NDCG@5 차이 0.025) 무료
모델의 실용성을 뒷받침했다.

**Keywords:** large language models, information extraction, Korean NLP, ASR noise, structured
metadata generation, retrieval augmentation, few-shot prompting, YouTube

## 1. 서론

### 1.1 연구 배경 및 문제 정의

YouTube API 메타데이터(제목·설명·태그)는 업로더 입력값이라는 태생적 한계를 갖는다.
검색 노출을 위한 키워드 스터핑이 흔하고, 실제 콘텐츠 내용과의 불일치도 빈번하다.
자동 자막(STT) 기반 트랜스크립트는 콘텐츠 내용을 더 충실히 반영할 잠재력이 있지만,
한국어 STT는 전문 용어 오인식이 심해 그대로 활용하기 어렵다. 본 연구는 GPU 자원 없이
무료 API만으로 이 노이즈를 다루면서도 검색에 실제로 기여하는 구조화 메타데이터를
뽑아낼 수 있는지를, 인간 레퍼런스 작성 없이 검색 품질 지표만으로 실증한다.

### 1.2 연구 질문

> LLM이 생성한 메타데이터를 추가했을 때, 트랜스크립트가 없는 API 메타데이터만
> 사용한 경우 대비 검색 정확도가 통계적으로 유의하게 향상되는가?

### 1.3 기여점

1. STT 노이즈 유형 분류 및 전처리 파이프라인 (타임스탬프 제거, 반복 구문 병합,
   토큰 수 기반 청킹)
2. 요약·키워드·개체명·콘텐츠 유형 4종을 동시에 추출하는 구조화 출력 프롬프트 설계
3. 무료 LLM(Groq: llama-3.1-8b, gemma2-9b)의 한국어 실용 성능을 검색 품질
   향상 기여도로 측정 — 인간 레퍼런스 작성 없이 재현 가능한 평가 설계
4. LLM 메타데이터 추가 시 벡터 검색 품질 향상의 정량화 — 향상이 조건(요약+키워드
   vs. 개체명+콘텐츠유형)과 도메인에 따라 고르지 않다는 점을 실증

### 2.1 선행 연구 대비 위치

GPT-3(Brown et al., 2020)와 Emergent Abilities(Wei et al., 2022)는 모델 규모가
정보 추출 능력에 미치는 영향을 실증했지만 평가는 영어 벤치마크 중심이며, 생성
품질 자체를 평가할 뿐 하위 응용(검색) 성능으로 이어지는지는 다루지 않는다. 본
연구는 이 창발 능력이 한국어·8~9B급 오픈소스 모델·STT 노이즈라는 조건에서
**검색 기여도**로 나타나는지를 직접 측정하며, §6.3에서 그 기여가 조건(요약+키워드
vs. 개체명+콘텐츠유형)과 도메인에 따라 고르지 않음을 실증적으로 보인다. Llama
2(Touvron et al., 2023)의 한국어 이해 가능성이나 T5(Raffel et al., 2020)의
text-to-text 통일 프레임워크 역시 구조화 메타데이터 추출의 실용성이나 교착어 STT
노이즈 로버스트성을 직접 검증하지 않았다.

## 3. 제안 방법

### 3.1 파이프라인 구성

```
[youtube-transcript-api] → 원시 트랜스크립트
        ↓ 전처리
  - 타임스탬프 제거
  - 반복 구문 병합 (STT 버벅임 제거)
  - 토큰 수 계산 → 16K 초과 시 청킹
        ↓ LLM 호출 (Groq API)
  프롬프트: "아래 YouTube 트랜스크립트를 분석하여 JSON으로 반환하라.
             {summary, keywords, entities, content_type}"
        ↓ 파싱 및 검증
  - JSON schema validation
  - 빈 필드 fallback 처리 (title+description으로 재시도)
        ↓
  meta_youtube_video_ai 테이블 저장
```

### 3.2 Long Context 처리 전략

| 트랜스크립트 길이 | 전략 |
|----------------|------|
| ≤ 8K 토큰 | 전체 입력 |
| 8K ~ 32K 토큰 | Map-Reduce: 청크별 요약 → 최종 통합 |
| > 32K 토큰 | 앞·중간·뒤 3구간 샘플링 후 통합 |

### 3.3 구조화 출력 프롬프트

프롬프트는 요약(3문장 내외)·키워드(5~10개)·개체명(인물/기관/제품/기술 용어)·콘텐츠
유형 4개 필드를 하나의 JSON 객체로 동시에 요구한다. 4종을 한 번의 호출로 묶어
요청함으로써 무료 API의 일일 요청 한도(Groq 14,400 req/day) 안에서 영상당 호출
횟수를 최소화한다.

## 4. 실험 설계

### 4.1 데이터셋

| 항목 | 값 |
|------|-----|
| 영상 수 | 210편 (기술 110편 + 의료 50편 + 뉴스 50편) |
| 검색 평가용 Query-Relevance 쌍 | 50개 (2인 독립 관련성 판정, 불일치 6건은 제3자 조정) |
| 데이터 소스 | `meta_youtube_video`, `youtube-transcript-api` 원시 트랜스크립트 |

인간이 직접 요약·키워드·개체명을 작성하는 레퍼런스 구축 단계는 두지 않았다.

### 4.2 조건 비교

```
조건 A: 제목 + 설명 + 태그 (API 메타데이터만)
조건 B: 조건 A + LLM 요약 + 키워드
조건 C: 조건 B + 개체명 + 콘텐츠 유형
```

### 4.3 LLM 비교

```
llama-3.1-8b   (Groq, 무료)
gemma2-9b      (Groq, 무료)
GPT-4o-mini    (유료, 품질 상한 기준)
```

### 4.4 실험 절차

1. 영상 210편의 트랜스크립트 수집·전처리, Query-Relevance 쌍 50개를 2인 독립 판정.
2. 3개 LLM 각각으로 전체 영상에 대해 요약·키워드·개체명·콘텐츠 유형 생성.
3. 조건 A/B/C 각각으로 영상 210편을 임베딩·인덱싱(대표 모델 gemma2-9b 출력 사용)하고
   Query-Relevance 쌍 50개로 NDCG@5/MRR/Recall@10 측정.
4. 조건 C 기준으로 3개 LLM의 검색 기여도를 상호 비교.
5. 3개 LLM에 대해 영상당 평균 API 호출 횟수·응답 시간을 기록.

## 5. 평가 방법

### 5.1 검색 품질 향상

```
실험 절차:
1. 조건 A/B/C 각각으로 영상 210편을 임베딩·인덱싱 (gemma2-9b 출력 사용)
2. 50개 검색 쿼리를 각 조건에서 실행
3. 결과 상위 10개와 정답셋(Query-Relevance 레이블) 비교
```

| 지표 | 측정 대상 | 연결 이유 |
|------|----------|----------|
| NDCG@5 | 상위 5개 결과의 순위 품질 | 사용자는 보통 상위 몇 개만 확인 |
| MRR | 첫 번째 관련 결과의 순위 역수 평균 | 정확한 답을 얼마나 빨리 찾는지 |
| Recall@10 | 정답 중 상위 10개 안에 있는 비율 | 놓치는 관련 결과가 없는지 |

### 5.2 통계 검정 및 해석 기준

- **paired t-test** — 쿼리별 NDCG@5 차이(조건 C vs. 조건 A)의 유의성을 검정
  (p < 0.05 기준), 전체 및 도메인별로 각각 수행.
- 해석 기준: NDCG@5 Δ(C−A) ≥ 0.05 (p < 0.05) / 영상 1편당 Groq 호출 ≤ 3회,
  응답 시간 ≤ 10초

## 6. 결과

> ⚠️ 이하 수치는 전부 가상 데이터입니다.

### 6.1 검색 품질 향상 (조건별, gemma2-9b 메타데이터 사용)

| 조건 | NDCG@5 | MRR | Recall@10 |
|------|--------|-----|-----------|
| A (API 메타데이터만) | 0.598 | 0.531 | 0.688 |
| B (A + 요약 + 키워드) | 0.651 | 0.579 | 0.719 |
| C (B + 개체명 + 콘텐츠 유형) | **0.676** | **0.602** | **0.734** |

Δ(NDCG@5, C − A) = **0.078** / paired t-test: *t* = 2.68, *p* = **0.012**

해석 기준(Δ NDCG@5 ≥ 0.05, p < 0.05) 충족 여부: **충족**

조건별 증분을 분해하면 A→B 구간의 기여(Δ=0.053)가 B→C 구간의 기여(Δ=0.025)보다
두 배 이상 크다 — 검색 성능 향상의 대부분은 요약·키워드 추가에서 이미 발생했다.

### 6.2 LLM 모델 간 비교 (조건 C 기준)

| 모델 | NDCG@5 | MRR | Recall@10 |
|------|--------|-----|-----------|
| llama-3.1-8b (무료) | 0.658 | 0.583 | 0.712 |
| gemma2-9b (무료) | **0.676** | **0.602** | **0.734** |
| GPT-4o-mini (유료, 상한) | 0.701 | 0.628 | 0.751 |

gemma2-9b가 무료 모델 중 근소하게 우세했다. 유료 상한(GPT-4o-mini) 대비 검색
기여도 격차는 NDCG@5 기준 0.025로 크지 않아, 무료 모델도 실용적 대안이 될 수
있음을 시사한다.

### 6.3 도메인별 검색 품질 향상 (조건 C vs. A, gemma2-9b)

| 도메인 | Δ NDCG@5 (C − A) | paired t-test p-value | 해석 기준 충족 |
|--------|-------------------|------------------------|--------------|
| 기술 | 0.091 | 0.008 | 충족 |
| 뉴스 | 0.084 | 0.015 | 충족 |
| 의료 | **0.029** | **0.21** | **미충족** |

의료 도메인만 유의한 향상을 보이지 않았다. 전문 용어(약제명·시술명 등)의 STT
오인식이 요약·키워드 단계에서부터 핵심 정보를 지워버리는 경우가 잦았기 때문으로
관찰되었다 (§6.5 사례 2).

### 6.4 처리 효율

| 모델 | 영상당 평균 API 호출 횟수 | 평균 응답 시간 | 일일 처리 가능 영상 수 (14,400 req/day 기준) |
|------|--------------------------|---------------|----------------------------------------|

| gemma2-9b | 2.2회 | 5.1초 | 약 6,545편 |
| GPT-4o-mini | 1.3회 | 3.6초 | 별도 rate limit / 비용 기준 적용 (약 $0.004/편) |

해석 기준(호출 ≤ 3회, 응답 시간 ≤ 10초) 충족 여부: **모두 충족**

### 6.5 정성적 사례 분석

**사례 1 (요약·키워드만으로 충분히 커버된 경우)** — "HBM4 적층 구조 설명" 검색.
gemma2-9b가 생성한 개체명 필드는 STT 토큰화 오류로 "HBM4"를 "HBM"과 "4"로
분리 인식했지만, 요약과 키워드 필드에는 "적층", "메모리", "HBM4"가 정확히
포함되어 있어 조건 B 단계에서 이미 상위 순위로 올라왔다(Δrank 조건 A 대비
+6, 조건 C에서 추가 변화 없음). 개체명 필드의 국소적 오류가 검색 실패로
이어지지 않은 사례다.

**사례 2 (요약 단계부터 핵심 정보가 누락된 경우)** — "다한증 보톡스 시술 후기"
검색. STT가 "보톡스"를 "보독스"로 오인식해 요약 필드 자체가 시술명을 명시하지
못한 채 뭉뚱그려 서술되었고, 키워드·개체명에서도 누락되었다. 이 영상은 조건
B/C 모두에서 쿼리 "보톡스 시술 후기 영상"에 대해 상위 10위 밖으로 밀려났다
(Recall 실패 사례). 사례 1과 달리, 요약 단계에서부터 핵심 용어가 통째로
사라지면 이후 조건(B→C)에서 아무리 필드를 추가해도 만회되지 않는다.

이 두 사례는 §6.3의 의료 도메인 결과를 설명한다 — 의료 도메인의 STT 오류는
개체명 하나만의 문제가 아니라 요약 단계에서부터 정보 손실을 일으키는 경우가
많아, 조건 B/C를 거쳐도 검색 향상으로 이어지지 못했다.

## 7. 논의

**향상은 조건에 따라 고르지 않다** — A→B(요약+키워드 추가) 구간의 기여(Δ=0.053)가
B→C(개체명+콘텐츠유형 추가) 구간의 기여(Δ=0.025)보다 두 배 이상 컸다. 이는 4개
필드를 동시에 요구하는 현재 프롬프트 설계에서, 검색 관점의 한계효용이 요약·키워드
필드에 집중되어 있음을 시사한다. 개체명·콘텐츠 유형 필드가 여전히 유의한 증분
기여를 보이므로 완전히 불필요하지는 않지만, Groq 무료 호출 예산이 빠듯한 환경이라면
요약·키워드를 우선순위로 두는 것이 합리적일 수 있다.

**의료 도메인의 반례** — 전체 평균으로는 해석 기준을 충족했지만, 의료 도메인만
따로 보면 유의한 향상이 관찰되지 않았다(Δ=0.029, p=0.21). §6.5의 사례 2처럼
STT가 전문 용어 자체를 다른 단어로 오인식하면 요약·키워드·개체명 세 필드 모두
동시에 정보를 잃는다 — 이는 "필드를 더 추가하면 검색이 좋아진다"는 가정이
STT 품질이 특히 낮은 도메인에서는 성립하지 않을 수 있음을 보여준다. 프롬프트
개선만으로는 해결되지 않는, STT 단계의 구조적 한계로 보인다.

**무료 모델의 실용성** — gemma2-9b는 llama-3.1-8b보다 검색 기여도가 근소하게
높았고, 유료 상한(GPT-4o-mini)과의 격차(NDCG@5 0.025)도 크지 않았다. 인간 평가
없이 검색 품질만으로 비교했다는 점에서, "메타데이터가 사람이 보기에 그럴듯한가"가
아니라 "실제로 검색에 도움이 되는가" 기준으로는 무료 모델이 이미 실용적 대안이 될
수 있음을 뒷받침한다.

## 8. 한계

- Query-Relevance 쌍 50개, 평가자 2인 규모로는 통계적 검정력에 한계가 있다.
  특히 의료 도메인은 50개 쿼리 중 일부만 해당해 §6.3의 비유의 결과가 표본 부족
  때문인지 실제 효과 부재인지 완전히 분리하기 어렵다
- 인간 레퍼런스 기반 품질 평가(ROUGE-L, F1 등)를 생략했으므로, 생성된 메타데이터가
  "얼마나 사실에 부합하는가(factuality)"는 검색 품질 지표만으로는 직접 드러나지
  않는다 — 검색에 도움이 되었다고 해서 메타데이터 내용이 항상 정확하다는 보장은
  아니다
- Groq API rate limit(14,400 req/day) 하에서의 측정으로, 상용 유료 티어나
  온프레미스 배포 환경의 처리량과는 다를 수 있다
- 검색 평가는 gemma2-9b 출력을 대표로 사용했다(§6.1, §6.3) — llama-3.1-8b
  출력을 조건 B/C에 썼을 때도 도메인별 패턴이 동일한지는 확인하지 않았다
- Query-Relevance 쌍 50개는 기술 도메인에 다소 편중되었을 가능성이 있다

## 9. 결론

본 연구는 STT 노이즈가 심한 한국어 YouTube 트랜스크립트에서 공개 LLM으로 요약·
키워드·개체명·콘텐츠 유형을 추출하는 파이프라인을 제안하고, 인간 레퍼런스 작성
없이 검색 품질 지표만으로 이를 검증했다. 전체적으로는 API 메타데이터 단독 대비
검색 정확도가 통계적으로 유의하게 향상되었으나(NDCG@5 Δ=0.078, *p*=0.012), 그
향상은 (1) 조건별로 고르지 않아 대부분 요약·키워드 단계에서 발생했고, (2)
도메인별로도 고르지 않아 의료 도메인에서는 유의하지 않았다. 무료 LLM 중
gemma2-9b가 llama-3.1-8b보다 근소하게 우세했고 유료 상한과의 격차도 크지 않아
실용적 대안이 될 수 있음을 확인했다.

향후 연구로는 (1) 영상 썸네일 비전 결합 멀티모달 메타데이터로의 확장, (2)
트랜스크립트 변경 감지 시 자동 재생성 파이프라인 구축, (3) 의료 도메인처럼
검색 향상이 유의하지 않았던 영역에 한해 STT 후처리(전문 용어 사전 기반 보정)를
선별적으로 적용하는 저비용 개선 전략을 고려할 수 있다.
