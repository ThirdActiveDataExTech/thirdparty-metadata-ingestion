# P01. 상대 검색량 지수의 장기 연속 시계열 복원

## 연구 필요성 (Research Gap)

네이버 쇼핑인사이트·Google Trends 등 주요 검색 트렌드 API는 검색량 절대값 대신
**요청 범위 내 최댓값=100으로 정규화된 상대값**을 반환한다. 이 설계는 사용자 개인정보
보호와 API 남용 방지 목적이지만, 다음 두 가지 문제를 일으킨다.

1. **배치 간 비교 불가**: 한 번에 최대 N개 카테고리만 비교할 수 있어 여러 배치로
   나누어 호출하면 배치마다 M(최댓값 기준)이 달라진다.
2. **수집 구간 간 비교 불가**: 오늘 수집한 값과 3개월 전 수집한 값은 각각의 M
   기준이 달라 직접 연결하면 불연속 시계열이 생긴다.

기존 연구 대부분은 단일 호출 범위 내 상대 비교에 그치거나, 부연속 구간을 단순 이어
붙이는 방식을 사용한다. **Anchor 카테고리와 두 단계 Scale 보정(intra/inter)을
결합해 장기 연속 시계열로 복원하는 체계적 방법론**은 공개된 논문이 없다.

## 기여점 (Contribution)

- 상대 지수의 비연속성 문제를 수학적으로 정형화
- intra_scale (동일 수집 내 배치 간 보정)과 inter_scale (수집 구간 간 보정) 2단계 방법 제안
- 중앙값 기반 robust 추정으로 이상치(API 오류, 계절성) 영향 최소화
- 복원된 pseudo_volume의 오차 범위 및 신뢰도 분석

## 제목

> *Pseudo-Volume: A Two-Stage Scale Correction Method for Reconstructing Continuous Time-Series from Relative Search Indices*

## 초록

네이버 쇼핑인사이트를 비롯한 검색 트렌드 API는 절대 검색량이 아닌 요청 범위 내
상대값(ratio)을 반환한다. 이로 인해 호출 배치가 달라지거나 수집 시점이 분리되면
시계열이 단절되는 문제가 발생한다. 본 연구는 Anchor 카테고리를 모든 배치에 포함시키고
겹치는 수집 구간에서 중앙값 비율로 두 단계 Scale 계수(intra_scale, inter_scale)를
추정하는 Pseudo-Volume 방법을 제안한다. 제안 방법을 네이버 쇼핑인사이트 5개 카테고리,
약 1년 치 데이터에 적용하고 기존 단순 연결 방식 대비 연속성과 예측 정확도를 비교 평가한다.

## 연구 내용

1. 상대 지수 비연속 문제의 수학적 정의
   - `raw_ratio(c, t, B)` = 배치 B에서 카테고리 c의 시점 t 값 (max=100)
   - 배치 간 불일치: `E[raw(c,t,B1) / raw(c,t,B2)] ≠ 1` 일반적으로
2. Anchor 기반 intra_scale 추정
   - anchor 카테고리 a를 모든 배치에 포함
   - `intra_scale(B) = median_t { raw(a,t,B_ref) / raw(a,t,B) }`
3. Overlap 구간 기반 inter_scale 추정
   - 수집 구간이 겹치는 기간의 anchor raw값 비교
   - `inter_scale = median_t { raw_db(a,t) / raw_new(a,t) }`
4. pseudo_volume 산출
   - `pseudo_volume(c,t) = raw(c,t) × intra_scale × inter_scale`
5. 오차 분석: Bootstrap으로 scale 계수의 신뢰 구간 추정

## 연구 방법

- 네이버 쇼핑인사이트 API로 의도적으로 다양한 배치 구성을 만들어 수집
- 동일 기간을 서로 다른 배치로 2회 수집 → 복원값 비교 (Ground Truth 근사)
- 비교 대상: 단순 연결(naive), 선형 보간(linear interpolation), 제안 방법

## 실험 및 평가 방법

- **연속성 지표**: 구간 연결점에서 단절값(jump) 크기 — 작을수록 우수
- **예측 정확도**: 복원 시계열로 다음 주 값을 ARIMA 예측 → RMSE 비교
- **Robustness**: anchor 카테고리 변경 시 결과 안정성 (sensitivity analysis)

## 예상 결과

- 제안 방법이 naive 대비 연결점 단절값 50% 이상 감소
- ARIMA 예측 RMSE 10~20% 개선
- inter_scale의 중앙값 기반 추정이 평균 기반 대비 이상치에 강건함을 확인

## 구현 난이도: ★★☆☆☆ (하~중)

- 데이터 즉시 가용, 수식 구현 Python 200줄 이내
- 추가 API 호출 비용 소요 (의도적 중복 수집 필요)

## 향후 확장성

- Google Trends에 동일 방법 적용 (API 구조 유사)
- 다중 anchor (앙상블) 사용으로 단일 anchor 의존도 감소
- 실시간 streaming 수집 환경에서의 online scale 추정

# P02. DCAT 2.0 기반 이종 웹 데이터 통합 메타데이터 플랫폼 설계 및 구현

## 연구 필요성 (Research Gap)

데이터 카탈로그 표준인 DCAT(Data Catalog Vocabulary)은 공공 데이터 포털에 주로
적용되며, **YouTube·뉴스·쇼핑 트렌드처럼 구조·갱신 주기·수집 방식이 전혀 다른
이종 웹 API 데이터에 DCAT 2.0을 체계적으로 적용한 사례**는 거의 없다. 기존
웹 데이터 수집 연구는 수집 방법론에 집중하고 메타데이터 관리 구조를 경시한다.

특히 **시계열 통계 변화 추적(active_meta 패턴)**과 **벡터 임베딩 기반 의미 검색**을
단일 플랫폼에서 통합 제공하는 아키텍처 제안은 학술적으로 다루어진 바 없다.

## 기여점 (Contribution)

- DCAT 2.0을 한국어 웹 API 데이터 도메인에 확장 적용하는 매핑 규칙 제안
- 정적 메타데이터(meta_*)와 시계열 통계(active_meta_*) 분리 패턴 정형화
- source_type 경계 설계 원칙 (1 dataset = 1 source_type)과 dataset_origin 이분법
- 실제 운영 사례 기반 성능 및 확장성 평가

## 제목

> *A DCAT 2.0-Based Metadata Platform for Heterogeneous Korean Web Data Sources: Design, Implementation, and Evaluation*

## 초록

YouTube, Naver 뉴스, 쇼핑 트렌드처럼 구조가 상이한 웹 데이터를 단일 메타데이터
체계로 관리하는 것은 도전적인 과제다. 본 연구는 W3C DCAT 2.0 표준을 기반으로
이종 웹 API 데이터 통합 관리 플랫폼의 설계와 구현을 제시한다. 핵심 기여는
정적 메타데이터와 시계열 통계를 분리하는 active_meta 패턴, 소스 타입 경계 설계
원칙, 다중 레벨 벡터 검색 아키텍처이다. 실제 4종 데이터 소스, 총 60,000여 건
데이터로 구현·운영하며 확장성과 쿼리 성능을 평가한다.

## 연구 내용

1. DCAT 2.0 핵심 클래스(Dataset, Distribution, DataService)의 웹 API 데이터 매핑
2. active_meta 패턴: 정적 속성 변경 없이 시계열 통계를 축적하는 방법
3. source_type 설계 원칙과 다중 소스 혼합 방지 규칙
4. 2레벨 벡터 검색: 데이터셋 레벨(dcat_dataset_vec) + 아이템 레벨(meta_*_vec)
5. 수집 이력 및 품질 추적 (dcat_provenance 기반 Data Provenance)

## 연구 방법

- 기존 데이터 카탈로그 시스템(CKAN, DataHub, Amundsen)과 설계 비교 분석
- PostgreSQL 17 + pgvector 기반 실구현
- 4종 소스(YouTube API, Naver 뉴스/쇼핑인사이트/Persona) 통합 운영

## 실험 및 평가 방법

- **쿼리 성능**: 벡터 검색 응답 시간 (데이터 규모별)
- **메타데이터 완결성**: 각 소스별 필수 DCAT 속성 커버리지 측정
- **시스템 유용성**: 개발자 대상 설문 또는 task-based 평가
- **비교 기준**: 플랫폼 없이 원시 테이블 직접 사용 시 vs. 플랫폼 사용 시 탐색 시간

## 예상 결과

- DCAT 핵심 속성 90% 이상 커버, 웹 특화 속성 15개 이상 확장 정의
- 벡터 검색 p95 응답 시간 100ms 이하 (10만 건 기준)
- 플랫폼 사용 시 데이터 탐색 시간 40% 이상 단축

## 구현 난이도: ★☆☆☆☆ (하)

- 이미 구현된 플랫폼을 논문 형식으로 정리·평가하는 작업
- 비교 대상 시스템 설치·설정 필요 (CKAN 등)

## 향후 확장성

- DCAT-AP(유럽 공공 데이터 포털 프로파일) 호환성 확장
- 공공 데이터 포털(data.go.kr)과의 연동 가능성
- 멀티테넌시(기관별 독립 카탈로그) 지원

# P03. LLM 기반 한국어 YouTube 콘텐츠 메타데이터 자동 생성 파이프라인

## 연구 필요성 (Research Gap)

YouTube API가 제공하는 메타데이터(제목·설명·태그)는 업로더가 수동으로 입력한
값으로, **콘텐츠 실제 내용과 불일치하거나 키워드 스터핑(keyword stuffing)으로 오염된
경우**가 많다. 자동 자막(STT) 기반 트랜스크립트가 제공되지만 한국어 STT는 전문
용어 오인식 노이즈가 심하다.

**노이즈가 심한 한국어 STT 텍스트에서 LLM으로 고품질 메타데이터를 추출하는
파이프라인 연구**는 한국어 특화로 수행된 사례가 드물며, 무료 공개 LLM의 실용성
검증 연구도 부족하다.

## 기여점 (Contribution)

- STT 노이즈 전처리(타임스탬프 제거, 반복 구문 병합) 파이프라인 제안
- 요약·키워드·개체명·콘텐츠 유형 4종 메타데이터 동시 추출 프롬프트 설계
- 무료 공개 LLM(llama-3.1-8b, gemma2-9b via Groq)의 한국어 메타데이터 생성 품질 평가
- API 메타데이터 단독 사용 vs. 트랜스크립트 추가 시 검색 정확도 향상 정량화

## 제목

> *Automated Korean Metadata Enrichment for YouTube Videos via LLM-Based Transcript Analysis*

## 초록

YouTube 영상의 API 제공 메타데이터는 콘텐츠 실제 내용을 충분히 반영하지 못한다.
본 연구는 STT 기반 한국어 트랜스크립트에서 요약·키워드·개체명·콘텐츠 유형을
공개 LLM으로 자동 추출하는 파이프라인을 제안한다. STT 노이즈 전처리, Long Context
처리 전략, 구조화 출력(JSON) 프롬프트를 설계하고, 추출 메타데이터의 품질을 인간
평가와 검색 정확도(IR 지표)로 평가한다. Groq 무료 API 환경에서 일일 처리 가능
규모와 비용 효율성도 분석한다.

## 연구 내용

1. 한국어 STT 노이즈 분석: 전문 용어 오인식 패턴 유형화
2. 전처리 파이프라인: 타임스탬프 제거, 불완전 문장 병합, 반복 구문 탐지
3. 4종 메타데이터 추출 프롬프트 설계
   - 요약(3문장 이내), 핵심 키워드(5~10개), 개체명(기관·인물·제품·기술),
     콘텐츠 유형(tutorial/review/presentation/interview/news)
4. Long Context 처리: 트랜스크립트 길이별 청킹 전략 (16K 토큰 초과 시)
5. Groq API rate limit(30req/min, 14,400req/day) 내 처리 최적화

## 연구 방법

- 데이터: 한국어 YouTube 영상 200편 이상, 트랜스크립트 수집 (youtube-transcript-api)
- 도메인: 기술(반도체·AI), 의료, 뉴스 3개 도메인 교차 평가
- LLM 비교: llama-3.1-8b vs. gemma2-9b vs. GPT-4o-mini (품질 상한 추정)

## 실험 및 평가 방법

- **자동 평가**: ROUGE-L (요약), F1@K (키워드), NER F1 (개체명)
- **인간 평가**: 관련성·정확성·완결성 5점 척도, 평가자 2인 Cohen's Kappa
- **IR 평가**: 추가 메타데이터 포함 시 벡터 검색 MRR@10, NDCG@10 변화
- **효율성**: 영상 1편당 평균 처리 시간, API 호출 수, 월간 처리 가능 규모

## 예상 결과

- 트랜스크립트 추가 시 벡터 검색 NDCG@10 10~25% 향상
- llama-3.1-8b 인간 평가 평균 3.5/5.0 이상 (실용 수준)
- GPT-4o-mini 대비 70~80% 수준의 품질을 0원으로 달성

## 구현 난이도: ★★★☆☆ (중)

- 트랜스크립트 수집 및 LLM 호출 코드 구현 필요
- 인간 평가 설계 및 평가자 모집 필요

# P04. 쇼핑 Persona Index 독립 가정의 카테고리별 위반 정도 정량화

## 연구 필요성 (Research Gap)

`persona_index = gender_pv × age_pv` 는 성별과 연령 검색 행동이 독립적이라는
강한 가정에 기반한다. 그러나 실제로는 특정 카테고리(예: 임산부 용품, 군복)에서
성별-연령 교호작용이 강하게 나타날 것이다. **이 독립 가정이 카테고리별로 얼마나
성립하는지 측정하는 연구**는 공식 문서나 관련 논문 어디에도 없다.

정확한 joint distribution 데이터가 없는 상황에서 독립 가정 위반 정도를 추정하는
간접 방법론이 필요하다.

## 기여점 (Contribution)

- 독립 가정 위반 정도를 정량화하는 대리 지표(proxy metric) 제안
- 카테고리별 위반 정도 분포 분석 및 고위반 카테고리 유형 분류
- 위반 정도에 따른 persona_index 신뢰 구간 추정 방법
- 독립 가정이 안전한 카테고리와 사용 주의가 필요한 카테고리 가이드라인 제공

## 제목

> *Quantifying Independence Assumption Violations in Shopping Persona Indices: A Category-Level Empirical Analysis*

## 초록

네이버 쇼핑인사이트 Persona Index는 성별과 연령 검색 패턴이 통계적으로 독립이라는
가정 하에 `gender_pv × age_pv`로 산출한다. 본 연구는 이 독립 가정의 위반 정도를
카테고리별로 정량화하는 대리 지표를 제안하고, 패션·스포츠·유아·전자제품 등 다양한
카테고리에 적용하여 가정 위반이 심한 카테고리 유형을 분류한다. 또한 위반 정도에
따른 persona_index 오차 상한을 추정해 실무 활용 시 주의 기준을 제시한다.

## 연구 내용

1. 독립 가정 위반 대리 지표 설계
   - 동일 카테고리 내 성별·연령 시계열의 상관 계수 변화율
   - 계절성 분해 후 잔차의 성별-연령 공분산
2. 카테고리별 위반 지표 계산 (30개 이상 카테고리)
3. 위반 정도에 따른 카테고리 군집화 (고/중/저 위반 그룹)
4. 오차 상한 추정: 독립 가정 시 최대 과대/과소 추정 배율

## 연구 방법

- 데이터: 네이버 쇼핑인사이트 Persona API, 30개 이상 카테고리, 1년 이상 시계열
- 통계: Pearson 상관, 편상관 분석, Granger 인과 검정
- 군집화: k-means 또는 계층적 군집 분석 (위반 지표 기반)

## 실험 및 평가 방법

- **내적 검증**: 서로 다른 overlap 구간에서 계산한 위반 지표의 안정성
- **외적 검증**: 공개된 실제 구매 데이터(e커머스 공개 데이터셋)와 correlation
- **카테고리 해석**: 고위반 카테고리의 공통 특성 정성 분석

## 예상 결과

- 카테고리의 30~40%에서 독립 가정이 통계적으로 유의하게 위반됨
- 성별 편향이 강한 카테고리(임산부·군복·화장품)에서 위반 정도 최대
- 위반 정도와 카테고리 내 성별 검색 비율 불균형 간 양의 상관 확인

## 구현 난이도: ★★☆☆☆ (하~중)

- 데이터 즉시 가용, 통계 분석 중심으로 구현 복잡도 낮음
- 30개 이상 카테고리 추가 수집 필요 (API 호출 비용 소요)
- 외적 검증용 실제 구매 데이터 확보가 관건

## 향후 확장성

- 시간 지연(time-lag)을 고려한 동적 독립성 검정

# P05. 뉴스 기사 댓글 시계열 분석을 통한 사회적 임팩트 측정 지표 개발

## 연구 필요성 (Research Gap)

뉴스 기사의 "영향력"을 측정하는 기존 연구는 주로 기사 공유 수, 인용 수에 의존한다.
그러나 한국 뉴스 플랫폼에서는 **댓글 반응이 기사 파급력을 보여주는 핵심 지표**임에도
댓글 수 시계열 변화 패턴을 분석한 연구는 드물다.

특히 **기사 게재 직후 댓글 급증 패턴(velocity), 증가 지속 기간(duration), 장기 누적
규모(volume)**를 결합한 복합 임팩트 지표 개발 연구가 부재하다.

## 기여점 (Contribution)

- 뉴스 기사 댓글 시계열에서 velocity·duration·volume 3차원 임팩트 지표 제안
- 기사 발행 후 시간 경과에 따른 댓글 누적 곡선 모델링 (로그 증가 모형 제안)
- 임팩트 패턴에 따른 기사 유형 분류 (단발성 화제 vs. 지속적 관심)
- 댓글 수 임팩트와 뉴스 주제(AI·경제·사회) 간 연관성 분석

## 제목

> *Measuring Social Impact of News Articles via Comment Count Time-Series: Velocity, Duration, and Volume Metrics*

## 초록

뉴스 기사의 사회적 영향력을 댓글 수 시계열로 측정하는 방법을 제안한다. 기사 게재 후
댓글 급증 속도(velocity), 증가 지속 기간(duration), 장기 누적량(volume)의 3차원
복합 지표를 정의하고 네이버 뉴스 AI 관련 기사 1,000건 이상의 6개월 시계열에 적용한다.
기사 임팩트 패턴을 군집화하여 '단발 화제형', '지속 관심형', '장기 확산형' 등 유형을
분류하고, 각 유형과 기사 주제·발행 시간대 간의 연관성을 분석한다.

## 연구 내용

1. 댓글 누적 증가 곡선 모델: `C(t) = C_max × (1 - e^(-λt))` 파라미터 추정
2. 3차원 임팩트 지표 정의
   - Velocity: 발행 후 24시간 내 댓글 증가 속도
   - Duration: 댓글 증가율이 임계값 이상 유지되는 기간
   - Volume: 수집 종료 시점 총 댓글 수 (expose_count 기준)
3. 군집 분석으로 임팩트 패턴 유형화
4. 임팩트 유형 × 기사 주제·발행 시간·언론사 교차 분석

## 연구 방법

- 데이터: 네이버 뉴스 Naver-hosted 기사 1,000건 이상, 6개월 주기적 수집
- 수집 주기: 발행 직후 1시간, 6시간, 24시간, 72시간, 1주, 1개월 시점
- 분석: 비선형 회귀(NLS), k-means 군집, Chi-square 독립성 검정

## 실험 및 평가 방법

- **모델 적합도**: 로그 증가 모형 R², RMSE (실제 누적 곡선 vs. 적합값)
- **군집 안정성**: Silhouette Score, 다른 k값 민감도
- **예측력**: 발행 24시간 후 데이터로 최종 댓글 수 예측 → MAPE

## 예상 결과

- 기사 80% 이상이 발행 후 48시간 내 총 댓글의 90% 이상 수렴
- AI·경제 기사가 사회·문화 기사 대비 velocity 2배 이상
- 발행 시간대(오전 9~11시)와 velocity 간 유의한 연관성 확인

## 구현 난이도: ★★★☆☆ (중)

- 기사별 시점별 수집을 위한 스케줄링 파이프라인 구축 필요
- 1,000건 기사 × 6개 시점 = 6,000회 API 호출
- Naver comment API 안정성 의존 (비공식 API 리스크)

## 향후 확장성

# P06. YouTube 조회수와 네이버 쇼핑 검색량 간 그랜저 인과 분석

소셜 미디어 콘텐츠와 소비자 구매 행동 간 관계는 마케팅 분야의 핵심 연구 주제다.

특히 "영상이 트렌드를 주도하는가(creator-led)"와 "트렌드가 영상 소비를 이끄는가

## 기여점 (Contribution)

- YouTube 조회수 delta와 네이버 쇼핑 pseudo_volume의 이종 시계열 정렬 방법 제안
- 카테고리별 Granger 인과 방향(단방향/양방향/무관) 분류
- 최적 lead/lag 기간 추정 및 카테고리별 차이 분석
- 마케팅 인텔리전스 활용 방안 제시

## 제목

> *Creator-Led or Trend-Following? Granger Causality Analysis Between YouTube View Counts and Naver Shopping Search Volume*

## 초록

YouTube 콘텐츠 소비와 쇼핑 검색 트렌드 간 인과 관계를 그랜저 인과 검정으로 분석한다.
YouTube 주간 조회수 delta와 네이버 쇼핑인사이트 pseudo_volume을 동기화하고, 패션·
전자제품·스포츠 등 5개 이상 카테고리에 VAR 모델 기반 그랜저 검정을 적용한다. 분석
결과로 YouTube 조회수가 검색 트렌드의 선행 지표인 카테고리 유형과 그 반대 방향이
나타나는 카테고리를 구분하고, 마케팅 전략적 시사점을 도출한다.

## 연구 내용

1. 이종 시계열 정렬: YouTube 주간 단위 delta와 쇼핑 일간 pseudo_volume 주간 집계

4. Granger 인과 검정: YouTube→쇼핑, 쇼핑→YouTube 양방향 검정
5. Impulse Response Function으로 충격 후 반응 기간 추정

## 실험 및 평가 방법

## 예상 결과

## 구현 난이도: ★★★☆☆ (중)

# P07. RAG 기반 한국어 도메인 Q&A: 뉴스 기사 지식베이스와 LLM 결합

## 연구 필요성 (Research Gap)

Retrieval-Augmented Generation(RAG)은 LLM의 환각(hallucination)을 줄이고 최신 정보를
반영하는 방법으로 주목받는다. 그러나 **한국어 도메인 특화 뉴스 기사를 지식베이스로
사용하는 RAG 시스템**에 대한 실증 연구는 부족하며, 특히 AI·반도체 같은 전문 기술
도메인에서의 성능 평가 연구가 없다.

한국어 특성(교착어, 신조어, 전문 용어)이 청킹 전략과 검색 성능에 미치는 영향도
아직 충분히 연구되지 않았다.

## 기여점 (Contribution)

- 한국어 뉴스 기사 특화 RAG 파이프라인 설계 (청킹·임베딩·재순위화)
- 한국어 전문 도메인에서 Dense vs. Sparse vs. Hybrid 검색 성능 비교
- 뉴스 기사 청킹 전략 비교: 문단 단위 vs. 문장 단위 vs. 의미 단위
- RAG 답변의 출처 추적(provenance) 및 사실성 평가 방법 제안

## 제목

> *Korean Domain-Specific RAG: Evaluating Retrieval Strategies for News Article Knowledge Bases in Technical Domains*

## 초록

한국어 AI·반도체 뉴스 기사 1,000건 이상을 지식베이스로 구축하고, 다양한 검색 전략을
결합한 RAG 시스템을 평가한다. Dense retrieval(pgvector 기반 의미 검색), BM25 Sparse
검색, 두 방법의 하이브리드 조합을 비교하고, LLM(llama-3.1-8b)을 생성기로 사용해
Q&A 품질을 측정한다. 한국어 청킹 전략 4종을 비교하고 도메인 전문 용어 처리 방법을
제안한다.

## 연구 내용

1. 한국어 뉴스 지식베이스 구축: 1,000건 기사 전처리·청킹·임베딩
2. 청킹 전략 비교 4종
   - 고정 크기(512 토큰), 문단 경계, 문장 경계, 의미 단위(LLM 분할)
3. 검색 전략 비교
   - Dense(pgvector cosine), Sparse(BM25), Hybrid(RRF 결합)
4. 재순위화(Reranking): Cross-encoder 모델 적용 효과
5. 생성 품질 평가: RAGAS 프레임워크 적용

## 연구 방법

- 평가 데이터셋: 도메인 전문가가 작성한 질문 100쌍 이상 (질문-정답-근거 기사)
- 평가 지표: Faithfulness, Answer Relevancy, Context Precision, Context Recall
- 비교 LLM: llama-3.1-8b (무료) vs. GPT-4o-mini (유료, 상한 기준)

## 실험 및 평가 방법

- **검색 평가**: MRR@5, NDCG@5, Recall@10
- **생성 평가**: RAGAS 4개 지표, 인간 평가 Likert 5점
- **Ablation**: 청킹 전략, 검색 방법, 재순위화 각각 제거 시 성능 변화

## 예상 결과

- Hybrid 검색이 Dense/Sparse 단독 대비 MRR@5 10~15% 우수
- 의미 단위 청킹이 고정 크기 대비 Context Precision 8~12% 향상
- Faithfulness 지표에서 llama-3.1-8b는 GPT-4o-mini 대비 약 85% 수준

## 구현 난이도: ★★★★☆ (상)

- 평가 데이터셋 수동 구축이 가장 큰 병목 (전문가 참여 필요)
- RAGAS 평가 자동화 파이프라인 구현 필요
- BM25 + pgvector 하이브리드 검색 구현 필요

## 향후 확장성

- 멀티홉 Q&A (여러 기사 조합해야 답변 가능한 질문)
- 시간 인식 RAG: 질문의 시점과 기사 발행일 매칭
- 사용자 피드백 기반 검색 모델 fine-tuning

# P08. 계층적 벡터 검색을 이용한 이종 미디어 데이터셋 의미 탐색

## 연구 필요성 (Research Gap)

벡터 검색 연구 대부분은 **단일 컬렉션 내 유사 아이템 탐색**에 집중한다. 반면
"어떤 데이터셋에 무엇이 들어 있는가"를 파악하는 **데이터셋 레벨 탐색(dataset discovery)**
연구는 주로 데이터 카탈로그 키워드 검색에 그친다.

데이터셋 레벨과 아이템 레벨을 **계층적으로 결합한 2단계 벡터 검색**으로 이종 미디어
(영상, 기사)에 걸쳐 통합 탐색하는 아키텍처 연구는 공개 사례가 없다.

## 기여점 (Contribution)

- 데이터셋 레벨(coarse) + 아이템 레벨(fine) 2단계 계층적 벡터 검색 아키텍처 제안
- 데이터셋 description 임베딩이 아이템 검색의 사전 필터로 작동하는 효과 정량화
- 이종 미디어(YouTube 영상 vs. 뉴스 기사) 간 cross-modal 의미 탐색 가능성 검토
- 계층 검색 결과의 설명 가능성 (왜 이 데이터셋, 왜 이 아이템) 제공 방법

## 제목

> *Hierarchical Vector Search for Heterogeneous Media Dataset Discovery: Dataset-Level Coarse Filtering with Item-Level Fine Retrieval*

## 초록

YouTube 영상과 뉴스 기사가 혼재하는 이종 미디어 환경에서 자연어 질의로 관련 콘텐츠를
탐색하는 계층적 벡터 검색 시스템을 제안한다. 1단계에서 데이터셋 description 임베딩으로
관련 데이터셋을 좁히고, 2단계에서 해당 데이터셋 내 아이템 임베딩으로 세부 결과를
반환한다. 단일 컬렉션 전체 검색 대비 응답 시간과 정확도를 평가하고, 데이터셋 간
cross-modal 탐색 시나리오를 실험한다.

## 연구 내용

1. 2단계 검색 아키텍처 설계
   - L1: dcat_dataset_vec HNSW 검색 → top-K 데이터셋 선택
   - L2: 선택된 데이터셋의 meta_*_vec에서 HNSW 검색
2. 임베딩 텍스트 설계: 데이터셋 레벨 vs. 아이템 레벨 최적 텍스트 구성 비교
3. Cross-modal 탐색: 영상 쿼리로 관련 기사 탐색 또는 그 반대
4. 결과 설명: 어떤 데이터셋에서 왜 이 아이템이 선택됐는지 근거 제시 방법

## 연구 방법

- 평가 쿼리: 30개 이상 자연어 질의 (전문가 작성)
- 비교 기준: Flat 전체 검색 vs. 계층 검색 vs. 소스 타입 필터 후 검색
- 인덱스: HNSW (ef_construction=200, m=16) vs. IVFFlat 비교

## 실험 및 평가 방법

- **정확도**: Precision@5, Recall@10, MRR
- **효율성**: 응답 시간(ms), 인덱스 메모리 사용량
- **Cross-modal**: 동일 주제 영상-기사 쌍 정답 셋 구축 후 cross-modal recall

## 예상 결과

- 계층 검색이 Flat 검색 대비 응답 시간 40~60% 감소 (아이템 규모 10만 건 이상 시)
- Precision@5는 Flat 대비 동등 또는 5% 이내 차이
- Cross-modal 탐색에서 동일 주제 영상-기사 쌍 Top-5 recall 60% 이상

## 구현 난이도: ★★★☆☆ (중)

- pgvector HNSW 인덱스 설정으로 구현 가능
- 평가용 정답 셋(qrel) 구축에 시간 필요
- Cross-modal 쌍 레이블링 작업 필요

## 향후 확장성

- 3레벨 계층 (소스 타입 → 데이터셋 → 아이템) 확장
- 사용자 피드백 기반 데이터셋 레벨 임베딩 fine-tuning
- 연합 검색(Federated Search): 여러 독립 카탈로그 인스턴스 통합 탐색
