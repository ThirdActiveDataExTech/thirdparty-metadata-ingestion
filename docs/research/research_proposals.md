# P01. 상대 검색량 지수의 장기 연속 시계열 복원

## 연구 필요성 (Research Gap)

네이버 쇼핑인사이트·Google Trends 등 검색 트렌드 API는 절대 검색량 대신
**요청 범위 내 최댓값=100으로 정규화된 상대값**을 반환한다. 이 구조는 두 가지
문제를 일으킨다.

1. **배치 간 불연속**: API가 한 번에 최대 3개 카테고리 비교를 허용하므로 여러
   배치로 나눠 호출하면 배치마다 정규화 기준 M이 달라진다. 같은 카테고리라도
   배치 구성에 따라 raw_ratio가 달라지는 것이다.
2. **수집 구간 간 불연속**: 다른 날 같은 기간을 재수집하면 검색량 분포 자체가
   달라져 M이 바뀐다. 두 시점의 raw_ratio를 그냥 연결하면 단절이 생긴다.

기존 문헌 대부분은 단일 API 호출 범위 내 비교에 그친다. **anchor 카테고리와
두 단계 Scale 보정(intra_scale × inter_scale)으로 장기 연속 시계열을 복원하는
체계적 방법론**은 발표된 논문이 없다.

## 기여점 (Contribution)

- 상대 지수 비연속 문제의 수학적 정형화
- intra_scale / inter_scale 2단계 보정 방법 제안
- 중앙값 기반 Robust 추정으로 이상치 내성 확보
- pseudo_volume 신뢰도 분석 및 한계 명시

## 제목

> *Pseudo-Volume: A Two-Stage Scale Correction Method for Reconstructing Continuous Time-Series from Relative Search Indices*

## 초록

네이버 쇼핑인사이트 등 검색 트렌드 API는 절대 검색량 대신 요청 범위 내 상대값을
반환한다. 이로 인해 호출 배치가 달라지거나 수집 시점이 분리되면 시계열이 단절된다.
본 연구는 anchor 카테고리를 매 배치에 포함시켜 배치 간 정규화 기준 차이를 보정하고
(intra_scale), 수집 구간이 겹치는 기간의 anchor 값 비율로 수집 구간 간 차이를
보정하는(inter_scale) 두 단계 Pseudo-Volume 방법을 제안한다. 네이버 쇼핑인사이트
5개 카테고리 1년 치 데이터로 검증하고, 기존 단순 연결 방식 대비 연속성과 예측 정확도를
비교한다.

## 연구 내용

### 1단계: 문제 정형화

```
R(c, t, B) = 배치 B에서 카테고리 c, 시점 t의 raw_ratio
M(B) = 해당 배치의 검색량 최대값 (API가 숨기는 값)
R(c, t, B) = actual_volume(c, t) / M(B) × 100
```

배치 B1과 B2가 같은 기간을 다루더라도 M(B1) ≠ M(B2)이면 R의 직접 비교는 불가하다.

### 2단계: intra_scale (배치 간 보정)

anchor 카테고리 a를 모든 배치에 포함시킨다.
기준 배치(첫 번째 유효 배치)의 anchor 값과 각 배치의 anchor 값 비율 중앙값으로 보정한다.

```
intra_scale(B) = median_t { R(a, t, B_ref) / R(a, t, B) }
```

### 3단계: inter_scale (수집 구간 간 보정)

이전 수집과 신규 수집이 겹치는 기간을 이용해 anchor 값 비율 중앙값으로 보정한다.

```
inter_scale = median_t { R_db(a, t) / R_new(a, t) }   (겹치는 t에 대해)
```

### 4단계: pseudo_volume 산출

```
pseudo_volume(c, t) = R(c, t) × intra_scale(B) × inter_scale
```

## 연구 방법

### 핵심 연구 질문

> "두 단계 Scale 보정으로 복원한 pseudo_volume은, 배치 구성과 수집 시점이 달라도
> 동일한 (카테고리, 날짜)에 대해 일관된 값을 산출하는가?"

### 실험 1: 배치 구성 변경 실험 (intra_scale 검증)

동일한 카테고리 집합을 **의도적으로 다른 배치 구성**으로 수집한다.

```
실험 A 배치 구성: anchor + [패션의류, 스포츠] → [패션잡화]
실험 B 배치 구성: anchor + [스포츠] → [패션의류, 패션잡화]
```

같은 날짜의 pseudo_volume이 배치 구성과 무관하게 일치해야 한다.

### 실험 2: 수집 구간 겹침 실험 (inter_scale 검증)

같은 기간(예: 2025-01 ~ 2025-03)을 **두 번 다른 날에 수집**하고
두 번의 pseudo_volume을 비교한다. 차이가 클수록 inter_scale 보정의 필요성이 크다.

### 실험 3: 예측 정확도 실험

1년 치 pseudo_volume vs. raw_ratio vs. normalized_ratio로 각각 ARIMA 모델을 학습하고
마지막 4주를 예측해 비교한다.

```
학습 기간: 2025-01 ~ 2026-03 (15개월)
예측 기간: 2026-04 ~ 2026-06 (3개월)
```

## 평가 방법

### 비교 대상 (Baselines)

| 방법 | 설명 |
|------|------|
| Naive 연결 | raw_ratio를 그냥 이어붙임 (보정 없음) |
| 선형 스케일링 | 각 수집 구간의 평균값으로 나눠 정규화 |
| 단일 anchor | intra_scale 없이 inter_scale만 적용 |
| 제안 방법 | intra_scale × inter_scale 2단계 |

### 측정 지표와 측정 대상의 연결

| 지표 | 측정 대상 | 연결 이유 |
|------|----------|----------|
| 배치 일관성 (CV) | 같은 (카테고리, 날짜)의 다른 배치 pseudo_volume 변동계수 | 배치 구성이 달라도 값이 같아야 한다는 핵심 요건을 직접 측정 |
| 구간 연결점 jump 크기 | 수집 구간 경계에서의 값 단절 절댓값 | 시계열이 얼마나 매끄럽게 이어지는지 측정 |
| ARIMA RMSE | 복원 시계열로 예측한 미래값의 오차 | 연속 시계열의 실용적 가치(예측에 써먹을 수 있는지) 측정 |
| Bootstrap 신뢰구간 폭 | scale 계수 추정 불확실성 | 방법의 안정성과 한계를 동시에 표현 |

### 주요 개념 설명

**CV (Coefficient of Variation, 변동계수)**
표준편차를 평균으로 나눈 값. 단위가 없어 서로 다른 스케일의 데이터에서도 변동성을 비교할 수 있다.
CV = 0.1이면 평균의 10% 수준으로 값이 흔들린다는 뜻. 값이 낮을수록 일관성이 높다.
배치 일관성 측정에 CV를 쓰는 이유: 같은 날짜·카테고리를 다른 배치에서 수집해도 pseudo_volume이 비슷해야 하므로, 배치 간 분산을 평균으로 정규화한 CV가 가장 적합한 지표다.

**ARIMA (Auto-Regressive Integrated Moving Average)**
시계열 예측의 표준 모델. 과거 자신의 값(AR)과 과거 예측 오차(MA), 그리고 차분(I)을 조합해 미래를 예측한다.
이 연구에서는 복원된 시계열이 실제로 "예측에 쓸 수 있는 연속 데이터"인지를 검증하는 도구로 사용한다.

**RMSE (Root Mean Squared Error)**
예측값과 실제값의 차이를 제곱해 평균낸 뒤 제곱근을 취한 값. 값이 작을수록 예측이 정확.
큰 오차에 더 민감하게 반응한다 (제곱 때문에 큰 오차가 강조됨).

**Bootstrap 신뢰구간**
정규 분포를 가정하기 어려울 때, 데이터를 수백~수천 번 재샘플링해 scale 계수의 분포를 직접 추정하는 방법.
"inter_scale = 1.05, 95% 신뢰구간 [0.98, 1.12]"처럼 추정의 불확실성을 범위로 표현. 신뢰구간이 넓을수록 scale 추정이 불안정하다는 뜻.

**paired t-test**
동일한 샘플(같은 카테고리·날짜)에 두 방법을 각각 적용한 결과를 비교하는 검정.
개체 간 자연적 차이를 제거하고 방법 간 차이만 검정하므로, 단순 두 집단 비교(independent t-test)보다 검정력이 높다.
p < 0.05이면 두 방법의 성능 차이가 우연이 아닌 것으로 판단.

### 해석 기준 (성공 조건)

- 배치 일관성 CV: 제안 방법 < Naive의 50% → 배치 간 일관성 확보 입증
- 연결점 jump 크기: 제안 방법 < Naive의 50%
- ARIMA RMSE: 제안 방법이 Naive 대비 통계적으로 유의하게 낮음 (paired t-test p < 0.05)

# P02. DCAT 2.0 기반 이종 웹 데이터 통합 메타데이터 플랫폼

## 연구 필요성 (Research Gap)

DCAT(Data Catalog Vocabulary)은 공공 데이터 포털 중심으로 적용되며, YouTube·뉴스·쇼핑
트렌드처럼 **구조·갱신 주기·수집 방식이 전혀 다른 이종 웹 API 데이터에 DCAT 2.0을
체계적으로 적용한 사례**는 거의 없다. 기존 CKAN, DataHub 같은 오픈소스 카탈로그는
정적 파일 기반 데이터에 최적화되어 있어 실시간 수집·갱신되는 웹 데이터에 그대로
적용하기 어렵다.

### 측정 지표와 연결 이유

| 지표 | 측정 대상 | 연결 이유 |
|------|----------|----------|
| 탐색 과제 완료 시간 (초) | 사용자가 과제를 푸는 데 걸린 시간 | 플랫폼의 실용적 효율성을 직접 측정 |
| DCAT 속성 커버리지 (%) | 필수+권고 속성 중 실제 채워진 비율 | 메타데이터 품질의 객관적 척도 |
| 벡터 검색 응답 시간 (ms) | 쿼리당 p50/p95 응답 시간 | 운영 실용성 평가 |
| 검색 Precision@5 | 쿼리 결과 상위 5개 중 관련 결과 비율 | 검색 품질 척도 |

### 주요 개념 설명

**Precision@5 (상위 5 정밀도)**
검색 결과 상위 5개 중 실제로 관련 있는 결과의 비율.
Precision@5 = 0.6이면 5개 중 3개가 관련 결과라는 뜻.
(Recall과의 차이: Recall은 "전체 관련 결과 중 몇 개를 찾았는가"이고, Precision은 "찾아낸 것 중 얼마나 맞았는가"다. 이 연구에서는 5개 결과를 제시할 때 정확한 것이 몇 개인지가 중요하므로 Precision@5를 사용)

**p50 / p95 응답 시간 (백분위수 응답 시간)**
응답 시간의 분포를 백분위로 표현한다.
- p50 = 중앙값: 전체 요청의 50%가 이 시간 이내에 응답됨
- p95: 전체 요청의 95%가 이 시간 이내에 응답됨 (나머지 5%는 더 느림)
평균 대신 p95를 쓰는 이유: 평균은 간헐적인 느린 요청을 희석시키지만, p95는 "실제 사용자 중 5%가 겪는 최악의 경험"을 드러낸다. API 운영 SLA 기준으로 널리 사용된다.

**DCAT 속성 커버리지**
W3C DCAT 2.0 표준에서 정의하는 필수(mandatory)·권고(recommended) 속성 목록 중 실제로 값이 채워진 비율.
커버리지가 높을수록 다른 시스템과의 상호운용성(interoperability)이 높고 데이터셋 발견 가능성(discoverability)이 좋아진다.

### 해석 기준

- 탐색 과제 완료 시간: 플랫폼 조건이 Raw SQL 대비 40% 이상 단축
- DCAT 속성 커버리지: 핵심 속성(title, description, publisher 등) 95% 이상
- 벡터 검색 p95: 100ms 이하 (10만 건 기준)

## 초록

YouTube 영상의 API 메타데이터는 콘텐츠 실제 내용을 충분히 반영하지 못한다. 본 연구는
STT 기반 한국어 트랜스크립트에서 요약·키워드·개체명·콘텐츠 유형을 공개 LLM으로 자동
추출하는 파이프라인을 제안한다. 노이즈 전처리, 구조화 출력 프롬프트, Long Context 처리
전략을 설계하고, 추출된 메타데이터가 **실제 검색 정확도(IR 지표)를 향상시키는지**로
효과를 평가한다. 인간이 직접 요약·키워드·개체명을 작성해 생성물과 비교하는 절차 대신,
Query-Relevance 레이블만으로 검증 가능한 평가 설계를 택해 재현 가능성과 실행 비용을
동시에 개선했다. Groq 무료 API(14,400 req/day) 환경에서 일일 처리 가능 규모와 비용
효율성도 분석한다.

### 실험 설계

**데이터 구축**

- YouTube 영상 200편 이상 (기술 100편 + 의료 50편 + 뉴스 50편)
- 검색 평가용 Query-Relevance 쌍 50개 구축
  (질문 예시: "HBM 제조 공정을 설명하는 영상", 2인 독립 관련성 판정 + 불일치 시 제3자 조정)

> **왜 인간 레퍼런스 요약·키워드·개체명을 별도로 만들지 않는가**: 애초에 이 연구의
> 핵심 질문은 "LLM 메타데이터가 검색에 실질적으로 도움이 되는가"이지 "LLM이 인간과
> 똑같은 요약을 쓰는가"가 아니다. 200편 각각에 3문장 요약·키워드·개체명을 2인이
> 작성하고 불일치를 조정하는 작업은 영상당 10~15분씩 200편×2인 규모의 공수가 들고,
> "정답 요약"이 본질적으로 주관적이라 다른 연구자가 재현하면 다른 레퍼런스가 나와
> ROUGE-L/F1 수치도 달라진다. Query-Relevance 판정(관련/부분관련/무관)은 요약 작성보다
> 훨씬 가볍고, 검색 품질이라는 최종 목적에 직접 연결된 신호이므로 이것만으로 가설을
> 검증한다.

```
조건 B: 조건 A + LLM 요약 + 키워드
조건 C: 조건 B + 개체명 + 콘텐츠 유형
```

```

```

| 지표 | 측정 대상 | 연결 이유 |
|------|----------|----------|
| NDCG@5 | 상위 5개 결과의 순위 품질 | 사용자는 보통 상위 몇 개만 확인 |
| MRR | 첫 번째 관련 결과의 순위 역수 평균 | 정확한 답을 얼마나 빨리 찾는지 |
| Recall@10 | 정답 중 상위 10개 안에 있는 비율 | 놓치는 관련 결과가 없는지 |

### 주요 개념 설명

**NDCG@5 (Normalized Discounted Cumulative Gain at 5)**
검색 결과 상위 5개의 순위 품질을 측정. 관련도가 높은 결과가 순위가 높을수록 점수가 높다.
"할인(discounting)": 1위 결과는 5위보다 더 크게 기여한다 (log 함수 기반 감쇄). 이상적 순위와의 비율로 정규화해 0~1 범위로 표현.
NDCG@5 = 1.0이면 관련도 높은 결과가 완벽하게 상위에 정렬된 상태.

**MRR (Mean Reciprocal Rank)**
첫 번째 관련 결과가 몇 위에 나타나는지의 역수 평균.
1위 = 1.0 / 2위 = 0.5 / 3위 = 0.33 / 10위 = 0.1 / 없으면 0.
사용자가 얼마나 빨리 첫 번째 정답을 만나는지 측정. NDCG와의 차이: NDCG는 전체 목록 품질을 보지만, MRR은 "처음 정답을 만나는 속도"에만 집중한다.

### 해석 기준

- NDCG@5: 조건 C > 조건 A에서 Δ ≥ 0.05 (paired t-test p < 0.05)
- 처리 효율: 영상 1편당 Groq 호출 ≤ 3회, 응답 시간 ≤ 10초

## 구현 난이도: ★★☆☆☆

- Query-Relevance 쌍 50개 구축이 주요 비용이나, 인간 레퍼런스 요약·키워드·개체명
  작성(200편×2인)을 없애 이전 설계보다 부담이 크게 줄었다
- Groq API rate limit 관리 로직 구현 필요

- 트랜스크립트 변경 감지 시 자동 재생성 파이프라인

# P04. 계층적 벡터 검색을 이용한 이종 미디어 데이터셋 탐색

## 기여점 (Contribution)

- 데이터셋 레벨(coarse) + 아이템 레벨(fine) 2단계 계층적 벡터 검색 아키텍처 제안
- 단계별 필터링 효과: 1단계 데이터셋 필터가 검색 공간을 얼마나 줄이는가 정량화
- 이종 미디어(YouTube 영상 ↔ 뉴스 기사) 간 cross-modal 탐색 가능성 검토

> *Hierarchical Vector Search for Heterogeneous Media Dataset Discovery: Coarse Dataset Filtering with Fine-Grained Item Retrieval*

## 초록

YouTube 영상과 뉴스 기사가 혼재하는 이종 미디어 환경에서 자연어 질의로 관련 콘텐츠를
탐색하는 2단계 계층적 벡터 검색 시스템을 제안한다. 1단계에서 데이터셋 description 임베딩
(dcat_dataset_vec)으로 관련 데이터셋 K개를 추려내고, 2단계에서 그 데이터셋 내 아이템
임베딩(meta_*_vec)에서 세부 결과를 반환한다. 전체 컬렉션 Flat 검색과 비교해 응답 시간과
검색 정확도를 측정하고, cross-modal 탐색 시나리오(영상 쿼리로 관련 기사 탐색)도 평가한다.

## 연구 내용

### 2단계 검색 아키텍처

```
질의 입력: "HBM 반도체 공정 기술"
        ↓ 임베딩
[L1] dcat_dataset_vec에서 유사 데이터셋 top-K 검색
        → K=3이면: youtube_samsung_official, naver_news_ai, user_hbm_collection 선택
        ↓
[L2] 선택된 K개 데이터셋의 meta_*_vec에서만 유사 아이템 검색
        → meta_youtube_video_vec ∪ meta_naver_news_vec 대상으로 검색
        ↓
최종 결과 반환 (데이터셋 정보 + 아이템 정보 포함)
```

### 검색 공간 축소 효과

```
전체 아이템 수: N
K개 데이터셋 선택 후 검색 대상: n  (n << N)
공간 축소율: (N - n) / N × 100%
```

K가 작을수록 속도는 빠르지만 관련 아이템을 놓칠 위험 증가.
K값에 따른 정확도-속도 트레이드오프 곡선을 그린다.

### Cross-modal 탐색 시나리오

```
시나리오 1: 영상 쿼리 → 관련 뉴스 기사
  "삼성 HBM 영상을 보고 관련 최신 뉴스 기사를 찾아줘"

시나리오 2: 기사 쿼리 → 관련 영상
  "AI 데이터센터 전력 소비 기사와 관련된 YouTube 영상을 찾아줘"
```

### 핵심 연구 질문

> "2단계 계층적 검색이 전체 Flat 검색 대비 응답 시간을 줄이면서도
> 검색 정확도 손실이 통계적으로 무시 가능한 수준인가?"

정확도 손실 없이 속도가 빨라지면 계층 구조가 의미 있다.
정확도가 크게 떨어지면 K값을 늘려야 한다 → 트레이드오프 분석 필요.

### 실험 1: 정확도-속도 트레이드오프

```
변수: K = 1, 2, 3, 5, 10, "전체"(Flat)
측정: 각 K에서 응답 시간(ms)과 검색 정확도(MRR@10, Recall@10)
결과: 정확도-속도 트레이드오프 곡선 작성
```

### 실험 2: 데이터 규모별 확장성

```
아이템 수: 1K, 5K, 10K, 50K (시뮬레이션 또는 실제 수집)
각 규모에서 Flat vs. 계층 검색 응답 시간 비교
→ 규모가 클수록 계층 검색의 이점이 커지는지 확인
```

### 실험 3: Cross-modal 탐색 평가

동일 주제 영상-기사 쌍 30개를 수동 레이블링하고,
영상 설명으로 관련 기사를 검색했을 때 recall을 측정한다.

## 평가 방법

### 비교 대상

| 방법 | 설명 |
|------|------|

### 측정 지표와 연결 이유

| 지표 | 측정 대상 | 연결 이유 |
|------|----------|----------|
| MRR@10 | 첫 번째 관련 결과의 순위 역수 평균 | 사용자가 처음 보는 결과의 품질 측정 |
| Recall@10 | 정답 중 상위 10개 안에 있는 비율 | 계층 검색이 관련 결과를 놓치는지 측정 |
| 응답 시간 (ms) | 쿼리당 처리 시간 | 속도 이점의 실질적 크기 측정 |
| Cross-modal Recall | 영상-기사 쌍 정답 회수율 | 이종 미디어 탐색 가능성 입증 |

### 주요 개념 설명

**MRR@10 (Mean Reciprocal Rank at 10)**
상위 10개 결과 중 첫 번째 정답의 순위 역수 평균.
1위 = 1.0 / 2위 = 0.5 / 3위 = 0.33 / 10위 = 0.1 / 없으면 0.
사용자가 처음 보는 결과에서 얼마나 빨리 정답을 만나는지를 측정. 검색 정확도 지표 중 가장 직관적이고 널리 사용된다.

**Recall@K (K개 결과 내 재현율)**
전체 정답 중 상위 K개 결과 안에 포함된 비율. Recall@10 = 0.8이면 정답의 80%를 상위 10개 안에 포함한다는 뜻.
계층 검색에서 "2단계로 나눠 탐색해도 관련 결과를 놓치지 않는가"를 확인하는 핵심 지표. MRR과의 차이: MRR은 "첫 정답의 위치"에 집중하고, Recall@K는 "전체 정답 중 얼마나 커버하는가"에 집중한다.

**ANN (Approximate Nearest Neighbor, 근사 최근접 이웃) / HNSW**
수십만 개 벡터 중 가장 유사한 것을 정확하게 찾으려면 모든 벡터와 비교(O(N))해야 해서 너무 느리다.
ANN은 약간의 정확도를 포기하고 훨씬 빠른 근사 탐색을 한다.
pgvector가 지원하는 HNSW(Hierarchical Navigable Small World)는 계층적 그래프 구조를 미리 구축해 검색 경로를 단축한다. 정확도 손실은 통상 1~2% 수준.

**Flat Dense 검색 (vs. 계층 검색)**
인덱스 없이 모든 벡터와 직접 비교하는 가장 단순한 방법. 결과는 정확하지만 아이템 수가 많으면 느리다.
계층 검색은 "데이터셋 레벨에서 먼저 상위 K개 데이터셋을 선택 → 그 안에서만 세부 검색"으로 탐색 공간을 줄인다.
이 연구의 핵심 질문: 탐색 공간을 줄이는 대가로 얼마만큼의 정확도를 잃는가? (MRR 차이 < 0.05이면 무시 가능한 수준으로 판단)

### 해석 기준

- MRR@10: 계층(K=3) vs. Flat 차이 < 0.05 → 정확도 손실 무시 가능
- 응답 시간: 10만 건 기준 계층 검색이 Flat 대비 50% 이상 단축
- Cross-modal Recall@5: 60% 이상 → 이종 미디어 탐색 실용 수준

## 구현 난이도: ★★★☆☆

- pgvector HNSW 인덱스로 구현 가능, 추가 라이브러리 불필요
- 평가용 Query-Relevance 쌍 50개 수동 구축 필요
- Cross-modal 쌍 레이블링 30건 필요

## 향후 확장성

- 3레벨 계층 (소스 타입 → 데이터셋 → 아이템)
- 사용자 피드백 기반 데이터셋 레벨 임베딩 fine-tuning

# P05. YouTube 썸네일+텍스트 멀티모달 임베딩을 이용한 영상 검색 성능 향상

## 연구 필요성 (Research Gap)

YouTube 영상 검색 시스템은 제목·설명·태그 등 텍스트 메타데이터에 의존한다. 그러나
썸네일은 영상 내용을 압축한 시각 요약으로, 텍스트에서 드러나지 않는 정보(등장 제품,
화면 구성, 감성 톤)를 담는다. **CLIP 모델 기반 썸네일 시각 임베딩을 텍스트 임베딩과
결합해 한국어 YouTube 도메인 검색 성능을 향상시키는 연구**는 발표된 바 없다.

시각 정보가 검색에 얼마나 기여하는지는 영상마다 다를 것이다. 다만 이를 "기술
설명형·인물형·제품형" 같은 사람이 눈으로 나눈 카테고리로 설명하려 하면 두 가지
문제가 생긴다. (1) 카테고리 경계가 주관적이고(혼합형 썸네일 처리 기준 불명확),
재현 불가능하며, (2) 라벨링 자체에 별도 인력 비용이 든다.

본 연구는 카테고리 분류 대신, 이미 파이프라인에서 계산하는 임베딩만으로 **완전
자동·재현 가능한 연속 지표**를 제안한다: 썸네일이 제목과 의미적으로 얼마나
겹치는지를 CLIP 자체의 이미지-텍스트 결합 공간에서 측정한 **텍스트-이미지 의미
격차(semantic gap)**다. 이 값이 클수록 썸네일이 제목에 없는 정보를 담고 있다는
뜻이므로, 융합(fusion)이 검색 순위에 기여하는 정도와 양의 상관관계를 가질 것이라는
가설을 세운다.

제안하고, 이 지표가 개별 영상이 융합으로 얻는 순위 개선폭과 상관관계를 갖는지 분석한다.

## 연구 내용

### 1단계: 임베딩 추출

```
[검색용 임베딩]
썸네일 URL → 다운로드 → CLIP ViT-B/32 (이미지 인코더) → 512-dim 시각 벡터 v_img
제목 + 설명 → paraphrase-multilingual-mpnet-base-v2 → 768-dim → PCA 512-dim v_txt

[진단용 임베딩 — gap 계산 전용, 검색 파이프라인과 별개]
제목 → clip-ViT-B-32-multilingual-v1 (CLIP 이미지 공간에 정렬된 다국어 텍스트 인코더)
     → 512-dim g_txt   (v_img와 동일한 CLIP 결합 공간)
```

> **왜 v_txt와 g_txt가 다른 모델인가**: v_txt(mpnet)는 한국어 검색 품질이 좋지만
> CLIP의 이미지 인코더와 같은 공간에서 학습되지 않았다 — 그래서 `sim(v_img, v_txt)`는
> late fusion의 두 점수를 가중합하는 데는 문제없지만(각자 독립적인 유사도 점수이므로),
> "이미지와 텍스트가 서로 얼마나 같은 내용을 말하는가"를 재는 gap 지표에는 쓸 수
> 없다. gap은 반드시 CLIP 자신의 이미지-텍스트 결합 공간에서 계산해야 의미가
> 있으므로, 한국어를 지원하면서 CLIP 이미지 공간에 정렬된 다국어 CLIP 변형
> (`clip-ViT-B-32-multilingual-v1` 등, distillation으로 원본 CLIP 이미지 임베딩에
> 맞춰 학습됨)을 gap 계산 전용으로 별도 사용한다.

### 2단계: 텍스트-이미지 의미 격차(gap) 계산

```
gap_i = 1 - cos_sim(v_img_i, g_txt_i)     # i = 영상 인덱스, 값은 0(완전 중복)~1(완전 무관)
```

라벨링 없이 1,000개 전체 영상에 대해 자동 계산된다 (추가 API/인력 비용 없음).

### 3단계: Fusion 방법 비교

```
Late Fusion:   score = α × sim(q_img, d_img) + (1-α) × sim(q_txt, d_txt)
               α ∈ {0.1, 0.3, 0.5, 0.7, 0.9}

Concat Fusion: [v_img ; v_txt] → 1024-dim 벡터 (단순 concatenation)
Learned Fusion: linear(α) 파라미터를 validation 쿼리 20개로 학습
```

### 4단계: gap과 순위 개선의 상관 분석

```
qrels(관련성 레이블)에 있는 모든 (쿼리, 관련 영상) 쌍에 대해:
  rank_text(영상 | 쿼리)   = Text-only 방식에서의 순위
  rank_fusion(영상 | 쿼리) = Late Fusion 방식에서의 순위
  Δrank = rank_text - rank_fusion   (양수면 순위가 개선됨)

Δrank ~ gap_i 의 Spearman 상관 및 단순 회귀로 가설 검증
```

## 연구 방법

### 핵심 연구 질문

> "썸네일 시각 임베딩을 텍스트 임베딩과 결합했을 때 텍스트 단독 대비 검색 정확도가
> 유의미하게 향상되는가? 이 향상은 영상별 텍스트-이미지 의미 격차(gap)가 클수록
> 더 크게 나타나는가?"

### 실험 0: 표본 구성

주제 도메인으로 영상을 한정하지 않고 여러 채널에서 1,000편을 수집한다. gap 지표는
카테고리 균형이 아니라 **gap 값 자체의 분산**이 확보되면 되므로 — 즉 gap이 낮은
영상(제목이 이미 시각 정보를 잘 설명하는 경우)과 높은 영상(썸네일이 제목에 없는
정보를 담은 경우)이 고루 섞이기만 하면 되므로 — 기존 운영 파이프라인(`data_registry`)
수집분을 그대로 쓰고 여러 주제의 채널을 섞어 다양성만 확보한다. 사람이 손으로
카테고리를 나누는 라벨링 작업은 필요 없다.

### 실험 1: 쿼리셋 구축 및 Relevance 레이블링

50개 한국어 테스트 쿼리를 다양한 주제에서 고르게 배분해 작성하고 영상 1,000개에
대해 상위 20개 후보의 관련성을 2인 독립 레이블로 수동 평가 (관련/부분관련/무관).
이 레이블링은 gap과 무관하게, 원래도 IR 평가에 필수적인 절차다.

### 실험 2: 가중치 탐색 (Validation)

Validation 쿼리 20개로 α를 그리드 탐색해 MRR@10이 최대인 α를 선택한다.

### 실험 3: gap-순위개선 상관 분석

qrels의 모든 (쿼리, 관련 영상) 쌍에서 Δrank를 계산하고, 영상별로 사전에 자동
계산해둔 gap_i와의 Spearman 상관계수를 구한다. 참고용 시각화로 gap을 3분위
(하위/중위/상위 33%)로 나눠 평균 Δrank를 막대그래프로 제시하되, 이는 어디까지나
연속 변수를 눈으로 보기 위한 시각화일 뿐 분석의 근거가 되는 그룹 정의가 아니다.

## 평가 방법

### 비교 대상

| 방법 | 설명 |
|------|------|
| Text-only | 텍스트 임베딩 단독 (paraphrase-multilingual-mpnet-base-v2) |
| Visual-only | CLIP 썸네일 임베딩 단독 |
| Late Fusion (최적 α) | 제안 방법 |
| Concat Fusion | 벡터 단순 연결 |
| Learned Fusion | Validation으로 학습된 가중치 |

### 측정 지표와 연결 이유

| 지표 | 측정 대상 | 연결 이유 |
|------|----------|----------|
| MRR@10 | 첫 관련 결과의 순위 역수 평균 | 사용자 첫 클릭 품질을 직접 측정 |
| NDCG@10 | 상위 10개 순위 가중 품질 | 전반적 검색 목록 품질 평가 |
| Recall@10 | 정답 중 상위 10개 안에 포함된 비율 | 시각 정보가 관련 결과를 더 많이 회수하는지 |
| Spearman ρ(gap, Δrank) | gap과 순위 개선의 상관관계 | 시각 정보 기여도가 "정보 격차"로 설명되는지 직접 검증 |

### 주요 개념 설명

**Late Fusion (후기 결합)**
두 채널(이미지, 텍스트)에서 각각 독립적으로 점수를 계산한 뒤 가중합으로 결합하는 방식.
`score = α × sim(q_img, d_img) + (1-α) × sim(q_txt, d_txt)`
각 모달이 독립적으로 작동하고 α 하나로 기여도를 조절할 수 있어 해석이 쉽다.
Concat Fusion과의 차이: Concat은 벡터를 이어붙여 하나의 긴 벡터로 만들어 한꺼번에 비교 — 해석이 어렵고 차원이 커져 속도가 느리다.

**텍스트-이미지 의미 격차 (gap)**
CLIP의 이미지 인코더와, CLIP 이미지 공간에 정렬된 다국어 텍스트 인코더로 각각
임베딩을 뽑아 코사인 유사도를 구하고 1에서 뺀 값. CLIPScore(Hessel et al., 2021)와
계산식은 같지만 용도가 다르다 — CLIPScore는 캡션 품질 평가에, 본 연구의 gap은
"이 썸네일이 제목에 없는 정보를 얼마나 담고 있는가"를 재는 데 쓰인다. 라벨링 없이
전체 코퍼스에 대해 자동 계산되므로 재현 가능하다.

**NDCG@10 (Normalized Discounted Cumulative Gain at 10)**
검색 결과 상위 10개의 순위 품질을 측정. 관련도 높은 결과가 앞에 올수록 점수가 높다.
MRR@10과의 차이: MRR은 "첫 정답 위치"만 보지만, NDCG@10은 10개 전체 목록에서 관련 결과들의 순위 분포를 평가한다.

**Wilcoxon signed-rank test (윌콕슨 부호순위 검정)**
두 방법의 성능 차이가 통계적으로 유의한지 검정하는 비모수 방법.
paired t-test의 비모수 버전 — MRR 값이 정규 분포를 따르지 않을 수 있어 선택. 50개 쿼리 각각에서 두 방법의 MRR 차이에 순위를 매겨 비교한다.
p < 0.05이면 두 방법 간 MRR 차이가 우연이 아닌 것으로 판단.

**Spearman 순위 상관계수**
두 변수 간 관계가 선형이 아니어도 단조 관계(monotonic relationship)만 있으면
탐지하는 비모수 상관계수. gap과 Δrank의 관계가 정확히 선형일 필요가 없으므로
Pearson 대신 사용한다. ρ가 1에 가까울수록 "gap이 클수록 순위가 더 많이
개선된다"는 관계가 강하다는 뜻이다.

### 해석 기준

- Late Fusion MRR@10 > Text-only + 0.05 → 시각 정보의 실질적 기여 입증
- Wilcoxon signed-rank test p < 0.05 → 통계적 유의성 확보 (전체 비교)
- Spearman ρ(gap, Δrank) > 0, p < 0.05 → gap 가설 검증 (카테고리 대신 연속 지표로 검증)

### 측정 지표와 연결 이유

| 지표 | 측정 대상 | 연결 이유 |
|------|----------|----------|
| Human Rating (1–5) | VLM 메타데이터 품질 | 자동 지표가 없는 생성 품질의 직접 측정 |
| 신규 정보 비율 (%) | VLM 전용 키워드 비율 | 보완성의 정도를 정량화 |
| MRR@10 | 검색 정확도 | 생성 메타가 실제 검색에 기여하는지 |
| NDCG@10 | 검색 순위 품질 | 전반적 목록 향상 측정 |
| Friedman p-value | 4조건 간 차이 유의성 | 조건별 성능 차이가 우연이 아님을 확인 |

### 주요 개념 설명

**Jaccard 유사도**
두 집합의 겹침 정도를 측정하는 지표. `|교집합| / |합집합|`. 0이면 완전히 다르고, 1이면 완전히 같다.
여기서는 LLM 트랜스크립트 키워드 집합과 VLM 썸네일 키워드 집합이 얼마나 겹치는지를 측정한다.
Jaccard가 낮을수록 두 채널이 서로 다른 정보를 담고 있어 보완 관계가 강하다는 의미다.

**신규 정보 비율**
`|K_visual \ K_transcript| / |K_visual|` — VLM이 찾아낸 키워드 중 LLM에는 없는 것의 비율.
신규 정보 비율 = 40%이면 VLM 키워드의 40%가 트랜스크립트에 없는 시각 전용 정보라는 뜻. 이 값이 30% 이상이어야 VLM을 추가하는 가치가 있다고 판단한다.

**Friedman 검정**
세 그룹 이상의 반복 측정 비교를 위한 비모수 검정. ANOVA의 비모수 버전(paired 데이터용).
여기서는 A/B/C/D 4조건에 대해 동일한 50개 쿼리를 적용한 MRR@10 값이 조건 간에 통계적으로 다른지를 검정한다. 정규 분포 가정 없이 순위 기반으로 검정하므로 소규모 실험에 적합.
p < 0.05이면 4조건 중 적어도 하나가 다른 조건과 유의미하게 다른 검색 성능을 보인다.

### 해석 기준

- Human Rating 평균 ≥ 3.5 → 실용 수준의 VLM 메타데이터 품질
- 신규 정보 비율 > 30% → 트랜스크립트와 충분히 독립적인 정보 제공
- 조건 C가 조건 A 대비 MRR@10 > +0.03 → VLM 메타의 검색 기여 입증

# P07. 썸네일-제목 의미 정합성을 활용한 한국어 YouTube 클릭베이트 탐지

## 연구 필요성 (Research Gap)

한국어 YouTube에서 클릭베이트—썸네일과 제목이 실제 내용과 유리된 영상—는 사용자
신뢰를 저해하는 주요 문제다. 기존 탐지 연구는 제목 텍스트의 감탄사·과장 표현 분석에
집중하며, **썸네일과 제목 사이의 시각-언어 의미 정합성(semantic alignment)을
탐지 신호로 활용한 한국어 연구**는 없다. CLIP 모델의 이미지-텍스트 정렬 능력을
활용하면 텍스트 분석이 포착하지 못하는 "시각적 낚시"(정상 제목·이상 썸네일)도
탐지할 수 있다는 가설이 있다.

## 제목

> *Multimodal Clickbait Detection via Thumbnail-Title Semantic Alignment Score in Korean YouTube*

## 초록

한국어 YouTube 클릭베이트 탐지 연구는 제목 텍스트 분석에 편중되어 있으며, 썸네일의 시각
정보를 탐지에 활용한 연구는 없다. 본 연구는 CLIP 모델로 계산한 썸네일-제목 의미 정합성
점수(alignment score)를 클릭베이트 탐지 신호로 활용하는 방법을 제안한다. 한국어 YouTube
영상 300건에 대한 2인 독립 클릭베이트 레이블 데이터셋을 구축하고, 텍스트 단독·시각 단독·
멀티모달 결합 탐지기의 Precision·Recall·F1을 비교한다.

## 연구 내용

### 1단계: CLIP 정합성 점수 산출

```
alignment_score(v) = cosine_similarity(
    CLIP_image(thumbnail_v),
    CLIP_text(title_v)
)
범위: [-1, 1] — 값이 낮을수록 시각-텍스트 불일치
```

### 2단계: 클릭베이트 레이블 체계

```
유형 A (시각적 낚시): 썸네일 내용이 영상 내용과 완전 무관 (예: 유명인 얼굴 삽입)
유형 B (텍스트 낚시): 과장 표현·물음표 제목으로 호기심 유발
유형 C (혼합):        A + B 동시
비클릭베이트:         정상
```

### 3단계: 탐지 모델 비교

```
M1 — 텍스트 단독:       제목 내 감탄사·과장 표현·물음표 비율 → Logistic Regression
M2 — 시각 단독:         alignment_score < τ → Threshold Classifier
M3 — 멀티모달 결합:     [alignment_score, text_features] → Logistic Regression
M4 — 유형 인식 결합:    유형 A/B/C 레이블로 multi-class 분류
```

### 핵심 연구 질문

> 추가적인 판별력을 제공하는가? 특히 '시각적 낚시형'은 텍스트 방법으로 탐지 불가능한가?"

### 실험 1: 데이터셋 구축

- 수집 영상 중 300건 샘플링 (클릭베이트 150건, 정상 150건 균형)
- 2인 독립 레이블 후 Cohen's Kappa 측정 → Kappa > 0.7 목표
- 불일치 케이스는 3인 합의로 결정

### 실험 2: 정합성 점수 분포 분석

클릭베이트 vs. 정상 그룹의 alignment_score 분포를 비교하고
Mann-Whitney U-test로 두 그룹 차이의 통계적 유의성을 검정한다.

### 실험 3: 탐지 성능 비교

5-fold cross-validation으로 M1–M4의 Precision·Recall·F1을 비교한다.
유형 A(시각적 낚시)는 M1이 탐지하기 어려우나 M2·M3는 가능할 것이라는 가설을 확인한다.

| Precision / Recall / F1 | 클릭베이트 탐지 정확도 | 오탐(Precision)과 미탐(Recall) 모두 중요 |
| Cohen's Kappa | 레이블 일치율 | 데이터셋 신뢰성의 필수 검증 지표 |
| ROC-AUC | 임계값 독립 전반 판별력 | 임계값 선택 없이 모델 자체 성능 비교 |
| MWU p-value | 클릭베이트/정상 그룹 점수 분포 차이 | alignment_score가 신호로서 유효한지 사전 검증 |
| 유형별 F1 | 유형 A/B/C 각각의 탐지 정확도 | 어떤 클릭베이트 유형에 시각 신호가 효과적인지 분석 |

### 주요 개념 설명

**Precision / Recall / F1**
- **Precision(정밀도)**: 클릭베이트라고 예측한 것 중 실제로 클릭베이트인 비율. 낮으면 정상 영상을 클릭베이트로 잘못 신고(오탐)하는 경우가 많다는 뜻.
- **Recall(재현율)**: 실제 클릭베이트 중 탐지기가 잡아낸 비율. 낮으면 클릭베이트를 정상으로 놓치는(미탐) 경우가 많다는 뜻.
- **F1**: Precision과 Recall의 조화 평균. 둘 다 높아야 F1이 높다. 오탐과 미탐 모두 중요할 때 균형 지표로 사용.

**Cohen's Kappa (코헨 카파)**
두 평가자가 얼마나 일치하는지를 "우연에 의한 일치를 제거한 후"의 값으로 표현한다. -1~1 범위.
단순 일치율(Accuracy)의 문제: 클릭베이트가 50% 비율이면 무작위로 레이블해도 50% 일치 — 이를 보정한 게 Kappa.
0.7 이상이면 "상당한 일치(substantial agreement)"로 데이터셋을 신뢰할 수 있다고 판단한다.

**ROC-AUC (Receiver Operating Characteristic - Area Under Curve)**
탐지기의 임계값(threshold)을 0~1 전체 범위에서 변화시켰을 때 전반적 판별 능력을 하나의 숫자로 요약한 지표.
0.5이면 무작위 분류기와 동일, 1.0이면 완벽한 탐지기.
임계값 선택에 독립적으로 모델 자체의 판별력을 비교할 수 있어, M1~M3 모델 간 공정한 성능 비교에 적합하다.

**Mann-Whitney U-test (만-휘트니 U 검정)**
두 그룹의 분포가 같은지를 정규 분포 가정 없이 검정하는 비모수 방법.
여기서는 클릭베이트 그룹과 정상 그룹의 alignment_score 분포가 다른지를 검정한다.
p < 0.05이면 두 그룹의 alignment_score 분포가 통계적으로 다르다 → CLIP 정합성 점수가 클릭베이트 탐지의 유효한 신호임을 사전 검증하는 단계.

### 해석 기준

- Cohen's Kappa > 0.7 → 레이블 신뢰 확보
- M3 F1 > M1 F1 by ≥ 5%p → 시각 정합성 신호의 추가 기여 입증
- ROC-AUC > 0.75 → 실용적 탐지기 수준
- 유형 A에서 M2 Recall > M1 Recall by ≥ 20%p → "시각적 낚시" 가설 검증
